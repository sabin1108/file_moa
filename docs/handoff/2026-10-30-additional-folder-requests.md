# 최신 추가 요청 — 폴더 연결 위치·확장자 판별·삭제

2026-10-30. 사용자가 다음 세 항목도 memory와 다음 작업에 기록하도록 요청했다. 이번에는 문서만 갱신했으며 기능 구현·버그 재현·테스트를 수행하지 않았다. 이전의 완료 보고가 이 추가 요구까지 완료했다는 뜻은 아니다.

1. **폴더 연결 설정의 위치 변경.** 현재 우측 상단에 있어 목록 작업 위치에서 너무 멀고 사용성이 좋지 않다는 피드백이다. 폴더 작업 영역 가까이에서 연결 관리를 실행할 수 있게 바꾼다. 정확한 배치는 구현 시 현재 화면과 좁은 화면을 함께 검토한다. 승인된 채팅 디자인을 바꾸는 요청은 아니다.
2. **파일명 확장자로 생성 의도를 반영.** 사용자는 “폴더”를 선택한 상태에서 `aaa.txt`를 입력하면 TXT 파일이 만들어져야 하는데 `aaa` 폴더가 생긴다고 보고했다. 기대 결과는 이름 그대로 **`aaa.txt` 파일** 생성이다. 종류 선택이 폴더여도 명시적으로 입력한 `.txt` 확장자를 우선해야 한다. 현재 코드는 folder 종류에서 파일 확장자로 종류를 바꾸지 않는 것으로 확인했지만, 사용자 보고의 확장자 제거/`aaa` 폴더 생성 현상은 아직 재현하지 않았다. 다음 구현에서 원인을 확인하고 최종 종류·이름·미리보기·실제 생성 결과를 일치시킨다. `.md` 등 추가 확장자와 종류 충돌 규칙은 같은 생성 흐름에서 명세하고 테스트한다. 이 정정은 기존의 ‘folder 종류면 확장자가 있어도 폴더로 생성’ 동작보다 우선한다.
3. **삭제 기능 마련.** 파일/폴더 관리에서 항목을 삭제할 수 있는 조작이 필요하다. 삭제 대상 선택과 실행 UX, 파일/빈 폴더/내용 있는 폴더 범위, 권한·확인·작업 기록·실패 처리와 복구 가능 여부를 먼저 정한다. 휴지통 이동인지 영구 삭제인지는 아직 정해지지 않았다. 이번 기록 요청으로 실제 항목을 삭제하거나 영구/재귀 삭제 방식이 승인된 것으로 취급하지 않는다.

## 다음 재개 순서

우선 새 피드백인 연결 설정 위치와 `aaa.txt` 생성 규칙을 수정·검증한다. 삭제 기능은 요구사항과 실패/복구 계약을 구체화하고, 기존 계획의 작업 기록 조회·재접속 후 결과 확인과 필요한 순서를 연결한다. 이후 실제 복사와 이동 순서는 기존 인수인계를 유지한다. 이 문서는 다음 할 일의 추가 기록이며 구현을 이번 세션에 착수한 것은 아니다.
