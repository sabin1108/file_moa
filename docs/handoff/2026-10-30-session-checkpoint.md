## 다음 작업 순서

아래는 재개할 때의 권장 순서다. 이번 요청은 기록 저장이며 다음 기능 구현을 지금 시작한 것은 아니다. 최신 사용자 지시가 있으면 우선한다.

1. **작업 기록 조회 UI부터 구현한다.** 현재 폴더의 `.moa-history`를 읽어 같은 작업 ID의 pending/ready/failed/uncertain 기록을 묶고, 항목 종류·경로·시간·결과를 보여준다. 기록이 없는 상태, 손상/알 수 없는 버전, 권한 거부, 연결 변경을 먼저 명세·테스트한다. 조회만으로 쓰기 권한을 요구하거나 기록 폴더를 생성하지 않는다. pending만 남은 작업을 성공으로 단정하지 않는다.
2. **새로고침·재접속 후 결과 확인을 연결한다.** 미확인 항목의 실제 존재/종류를 읽기 전용으로 재확인하고 사용자가 현재 상태를 볼 수 있게 한다. 자동 재생성·덮어쓰기·삭제·롤백은 하지 않는다. 생성 주체를 판별할 수 없는 API 한계를 표시한다. native OS 권한 검증 가능 여부도 별도로 기록한다.
3. **실제 복사 기능으로 확장한다.** 기존 복사 전 검사 결과에 실행을 바로 붙이지 말고, 원본 변경 감지·충돌/외부 경쟁·쓰기 권한·작업 기록·부분 실패·취소·재시작 복구 계약을 먼저 정한다. 실패 테스트 뒤 작은 단위로 구현하고 원본과 기존 목적지 파일 보존을 검증한다.
4. **이동은 복사 검증/복구 이후에 다룬다.** 원본 삭제가 추가되므로 복사 완료 검증과 삭제·복구 계약을 별도로 마련한다. 본문 편집/저장, 로그인, 실제 AI/API는 별도 후속 범위이며 이번 완료 기능에 포함하지 않는다.
