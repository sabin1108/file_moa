# 실제 사용 지연과 장기 세션 관찰 계획

2026-11-12 업데이트: 모델 없는 합성100/500 turn의 실제60분12.9초 관찰을 완료했다.600회 패널 왕복·120회 기록 재열기와 초안 보존, 메모리 증가의 독립 비교·미확정 원인은 [검증 보고서](../verification/stabilization-20261112/README.md)를 따른다. 기능 경로 통과와 누수 판정을 구분한다. 실모델·원격 DB를 합친 지연/비용 관찰은 수행하지 않는다.

2026-11-10. 현재 구현된 기능을 실제 환경에서 확인하기 위한 준비다. 아래 실행 계획을 실사용 검증 완료로 표시하지 않는다. [이번 준비 결과](../verification/runtime-observation/README.md), [실제 환경 확인 순서](../verification/resume-20261110/README.md)를 함께 따른다.

## 현재 코드에서 이미 제공하는 관측값

일반 채팅의 `apps/web/src/server/chat.ts`가 종료 정산 뒤 `Chat generation.`으로 숫자·공급자·결과를 기록한다. 서버 로그 전체에는 인증 정보가 있을 수 있으므로 원문 전체를 공유하지 않는다. 아래 허용 항목만 한 요청의 관측표에 옮긴다.

| 항목 | 시작과 끝 또는 의미 | 해석할 때의 주의점 |
| --- | --- | --- |
| `sessionMs` | 최초 세션 조회 전후 | 최초 인증 구간이며 이후 스트림 권한 재검사는 별도 |
| `quotaMs` | 공유 한도 예약 전후 | DB 실제 SQL 수를 직접 알려주지는 않음 |
| `preflightMs` | handler 진입부터 스트림 작업 준비까지 | 세션·입력 검사·한도 등 포함. 원장 예약 완료를 모두 기다린 시간으로 해석하지 않음 |
| `firstProviderTextMs` | handler 진입부터 공급자 첫 본문 이벤트를 읽은 때까지 | 초기 준비·토큰 계산·최신 권한 확인 등이 포함돼 공급자 단독 TTFT가 아님 |
| `firstPublishedMs` | handler 진입부터 첫 본문 공개 함수의 시점까지 | 브라우저 수신·실제 표시 시점이 아님 |
| `authorizationChecks`, `authorizationMs` | 스트림의 최신 권한 재검사 횟수와 누적 소요 | 전체 지연과 겹치므로 다른 구간에 단순 합산하지 않음 |
| `publicationBatches`, `maxPublicationGapMs`, `maxBatchCharacters` | 공개한 본문 묶음 수·최대 간격·최대 문자 수 | 네트워크 chunk 수·브라우저 frame 수와 다름 |
| `elapsedMs` | 스트림 작업용 시작 시각부터 종료 정산 뒤 로그까지 | 사용자 전송부터 화면 완료까지의 시간과 다름 |
| `outcome`, 알려진 토큰 수 | 서버 결과와 공급자가 확인한 사용량 | 사용량 미수신은0이 아니라 미확인 |

현재 이 로그에는 요청 식별자가 없다. 여러 요청이 섞인 로그를 임의로 한 사용자 행동에 대응시키지 않는다. 격리 환경에서 한 번에 요청 하나만 관찰하며, 실제 공급자 호출은 별도 비용 범위를 확정한 뒤에만 시행한다. 기존 승인을 재사용하지 않는다.

## 관찰 순서와 완료 조건

1. 사용자 직접 로그인 후 실제 소셜 callback 복귀·물리 한글 입력·Windows 권한 선택을 확인한다. 개인 비밀번호·코드·쿠키는 기록하지 않는다. 실제 폴더는 기존 합성 테스트 자료를 사용한다.
2. 고정된 합성 자료로 일반 대화 → 자료 찾기/원문 → 기록 저장/재열기 경로를 확인한다. 모델 호출 없는 동작부터 진행한다. 전송 동의·원본 보호·현재10회 한도는 유지한다.
3. 실제 AI 측정은 합성 질문·최대 요청 수·중단 조건·비용 범위가 별도로 확정된 경우만 시행한다. 중지·오류·한도 도달은 자동 재전송하지 않는다. 원장 상태를 확인하되 사용량 화면 조회도 오래된 예약을 `unknown`으로 정리하는 쓰기가 있을 수 있음을 구분한다.
4. 브라우저 표시 시간은 전송 조작부터 첫 글이 화면에 보인 때와 완료 표시까지 따로 관찰한다. 현재 서버 지표로 이를 대체하지 않는다. 최초/반복, dev/production, 로그인 계정·자료량·캐시·동시성을 구분해 기록한다.
5. 장기 세션은 같은 브라우저·같은 자료에서0/15/30/60분 시점에 기록한다. 모델 호출 없이 기록함 재열기·자료 미리보기·패널 전환·초안 입력을 반복한다. 각 시점의 현재 turn 수, 대화 article 수, JS heap, 브라우저 메모리, 예외 수, 입력·표시 지연을 구분한다.

장기 실행은 현재 준비만 했으며 아직 수행하지 않았다. 각 시점에 자료가 늘었다면 메모리 변화와 함께 기록한다. GC를 통제하지 않은 heap 상승만으로 누수를 판정하거나, 짧은 합성 반복으로60분 사용을 대신하지 않는다. 원래 자료·권한·계정 상태가 바뀌거나 오류·한도가 나오면 중단하고 재현 가능한 증거부터 남긴다.

## 사용량과 비용의 대조

`AiUsageEvent`에는 공급자·작업 종류·모델·상태·입출력/합계 토큰·생성/종료 시각이 있다. `startUsage()`가 `reserved`를 만들고 `finishUsage()`가 최초 종료 정산만 반영한다. 사용량이 알려지면 `completed`, 알려지지 않으면 `unknown`이다. 이 상태는 채팅 화면이 정상 완료됐다는 결과와 항상 같은 뜻이 아니다. 중지 전 공급자 사용량을 받았다면 화면은 중지여도 원장은 알려진 사용량으로 정산할 수 있다.

`readUsage()`는 현재 작업 공간의 최근50개 항목만 보여주므로 이를 기간 전체 청구 합계로 사용하지 않는다. 화면의 비용은 확인된 모델 단가와 알려진 토큰 수의 추정값이며 실제 청구서·캐시 할인·지역 비용 대조와 구분한다. 이번 준비에서 최신 단가를 검증하거나 청구서를 조회하지 않았다.
