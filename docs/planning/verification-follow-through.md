# 앞선 작업의 검증·운영 보완 — 2026-11-09

사용자 ‘다음 작업도 이어서 하고 아까 지시했던 작업들’에 따라1~9의 미검증 경로와 기존10~12의 검증/성능/운영 준비를 이어간다. 이미 승인한 사용량 실제 DB/로컬 활성화와10회 한도는 유지한다. 이는 현재 한도 제거·새 유료 모델 평가·실제 사용자 삭제·배포 승인으로 확장하지 않는다. 로컬 AI/위키/성장은 후속 범위로 유지한다.

이번 완료 기준:

1. 활성 사용량의 early exit·취소·중복·서버리스 수명·오래된 예약을 실패 검사로 고정하고 수정한다. 예약과 최신 인증은 병행하지만 둘 다 성공해야 provider를 호출한다. 불명 사용량은0으로 만들지 않는다.
2. 선택 자료 질문의 실제 제품 UI에서 동의·재확인·인용·원문 왕복·원본 변경·권한 상실·취소·새 owner를 합성 파일/응답으로 검증한다. 모델 의미 정확도를 통과로 부르지 않는다.
3. 기록/내보내기/다중 폴더와 긴 대화의 대표 실패·키보드/좁은 화면을 보완하고 실제 측정 값과 조건을 남긴다. 예전 S0 도구의 제품 모듈 경로도 확인한다.
4. 관련 검사 → 타입·린트·전체 단위·경계·빌드와 임시 DB/브라우저를 실행하고, 비밀 포함 여부·문서 상태를 점검한다. dev를 다시 열고 안정성 검사를 한다. 커밋/푸시/배포는 별도 지시 없이 실행하지 않는다.

computer-use 지침의 실제 보안/개인정보 권한 조작 금지 때문에 native 권한 승인·철회와 물리 IME는 자동 통과로 보고하지 않는다. 합성 권한·실제 파일/Worker·실제 Windows UI를 명확히 구분한다. 구현을 기다리게 하지 않고 나머지 검증을 끝낸다.

이번 안전한 자동 실행 범위는 완료했다. [결과와 미검증 경계](../verification/follow-through/README.md): 정산 수명/오래된 예약/잘못된 인용 수정, 전체1,260개·임시DB25+60·자료UI11·기록14·채팅32·설정26·S0 검증 통과. 실제 Windows·실모델·인증 field 성능·배포가 남아 10~12 전체 완료로 표시하지 않는다.
