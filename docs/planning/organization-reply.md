# 채팅 답변을 기존 정리 질문에 연결

2026-11-08. 사용자가 확장 프로그램은 직접 처리하고 다음 작업 진행을 요청했다. 이번 단위는 CF-003의 답변 연결이다. 실제 Windows 브라우저 제어의 주소 확인 문제는 우회하지 않으며 실환경 검증 완료로 보고하지 않는다.

## 범위와 실패 조건

- 질문이 있을 때 채팅 입력은 최초 정리 요청과 분리된 답변 초안이다. 입력만으로 자료 준비/제안/동의/답변을 바꾸거나 전송하지 않는다.
- 제출한 문장을 현재 질문의 문서 이름·상대 경로와 실제 날짜 후보에만 연결한다. 날짜 기준/날짜, ‘자료는 학습 폴더로’ 같은 명시 경로, 제외를 지원하는 작은 로컬 해석이다. 새 모델 호출이나 일반 대화 이해를 추가하지 않는다.
- 여러 문서/날짜가 맞거나 부정·모순·미지원 문장이 섞이면 전체 반영을 거부하고 기존 선택 입력을 유지한다. 경로는 기존 schema, 날짜는 기존 발췌 근거 검증을 재사용한다.
- 답변 묶음은 기존 단일 답변과 같은 검증/동의·제안 폐기를 원자적으로 사용한다. 자동 재전송/파일 적용은 없다. 성공 후 답변과 기존 질문 입력에서 결과를 확인하고 새 동의·전송을 거친다.
- 초기 요청 수정은 기존 조건 영역에서 명시적으로 한다. 답변 초안은 Provider/controller 수명에 보관하고 계정 전환/취소/범위·선택 변경 때 폐기한다. 대기 중 제출은 차단한다.

## 변경 책임과 완료 조건

순수 해석 `lib/organization-reply` → 기존 preparation controller의 초안/묶음 답변 → LiveConversation의 입력 연결이다. 공통 composer는 입력 이름/힌트를 받는 표시 역할만 추가한다. 기존 질문 선택 UI·서버 검증·원본 재검사·실행 엔진을 유지한다.

실패 테스트부터 고정하고 명확한 두 답변, 이름 충돌, 여러 날짜, 경로 탈출/예약 이름, 부정/미지원/부분 실패, 수정/동의 폐기, pending/늦은 응답/owner 초기화, IME/키보드/4폭을 확인한다. 타입·린트·전체 테스트·경계·빌드와 전후 성능을 남긴다. 물리 IME·실제 Windows 전체 여정은 별도 미검증이다.
