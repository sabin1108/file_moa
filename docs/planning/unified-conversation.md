# 하나의 대화로 통합 — 2026-11-09

사용자는 일반 질문과 자료 찾기/정리를 하나의 대화·입력창으로 통합하고 UI의 재사용성을 반드시 지키라고 지시했다. 요청 내용을 판단하며 애매할 때만 확인하는 방식을 명시 선택했다. 자료 외부 전송 동의와 원본 작업 실행 승인은 유지한다.

기존 화면은 같은 `ConversationWorkspace` form을 쓰지만 상위 화면을 교체하고 interaction 유무로 입력을2/3줄로 바꿨다. 입력은3줄로 수정했고 네 너비의 실제 크기 일치와 찾기55개·관련48개·타입/린트/빌드가 통과했다. 이것만으로 한 대화가 되는 것은 아니다.

1. 실패 계약: 한 입력 DOM·단일 스레드·초안/스크롤 보존, 자동 요청 분류/모호함 확인, 일반 대화 무자료 접근, 자료 명령 무자동 외부 전송, 검색→선택→정리의 동의/검토, 새 대화/owner/복원/취소 시 늦은 작업 차단을 검사한다.
2. 기존 finding/organization/preview/실행 컨트롤러를 유지한다. 자료 UI는 작업 패널로 재사용하며 공통 입력·메시지·shell을 다시 만들지 않는다. 모드 전환과 별도 입력 소유권을 제거한다.
3. 일반 응답과 자료 작업은 한 기록에 표시하되 종류를 보존한다. 이전 기록은 일반 대화로 복원한다. 자료 검색/정리/근거 답변을 일반 모델 문맥에 묵시적으로 넣지 않으며 복원은 모델·검색·원본 작업을 재실행하지 않는다.
4. 자료 근거 질문도 같은 입력에서 받고 원본 재확인·발췌 동의·인용 검증·늦은 응답 차단을 재사용한다. 질문·자료가 바뀌면 동의를 무효화한다.
5. 관련 단위·실제 통합 UI 브라우저·타입/린트/빌드·경계를 검증하고 dev를 복구한다. 분리된 옛 화면만 테스트해 통합 완료로 보고하지 않는다.

공통 form·메시지는 `ConversationWorkspace`, 분류는 순수 규칙, 스트림은 기존 chat hook, 자료 상태/동의는 기존 컨트롤러/hook, 기록은 기존 AI 폴더 저장소가 맡는다. 새 의존성·DB 변경·유료 모델 호출·배포는 추가하지 않는다. 읽기 전용 설계 조언은 공식 Ralplan/Team/goal 실행 권한을 뜻하지 않는다.
