# 작업 목록1~9 연결 구현 — 2026-11-09

사용자 요청: ‘9번까지 쭉 이어서 작업해’. 이는 직전 답변의1~9이며 기존 완료 로드맵의9번까지라는 뜻으로 바꾸지 않는다. 아래는 실행 추적이며 완료 증거를 대신하지 않는다. 기존 미커밋 일반 채팅·초점·로딩·한도·DB 왕복 개선을 보존한다.

## 실행 경계

- 기존 공통 화면·컨트롤러·파일 검증·동의·복구를 재사용한다. 대화·승인 기억·결과물 본문은 지정 AI 폴더에 저장하며 서버에는 운영 메타데이터만 둔다.
- 저장 전에 명시적 폴더 쓰기 권한을 받고 임시 대화는 저장하지 않는다. 계정/작업 공간/연결 세대가 바뀌면 늦은 결과를 버린다. 원본 파일은 AI 기록 저장만으로 변경하지 않는다.
- DB 리전 이관·운영 migration·유료 모델 평가·실계정 삭제·보류한 Kakao 재개는 이번 코드 작업만으로 실행하지 않는다. 필요한 외부 변경은 로컬 결과와 검증을 준비한 뒤 구체적으로 다룬다.
- 새 의존성이 꼭 필요한 PDF 파서는 기존 패키지 조사와 공식 근거를 먼저 확인한다. 새 패키지 추가는 AGENTS의 명시적 요청 규칙을 따른다.

## 순서와 완료 기준

현재 판정: 1번 최적화/진단과 2~7·9번 제품 연결·자동 검증을 완료했다. 8번 실제 DB와 로컬 활성화도 완료했다. 이후 정산·자료 응답 실패 경로를 보완했다. [최신 후속 검증](../verification/follow-through/README.md)과 [기본 구현 보고서](../verification/workspace-nine/README.md)를 함께 확인한다. 최종 횟수 제한 제거는 후속이며 현재10회 제한은 유지한다.

## 구조와 검증

`shared/ai-records`는 엄격한 저장 payload, `features/ai-records/services`는 기존 S0 알고리즘을 제품 수명/owner와 연결한 기록 접근, `store`는 세대·dirty·저장 결과, `components`는 기존 표시/입력 재사용을 맡는다. 일반 채팅은 기존 reducer/hook의 상태를 저장소와 연결하고 생성 요청을 복원 시 재전송하지 않는다. 자료 대화는 기존 snapshot 계약을 서버 shared에서 다시 검증한다.

각 단위는 작은 실패 테스트 → 구현 → 관련 검사 순서로 진행한다. 최종 타입·린트·전체 단위·서버/기능 경계·빌드, 실제 제품 UI의 합성 폴더/스트림·키보드/좁은 화면·철회/동시성, 임시 PostgreSQL의 owner/usage/delete 실패 경로를 확인한다. 운영 DB와 실제 파일·물리 IME 미검증은 별도 표시한다.

현재 작업은 일반 native 실행 경로이며 공식 Ralplan/Conductor/Team 합의 영수증이나 goal-mode 활성화를 주장하지 않는다. 전문 에이전트는 코드 지도·설계·독립 검토를 제공하고 root가 변경과 통합 검증을 소유한다.
