# 소개 페이지의 스크롤 장면 보완 — 2026-11-11

## 목표와 경계

사용자는 단순 등장 효과보다 Toss처럼 화면에 시선이 머물고 기능의 변화가 스크롤에 맞춰 이어지는 연출을 요청했다. 기존 Colour chapters·네이비/은회색·글꼴·공개/체험 경로를 유지한다. 기능 소개용 문서와 화면만 움직이며 실제 자료 읽기·모델 요청·파일 변경은 하지 않는다.

## 세 장면

1. 첫 화면: 제목과 시작 버튼을 먼저 읽는다. 스크롤하면 흩어진 문서가 폴더 안으로 모이고, 폴더가 자료 작업 화면으로 이어진다. 사용자가 스크롤을 되돌리면 같은 위치로 돌아온다.
2. 자료에서 답변까지: 제품 표시를 고정하고 키워드 검색 → 원문 확인 → 자료 기반 답변의 세 장면을 교대한다. 텍스트 설명은 자연스럽게 스크롤하고 화면 상태는 해당 진행 구간에 대응한다.
3. 정리 계획: 흩어진 파일 → 목적지 검토 → 확인 후 정리된 폴더를 보여 준다. 소개 예시임을 표시하며 자동 원본 정리를 약속하지 않는다.

기록/위키와 마지막 시작 조작은 차분한 읽기 구간으로 남긴다. 고정 장면 사이에는 정적인 자료 예시 지면을 둔다.

## 구현과 실패 조건

기존 ProductScenes를 재사용하고 정리 전후 디렉터리 표시와 스크롤 이야기 조합을 분리한다. 추가 패키지·전역 스크롤 이벤트·휠 가로채기 없이 CSS view-timeline과 sticky로 진행한다. 브라우저가 필요한 CSS를 지원하고 움직임 감소 설정을 사용하지 않는 경우에만 긴 고정 지면과 겹친 장면을 활성화한다.

지원하지 않는 환경·움직임 감소·높이가 작은 화면에서는 모든 설명과 제품 장면을 순서대로 펼친다. 중요한 시작 링크를 고정 지면이 가리지 않아야 한다. 모바일은 더 짧은 진행 구간과 작은 제품 지면을 사용한다. 키보드와 네이티브 자료 예시 선택을 유지한다.

검증은 실제 ego-browser에서 시작/중간/끝·역방향·멈춤·키보드·모바일·움직임 감소·CSS 미지원 대체 표시를 확인한다. 소개 방문과 스크롤이 모델 요청이나 파일 권한 요청을 만들지 않아야 한다. 기존 공개/체험 진입 테스트와 전체 테스트·타입·린트·빌드·구조 검사를 실행한다. 이전 공백 정리는 이번 변경 범위에 섞지 않는다.

## 근거

실제 Toss의 송금 장을 ego-browser로 열어 하나의 큰 제품 장면과 짧은 문장이 스크롤 중 교대하는 구성을 확인했다. 자산·문구는 복제하지 않는다. CSS 진행 구간은 [MDN timeline range](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Scroll-driven_animations/Timeline_range_names)와 [Chrome scroll-driven animation 가이드](https://developer.chrome.com/docs/css-ui/scroll-driven-animations)를 확인했다. 단순 진입 효과와 진행 위치에 묶인 연출은 별도로 검증한다.
