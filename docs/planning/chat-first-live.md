# 대화 중심 정리 실제 적용과 하이드레이션 확인

2026-11-08 사용자 요청. 이전 시안에 대한 긍정 피드백 뒤 실제 적용, 기존 복사/이동 UI 재사용, 유지보수·확인 용이성·책임 분리와 하이드레이션 경고 확인을 요청했다.

## 확인할 주장과 변경 범위

1. 사용자가 제공한 차이는 루트의 `data-map-dyoa-ext="1.3.0"` 외부 속성이다. 앱 코드 검색에는 없다. 실제 RootLayout의 서버/클라이언트 초기 렌더를 비교하고 이 속성 주입 시 경고를 재현한다. 확장 프로그램 접근 해제는 사용자 브라우저 설정이며 앱이 자동 변경하지 않는다. 경고 전체 억제/SSR 비활성은 해결로 사용하지 않는다.
2. 기존 실제 컨트롤러와 쓰기/동의 경계를 유지한다. 대화의 현재 상호작용 표시와 자료 상세를 분리하고 자동으로 오른쪽 창을 열지 않는다.
3. 기존 경로/계획 표시를 확인하고 현재/도착 비교를 공통 표시 책임으로 만든다. 기본 복사·이동, 실제 AI 정리, 검토 시안이 같은 표시를 사용한다. 임의 실행 컨트롤러나 파일 writer를 추가하지 않는다.
4. 질문/동의/제안은 지금 할 일을 먼저 보이게 하고 발췌·해시·토큰은 상세로 접는다. 입력/초점/취소/선택·동의 무효화/외부 전송 사실을 보존한다.

## 작업 순서와 검사

- 기존 상태/실행 실패 테스트를 유지하고 새 순수 표시 투영의 경로/공통 부모/복사 원본 유지/빈 결과/폴더를 먼저 검사한다.
- 실제 RootLayout+시안의 SSR→hydrate 브라우저 검사와 외부 속성 재현을 만든다.
- 공통 비교 표시를 기존 복사 계획/managed 검토/AI 표시/시안에 연결한다. 데이터 투영, React 표시, controller 조합, 실제 접근의 책임을 나눈다.
- 대화 안 상호작용을 연결하고 기존 승인/실행/복구를 재사용한다. 보조 면의 상세와 필수 행동을 중복 렌더링하지 않는다.
- 관련 단위 → 전체 검사 → 타입/린트/경계/빌드 → 실제 브라우저4폭/키보드/합성IME/취소/동의/복사·이동·복구 → 성능 전후를 확인한다. 확장 프로그램을 끈 사용자 창과 물리IME는 별도 확인이 필요하다.

## 중단 조건

범위 밖 파일 쓰기/개인 자료 전송/배포/사용자 브라우저 제한 우회를 하지 않는다. 현재 알려진 실제 환경의 사용자 결과는 완료한 단계만 유지하며 새 기능 검증을 과거995개 통과로 대신하지 않는다. native explore는 기존 재사용 지점만 읽어 보고했고 제품 변경/하이드레이션 검증은 직접 수행한다.
