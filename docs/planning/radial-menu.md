# 채팅 원형 빠른 이동 메뉴 — 후속 기획

상태: 아이디어 기록. 정적 프로토타입에는 구현하지 않음.
사용자 요청: 마우스 좌클릭을 꾹 누르면 원형 메뉴를 열고, 상하좌우·대각선 방향으로 움직여 지정한 위치로 이동.

## 제안 상호작용
- 채팅의 빈 배경에서 왼쪽 버튼을 450ms 유지하면 8방향 메뉴 표시. 350–500ms 범위를 사용자 검증할 후보로 두며 확정값이 아님.
- 누른 위치를 중심으로 방향 이동 시 후보를 강조하고 명칭을 표시. 손을 떼면 선택한 위치로 이동.
- 중심의 안전 영역에서 떼기, Esc, 창 focus 상실, pointercancel은 취소. 영역 밖 이동도 취소 규칙으로 정하고 구현 시 확인.
- 화면 가장자리에서는 메뉴 전체가 보이도록 배치. 중심 보정이 방향 선택에 미치는 영향도 검증.
- 목적지는 대화·내 폴더·지정 폴더·검색 등 사용자가 설정. 초기 8개를 모두 강제로 채우지 않음.
- 파괴적 작업/파일 쓰기/전송은 빠른 이동 메뉴의 직접 실행 항목으로 두지 않음.

## 입력 충돌과 대체 경로
- 텍스트·링크·버튼·입력창·선택 영역·파일 드래그에서는 시작하지 않음. 일반 텍스트 선택과 복사를 방해하지 않아야 함.
- 임계 이동량을 넘으면 길게 누르기 후보를 취소하고 기존 드래그를 유지. 전역 preventDefault로 기본 브라우저 동작을 막지 않음.
- 우클릭 메뉴를 대체하지 않음. 터치/펜 동작은 별도 설계 전 미지원으로 명시.
- 눈에 보이는 메뉴 버튼과 키보드 탐색 경로를 함께 제공. 키보드 열기/방향 이동/Esc/focus 복귀 계약 마련.
- reduced motion, 충분한 레이블 크기/대비. 원형 배치가 어려운 보조기술에는 선형 메뉴 표현 제공.

## 기능 착수 시 명세/테스트
QUICKNAV-001: 열기/선택/취소/경계/비활성 항목, 입력 충돌, 한국어 IME, draft·스크롤·대화ID 보존, 반복 열기 후 listener/타이머 해제.
메뉴 표시/이동 지연은 동일 화면·장치에서 측정하며 사이트 전체 성능 정책을 적용.
현재 선택 유지시간, dead zone 크기, 방향 판정 hysteresis, 메뉴 위치, 단축키는 미확정. 실제 사용 피드백으로 결정.
