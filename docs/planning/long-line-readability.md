# 긴 코드 줄 가독성 정리 계획

2026-11-07. 사용자 요청은 지나치게 긴 줄을 실무에서 읽기 좋은 형태로 정리하되 짧은 코드를 억지로 늘리지 않는 것이다. 기능/설계 변경 없이 범위를 제한한다.

## 대상과 유지할 것

- apps/web/src의 TS/TSX를 조사해 주석/단독 문자열/import를 제외하고 180자 초과 코드 줄이 있는 100파일/212줄을 후보로 고정했다. 180자는 이번 선별 기준이며 프로젝트 전체의 강제 줄 길이 규칙이 아니다.
- 후보 파일의 과밀한 코드 줄을 하나씩 찾아 그 구문 범위만 포맷한다. 첫~마지막 긴 줄 사이 전체를 포맷하는 시안은 불필요한 변경이 커 제외했다. Prettier는 완전한 구문 단위로 범위를 확장하므로 해당 구문의 짧은 자식 줄은 같이 정돈될 수 있다. 후보가 아닌 짧은 파일·테스트·CSS·JSON·생성 파일은 포맷하지 않는다.
- 로그인 page는 사용자가 지목한 파일이므로 긴 매개변수/조건문/JSX와 하단 import 위치를 함께 정돈한다. import 간 상대 순서와 나머지 실행문 순서는 유지한다.
- copy-execution은 긴 함수 선언 하나 때문에 실행 본문 전체가 다시 포맷되는 제안을 제외하고, 선언부만 별도로 정돈한다. 클래스/상태 파일도 줄 단위 범위 선택으로 짧은 기존 메서드의 무관한 변경을 줄였다.
- 100자 정도의 읽기 폭, 2칸 들여쓰기, 기존 쌍따옴표/세미콜론/간단한 화살표 매개변수 스타일을 사용한다. 짧은 컴포넌트는 한 줄로 남긴다. 문자열·URL·정규식·모델 지침·SQL 원문을 길이 때문에 쪼개지 않는다.
- 설치된 VS Code Prettier 3.7.4를 일회성 도구로 사용한다. 새 의존성·포매터 설정·함수 추출·변수명 변경·UI 디자인 변경은 하지 않는다.

## 동작 고정과 안전 장치

1. 변경 전 기존 전체 테스트를 실행하고 현재 파일을 .omx/readability-format/before에 복구 사본으로 보존한다. 기존 미커밋 변경을 Git HEAD로 되돌리지 않는다.
2. 포맷 제안은 .omx/readability-format/after에 먼저 생성한다. 문자열/템플릿 내부 자동 포맷은 끈다.
3. TypeScript로 변경 전후 JS/JSX를 컴파일하고, 실행 AST의 순서·문자열/숫자·연산자·변수 선언 종류·template rawText와 import 상대 순서를 비교한다. 타입 전용 문법/주석은 비교 대상에서 제외하고 타입/린트로 확인한다. 괄호만의 차이는 정규화한다. 비교기의 자체 검사도 값·조건·문자·실행 순서 변화가 검출되는지 확인한다.
4. 일반 JSX 줄바꿈은 인접 문자열 조각 수를 바꿀 수 있다. 실행 AST가 달라진 9파일은 기존 단일 줄 텍스트를 명시적 문자열 표현식으로 고정하여 공백/자식 값·순서를 보존한 뒤 포맷한다. 바뀐 결과를 허용하는 느슨한 예외를 추가하지 않는다.
5. 모든 제안의 AST가 같을 때만 적용하고, 적용 직전 원본 hash가 사전 snapshot과 같은지 재검사해 동시 편집을 덮어쓰지 않는다.

## 정리 분류와 검증

이번 냄새는 과밀한 JSX/조건/호출/객체 선언이다. fallback·예외 처리·보안·상태 분기를 제거하거나 추가하지 않는다. 범용 계층이나 들여쓰기용 도우미 함수도 만들지 않는다. 디자인 시안과 실제 기능 구분을 유지한다.

사전/사후 테스트, 타입·린트·서버/기능 경계·빌드, 실제 시안 렌더 smoke와 대표 화면 확인을 진행한다. 별도의 읽기 전용 검토는 snapshot/변경 파일과 선택 범위를 대조한다. API 호출·개인 파일 접근·원본 쓰기·외부 배포는 하지 않는다.

참고: [Prettier API](https://prettier.io/docs/api), [범위/읽기 폭 옵션](https://prettier.io/docs/options). 포맷 범위와 출력 폭은 강제 문장 길이 규칙으로 취급하지 않는다.
