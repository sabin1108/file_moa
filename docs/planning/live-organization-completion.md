# 정식 AI 정리 1~10 작업 계획

2026-11-08. 사용자가 남은 작업 10개 모두 진행하고 본인 조작이 필요한 지점만 알려 달라고 요청했다. 직접 구현/검증으로 진행한다. 이전 native executor는 현재 계정에서 설치 모델 미지원으로 시작에 실패했으므로 병렬/독립 리뷰 완료를 주장하지 않는다.

## 이번 범위와 완료 기준

1. 날짜 근거와 의미를 실제 발췌에서 확인하는 질문, 혼합/애매 자료를 마지막 묶음으로 확인하는 질문을 서버 검증 DTO로 반환한다.
2. 사용자 답은 요청/원본 버전에 묶는다. 답/조건/선택/원본 변경은 이전 제안/검토 승인을 폐기한다. 자동 모델 재요청은 하지 않는다.
3. 명확한 자연어 경로 조건을 기존 폴더 구조와 대조해 제안하고 불명확하면 확인한다. 명시적 UI 선택을 덮어쓰거나 참고/목적지를 탐색 범위로 바꾸지 않는다.
4. 선택한 참고 폴더의 bounded 디렉터리 구조만 읽고 전송 전에 표시한다. 본문/전체 디스크를 자동 수집하지 않는다. 재검사 때 바뀌면 동의를 폐기한다.
5. AI 제안의 복사/이동은 사용자가 검토에서 선택한다. 출발 부모/도착 폴더별로 기존 ManagedFilesController·ManagedFilesDialog에 연결하고, 제안 원본의 해시를 기존 검사 결과와 대조한다.
6. 실행은 기존 보존/권한/충돌/재검사/journal 엔진을 사용한다. 묶음별로 명시적 실행하고 결과/부분 실패/복구 기록을 추적한다. 새 목적지는 기존 공통 picker/생성 흐름에서 명시적으로 만든다. AI 응답만으로 폴더를 만들거나 파일을 쓰지 않는다.
7. 전체 선택 해제는 선택 모드를 유지하고 마지막 개별 해제는 종료한다.
8. 합성 단위/브라우저와 실제 production·DB 예약 경합·공급자(합성 자료) 검증을 구분한다. 사용자 자격증명/네이티브 OS 조작/물리 IME가 필요하면 구체적인 준비된 화면에서 요청한다. 그 결과를 자동 검사로 대체해 통과라고 보고하지 않는다.

## 변경 책임과 재사용

- shared live review 계약/파서: 서버 응답의 질문/날짜 근거/명시 답변 검증. 기존 샘플 계약은 유지한다.
- server live-organization/generation: 질문/답변 정책, 기존 인증/Origin/입력/예약·모델 검증 유지.
- local-folders services/session: 참고 구조 읽기/재검사와 제안 버전→기존 managed 검사 연결. 파일 실행 코드를 새로 만들지 않는다.
- organization controller/UI: 답변 상태·무효화, 공통 picker/폼/행과 검토/실행 연결. Provider 수명/F5 무재실행 유지.
- tests: 신뢰 경계·실패·상태 전이부터 고정하고 기존 원본/샘플/동시성 회귀를 실행한다.

## 검증 순서

실패 테스트 → 최소 구현 → 관련 테스트 → 전체 테스트/타입/린트/경계 → 빌드 → 실제 브라우저의 질문/답/검토/원본 변경·취소/복사·이동/부분 실패·복구/초점/좁은 화면/IME 자동 이벤트 → 실제 환경 확인 → 성능/코드 설명/원장/인수인계.

보안·원본 보호·명시 전송·자동 재시도 금지·공급자 비용 한도는 유지한다. 개인 원본의 임의 수집/자동 전송/배포는 하지 않는다. 이번 10개 밖 PDF/XLSX/다중 루트/일반 채팅 전체 구현으로 확장하지 않는다.
