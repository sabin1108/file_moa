# 일상 요청 평가 확장·불필요 시안 정리 계획

2026-11-07 사용자 요청. 두 실모델 예시만으로 품질을 대표하지 않고 일상 사용자가 요청할 법한 의도를 추려 평가한다. 실제 사용자 조사/빈도 자료는 없으므로 후보와 기대값은 도우미 초안으로 표시한다.

## 변경 범위

1. 기존 request-v1의 16 development/4 holdout을 보존하고 회사 지출·재고·미수금·반품·지원·입사, 여행·회의, 공부, 연구, 개발, 수치, 해당 자료 없음, 기간 필터와 날짜 그룹 분리 요청을 추가한다. 목표 40 development/4 holdout. 의도 그룹·형식·범위·부정/보류를 연결하고 지원하지 않는 요청은 실제 품질 분모와 분리한다.
2. 기존 후보 함수·응답 파서·평가기·실제 서버 호출을 재사용한다. 후보 누락이 생기면 기대값을 맞추지 않고 실패 사례를 고정한 뒤 검색 원인을 수정한다. holdout을 제품 튜닝에 사용하지 않는다. 후보 함수 변경은 필요가 확인된 경우만 한다.
3. 회사/수치/공부/연구/개발/결과 없음의 새 대표 요청 6개를 기존 무료 사용 한도 안에서 각 1회 평가한다. 생성 자동 재시도·한도 우회·정답/유보 전송·개인 파일 사용은 하지 않는다. 한도 거절은 남기고 중단한다.
4. 참조 그래프에서 고립된 prototype 4컴포넌트(`SourcePanel`, `DocumentInspector`, `FileList`, `FolderOverview`)와 확인된 전용 CSS만 삭제한다. `/demo`의 준비된 제안/실제 API/리뷰/되돌림은 살아 있는 기능이다. `/preview` 28 scene/5 screen과 카탈로그, 디자인 자료·과거 검증 증거는 보존한다. 미완성이라는 이유만으로 기능을 지우지 않는다.

## 동작 고정과 삭제 근거

- 변경 전 sample-workspace/server 관련 테스트를 실행한다. 정적 미사용 컴포넌트에는 구현을 흉내내는 테스트를 만들지 않는다.
- 기존 타입·린트·빌드와 삭제 후 실제 preview/demo 경로 렌더링을 확인한다. 참조 없음은 explorer의 전체 import/reference 조사로 확인하며 CSS는 별도 확인한다.
- 기존 사용자 변경은 보존한다. 삭제 파일의 변경 상태를 확인하고 필요하면 무시된 `.omx` 아래 복구 사본을 둔다. 원본 사용자 파일·비밀·DB/인증 기록은 삭제 대상이 아니다.
- fallback 조사: sample의 준비된 제안은 명시적으로 선택하는 합성 기능이며 실제 AI 실패를 성공으로 바꾸는 fallback이 아니므로 유지한다. 이 정리에서 광범위/모호한 fallback 분기나 호환 경계를 바꾸지 않는다.

## 검증·중단 기준

확장된 요청별 무결성/후보/판정 검사, 관련 회귀와 전체 테스트, 타입·린트·경계·빌드가 통과하고 삭제 후 경로가 유지되면 완료한다. 실제 모델 결과는 호출별 기록과 제한된 요청 수로 보고한다. 실제 실패를 숨기거나 기대값을 모델 출력에 맞춰 바꾸지 않는다. 유보/개인 파일/외부 배포/정식 AI 연결은 이번 작업에서 진행하지 않는다.
