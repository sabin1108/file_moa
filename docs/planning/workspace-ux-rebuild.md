# 대화·기록함 UX 재구성 — 2026-11-09

사용자는 기능을 만든 본인도 사용법을 알기 어렵다고 지적했다. 긴 안내와 동일한 무게의 글/버튼을 줄이는 전면 UI 변경이며, 새 인증/저장/AI/프로젝트 기능을 만드는 작업은 아니다. 기존 안내와 폼을 다른 곳에 중복해 남기지 않는다.

## 확정할 화면 구조

1. 입력창 위에는 자료 선택, 저장 상태/저장 설정, 대화 설정의 짧은 조작만 남긴다. 공급자와 자료 전송 동의는 짧게 알리고 상세 정책은 설정에서 연다. 전송 범위/실제 발췌와 명시 동의는 자료를 보낼 때 계속 확인한다.
2. 같은 기록 drawer를 기록/참고 자료/대화 설정으로 나눈다. 기록은 종류별 목록·검색·하나의 새 항목 버튼이 중심이다. 기록 제목은 큰 열기 버튼, 삭제는 항목 관리 메뉴로 구별한다. 저장 위치와 사용량·설명은 별도 관리 화면으로 옮긴다.
3. 저장 위치가 없을 때만 연결 안내와 선택 버튼을 먼저 보여준다. 기록 읽기 폴더와 참고 원본 폴더는 이름/목적을 구분한다. 보관 시작은 명시 행동이고 임시 대화를 묵시적으로 저장하지 않는다. 원본/권한/삭제/암호화 한계는 필요한 결정 위치에서 짧게 확인한다.
4. 결과물/기억/프로필 편집은 제목·본문·저장을 우선한다. 내보내기·버전·프로젝트 식별자는 부가 설정으로 분리한다. 현재 프로젝트 저장소가 없으므로 가짜 이름 목록이나 이름→ID 변환을 만들지 않는다. 기억 사용 동의/승인/범위·미저장 편집·연결 revision 삭제 보호를 유지한다.
5. 인증 종이/폴더 무대는 폼 위에서 제거해 AuthShell 왼쪽의 세 폴더 그림을 크게 대체한다. 실제 단계와 연결하고 입력 위에는 짧은 의미 있는 단계 표시만 둔다. 단계가 없는 로그인에서는 자료를 모으는 장식 모션을 표시하며 실제 인증 진행률로 표현하지 않는다. 작은 화면은 입력 공간을 우선한다. 기존 3000/1100/3600ms 키프레임 유지.

## 수정 경계

- UI/표시·접힘·검색·drawer·초점만 변경한다. 기존 controller/repository/ServerAction과 owner·원본·외부 전송 동의·공유10회 제한을 유지한다.
- 대화/초안/스크롤/편집 상태를 패널 변경으로 unmount하거나 초기화하지 않는다. 연결 변경/삭제 확인/응답 중 전환/실패 저장 경로를 회귀로 고정한다.
- 기존 버튼/아이콘/SettingsRow/drawer 수명을 재사용하고 새 의존성을 추가하지 않는다. 실제 반복된 목록/관리/설명만 분리한다.

## 검증 순서

현재 동작을 회귀 검사로 확인→UI를 책임별로 대체→기본 화면 문구/명확한 행동/키보드·좁은 화면·미저장·동의·삭제·저장 복원을 제품 코드와 격리 OPFS에서 검증→타입/린트/전체/경계/build→실제 Next 게스트/임시 인증·자산 비용→dev3034 복구. 유료 모델·운영 DB 변경·배포 없음. 실제 사용자 UX 최종 평가는 사용자 피드백으로 남긴다.

사용자의 최신 전면 개편 지시가 이전 승인 UI의 이 범위를 대체한다. 계획에 따른 구현·검증을 마쳤으며 실제 결과와 한계는 [검증 보고서](../verification/workspace-ux-rebuild/README.md)를 따른다. 사용자 체감의 최종 판단은 직접 사용 피드백으로 확인한다.
