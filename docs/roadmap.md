# 실행 순서와 검증

## 최신 완료 — 2026-10-29 목적지 탐색·선택

사용자가 요청한 상대 경로 선택을 변경 계획에 연결했다. 하위/상위/연결 폴더를 탐색해 목적지 입력을 채우며 주 목록과 선택은 유지한다. 경고는 황갈색, 오류는 적색으로 명확하게 구분했다. 읽기 취소·늦은 응답·권한 상실·부분 목록과 키보드 경계를 검증했다. [명세](specs/plan-destination-picker.md), [실행 증거](verification/plan-destination-picker/README.md). 아래 이전 절의 목적지 탐색 후보는 이 구현으로 완료됐다. 로그인 보류와 원본 쓰기 별도 계약은 유지한다.

## 사용자 피드백 우선 수정 — 2026-10-29

목적지 탐색을 시작하기 전에 브라우저 뒤로/앞으로와 파일 우선 화면을 구현했다. 검색·선택 도구는 요청해서 펼치며 모바일 첫 화면에서 파일이 먼저 보이고 데스크톱의 중앙 카드 바깥 여백을 제거했다. 폴더/문서 기록은 Provider 메모리에서만 관리하고 연결 변경에 무효화한다. [명세](specs/file-browser-navigation.md), [검증](verification/file-browser-navigation/README.md). 후속 목적지 선택은 위 최신 완료 절을 따른다.

## 다음 단위 완료 — 2026-10-29 현재 폴더 이름 검색

연결 → 탐색 → **이름 검색 → 선택 유지 → 미리보기/변경 계획 검토**를 연결했다. 검색은 현재 읽은 최대 1,000개 직접 자식 안에서만 동작한다. 숨겨진 선택을 보존하고 표시 결과만 전체 선택/해제하며, 한글 조합 중에는 목록을 유지한다. [명세](specs/file-name-search.md), [현재 실행 증거](verification/file-name-search/README.md).

사용자 지시: **로그인은 추가 요청 전까지 구현하지 않는다.** 다음의 작은 기능을 기존 흐름과 연결하고 명세 → 실패 조건/테스트 → 구현 → 검증 순서를 유지한다. 다음 후보는 변경 계획에서 목적지 경로를 직접 입력하는 부담을 줄이는 **연결 폴더 안 목적지 탐색·선택**이다. 읽기 전용 탐색과 계획 입력을 연결하는 단위이며 원본 적용을 포함하지 않는다. 선택한 목적지/현재 목록 수명·읽기 취소·권한 상실·부분 목록 계약을 먼저 정의한다. 아직 구현 완료나 확정된 상세 설계로 기록하지 않는다.

Gothic A1은 공식 자료를 확인한 서체 후보로 DESIGN.md에 기록했다. 새 외부 서비스·유료 호출·인증 제공자·실제 원본 쓰기는 이번 구현에 포함하지 않았다.

## 현재 진행 위치 — 2026-10-29

선택 파일의 읽기 전용 변경 계획 검토를 구현했다. 실제 출발·목적지 이름을 재조회하고 이동/복사/확장자 분류의 도착 위치, 충돌과 미확인 범위를 표시한다. [계약](specs/file-change-plan.md), [검증과 코드 리뷰 순서](verification/file-change-plan/README.md). 아래 28일의 다음 작업 3번은 완료된 단위다.

현재 폴더 파일명 검색/필터를 구현했다. [SEARCH-001~006 계약](specs/file-name-search.md)에 따라 이미 표시된 직접 자식 이름만 검색하고, 검색 밖 선택을 보존하면서 표시된 파일만 추가·해제한다. 1,000개 일부 목록, 경로·연결 수명의 초기화, 미리보기 왕복, 한국어 IME 조합과 읽기 전용 경계를 검증했다. 다음 작은 후보는 검색 결과·선택·계획 검토와 충돌하지 않는 **MD/TXT 본문 안 찾기**의 요구사항 검토다. 이는 파일 본문 읽기 한도·동의·검색 결과 표현·선택 자료 전송과의 경계를 먼저 명세하며, 재귀 전체 검색·원본 적용·로그인 구현으로 자동 확장하지 않는다.

## 현재 진행 위치 — 2026-10-28

localhost에서 자료 폴더 연결·목록 탐색·MD/TXT 원문 미리보기를 구현했다. 연결 성공 후 내 파일로 이동하며, 취소/실패/늦은 완료에는 화면을 바꾸지 않는다. 기능·공통 UI·시안은 각각 features/components/prototypes로 구분했다. 실제 인증·AI·원본 쓰기는 미구현이다. 아래 25일 로드맵의 이미 완료된 부분과 구분한다.

사용자의 후속 요청으로 **현재 폴더 파일 다중 선택과 연결 관리 팝업**을 구현했다. [명세](specs/file-selection-and-connection-dialog.md)와 [검증](verification/file-selection-dialog/README.md)을 따른다. 다음 단위는 선택 파일의 읽기 전용 변경 계획 검토이며 원본 쓰기를 자동으로 포함하지 않는다.

1. 완료: 파일 checkbox·선택 수·표시된 파일 전체 선택·해제. `components/listing/SourceFileRow.tsx`와 `components/listing/FileSelectionToolbar.tsx`가 표시를 맡는다.
2. 완료: 현재 폴더 범위 선택을 기존 `store/source-listing-controller.ts`에서 관리한다. 미리보기·화면 왕복은 보존하며 폴더 이동/연결 교체·해제·소유자 변경에 비운다. 새로고침 성공 때 표시 파일만 유지하고 실패 때는 보존하되 추가 선택을 막는다.
3. 선택 후 이동/복사/분류의 **변경 계획 검토**를 읽기 전용으로 연결한다. 출발/도착·동일 이름 충돌·예상 결과를 보여준다. 실제 원본 적용은 쓰기 권한·hash 재검사·journal·부분 실패/복구 계약 뒤에 구현한다.

정리 대상 선택과 AI 참고 자료 선택은 별도 상태/행동으로 구분한다. AI 전송·PDF 추출·모델 호출을 한 단위에 묶지 않는다. [FILE-001](specs/workflows.md), [코드 위치 안내](code-map.md)를 기준으로 작은 명세→실패 테스트→구현 단위로 진행한다.

2026-10-25. 시안은 사용자 승인 상태이며 기능을 연결하면서 필요한 UI를 수정한다. 실제 제품 기능은 아직 미완료다. [S0 실행 기록](verification/s0/README.md)과 [로컬 보관 계약](specs/local-ai-storage.md)이 과거 서버 중심 계획보다 우선한다.

## 다음 구현 단계

1. **S0 마무리:** 실제 브라우저 폴더 선택·권한 거절/철회/재연결과 [중단 저장 복구](specs/local-record-recovery.md)를 확인한다. 격리 OPFS 검증을 외부 폴더 권한 검증으로 대체하지 않는다.
2. **로컬 보관 연결:** 승인된 기록 형식·버전·충돌·임시 대화·계정별 핸들 분리를 앱에 연결한다. 계정별 핸들 저장소/늦은 응답 차단 기반과 가상 A/B 검증은 완료했다([계약](specs/account-folder-connections.md)). 실제 인증 세션·다른 탭 계정 변경·제품 화면 연결은 남아 있다. 합성 자료로 저장→재열기→복구를 검증한다.
3. **자료 읽기:** MD/TXT 탐색·검색·미리보기·선택과 텍스트 PDF 추출을 검증한다. OCR과 PDF 출력은 별도 범위다. 검색·캐시는 로컬 보관 계약 안에서 설계한다.
4. **인증 기반:** Google/Naver/Kakao 제공자 조건과 최소 DB/세션/workspace 구조. A/B 접근·계정 전환·만료를 실제 연결로 확인한다. 제공자 설정 조사는 앞 단계와 병행할 수 있다.
5. **모델·비용:** 작은 합성 보고서/분류 평가셋에서 정확도·근거·한국어·규칙 준수·지연·작업당 비용 비교. 모델·예산·과금·배포는 미정이며 유료 호출은 승인된 범위에서 실행한다.
6. **자료로 문서 만들기:** 선택·전송 범위 확인 → 요청/부족 정보 확인 → 초안/근거 → 수정 → 새 파일 저장. 스트림·중지·단절·중복 요청과 로컬 기록 연결.
7. **기억·백업·삭제:** 사용자 승인 및 적용 범위, 일회성 지시/타인 정보 구분, 삭제 후 부활 차단, 내보내기·가져오기·원본 재연결.
8. **실제 파일 정리:** 계획·변경 전후 비교·별도 쓰기권한·hash 재검사·충돌·journal·부분 실패/복구. 합성 폴더부터 검증하며 개인 노트 읽기 허용으로 원본 쓰기를 시작하지 않는다.
9. **공개 검증:** 3종 로그인, 계정·자료 삭제, 비용 한도·악용 방지, 공급자 처리 안내, 배포/관측/복구 기준 확인.

## 단계별 완료 기준

기능 명세·실패 조건 → 작은 핵심 테스트 → 구현 → 관련 검증 순서다. 계획한 사례와 실행해서 통과한 테스트를 구분한다. 실제 외부 연결 없이 통과한 검사를 인증·AI 준비 완료로 보고하지 않는다.

실제 기능 변경은 관련 테스트·typecheck·lint·build를 수행한다. 제품 UI를 연결할 때 키보드·IME·좁은 화면·실제 권한을 확인하고 [성능 정책](performance-policy.md)에 따라 사이트 전체/경로별 기준선을 기록한다. 동일 조건의 기존 여정 회귀와 신규 기능 비용을 나눠 비교한다.

정적 시안만 바꾸는 경우에는 타입·린트·빌드·화면 확인을 적용하고 기능 테스트/Lighthouse를 반복하지 않는다. 현재 승인 화면은 [최종 프로토타입](prototype/README.md), 자세한 실패 조건은 [업무 흐름](specs/workflows.md), 테스트 구성은 [테스트 전략](testing-strategy.md)을 따른다.

후속 범위: [원형 메뉴](planning/radial-menu.md), 성장·고급 폴더 시각화, OCR, 로컬 모델, 로컬 암호화. 별도 범위 결정 없이 핵심 구현에 추가하지 않는다.
