2026-11-17. 기준 배포 `b29aacf`, 직전 로컬 대화 개편 이후의 후속 작업이다. 이번 내용은 로컬 구현이며 새 배포가 아니다.

## 사용자 요청과 결과

정리 카드를 눌러도 다시 첫 채팅을 요구하고, 작은 폴더 목록과 중복 조건 폼을 조작해야 했던 흐름을 바꿨다. 카드 선택만으로 첫 질문을 시작한다. 폴더 → 하위 포함 여부 → 정리 기준 → 목적지 → 자료/발췌 확인 → 명시적 AI 분석 순서에서 부족한 조건만 묻는다. 기준은 같은 채팅으로 받고, 위치를 고를 때만 큰 탐색창을 연다. 검색에서 고른 자료도 같은 안내를 사용한다.

`작업 선택`은 온보딩을 거치지 않고 네 작업 카드로 돌아가며 기존 초안을 보존한다. `이전 질문`은 실제 지나온 질문을 되짚고 기준/목적지 입력을 보존한다. 하위 폴더를 제외했다가 다시 포함하는 경로도 확인했다. 기존 조건 폼 컴포넌트172줄을 제거했고, 버튼은 `자료 확인 실행`과 `AI 분석 실행`으로 용도를 구별했다. 자료 준비/대화 안내는 새 모델 호출을 추가하지 않는다.

폴더 선택은 기존 picker를 공통 SelectionWorkspaceDialog에서 사용한다. 데스크톱 최대1120px, 높이 최대960px/화면 여유32px이며 휴대폰은 전체 화면이다. 폴더/파일은 넓은 화면에서 두 열로 표시하고, 48px 폴더 행과 본문 크기를 줄이지 않는다. 목록은 240px에서 최대52dvh/560px로 늘렸다. 긴 사이드바도 스크롤 면 안에 머물도록 flex-shrink 충돌을 고쳤다.

자료는 자동 추천 밖도 직접 선택할 수 있다. UI와 controller의 후보 ID 차단을 함께 없앴다. 수·발췌량 초과는 선택을 몰래 지우거나 줄이는 대신 전송 전에 알리고, 선택 변경은 이전 동의/제안을 폐기한다. 실제 발췌는 큰 자료 선택창에서 확인한다.

## 오류 대응과 실제 원인 구분

실제 큰 합성 폴더에서 원본 재검사가40문서까지만 허용해 전송 전에 실패하는 경로를 재현했다. 이 검사를 기존500문서 경계와 맞추고200/500문서의 재검사 회귀를 추가했다. 검사 실패 뒤에는 조건을 유지한 자료 확인 질문으로 돌아간다.

공급자 인증/설정, 토큰 초과, 출력 중단, 잘못된 JSON/응답 형식·원문 근거, 네트워크·공급자 장애를 구별한다. 선택은 유지하고 재동의 후 직접 다시 실행할 수 있다. 출력 JSON에도 알려진 문서 ID와 서버 검증기의 길이/개수 조건을 사용한다. [OpenAI 공식 Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs)의 incomplete 처리와 스키마 조건을 확인했다. 원문·경로·키·공급자 오류 본문은 로그에 남기지 않는다.

사용자가 운영 화면에서 본14개 자료의 `unavailable` 오류 자체는 운영 로그/실제 호출 근거가 없어 원인을 확정하지 않았다. 이 작업은 모든 실제 모델 판단 실패를 해결했다는 증거가 아니다.
