## 연결된 목록과 새 선택 비용

실제 UI/controller/OPFS를 사용하되 OS 선택창·권한 응답은 합성 경계다. 390×1000px 전체 선택 각각 3회. CDP 클릭·React 반영·DOM polling을 포함하므로 사용자 INP나 순수 함수 실행시간으로 해석하지 않는다.

| 데이터 파일 수 | 표시/선택 상한 | 전체 선택 중앙값 ms | 범위 ms |
| ---: | ---: | ---: | ---: |
| 100 | 100 | 29.1 | 17.5–32.1 |
| 1000 | 1000 | 277.9 | 167.1–290.7 |
| 1001 | 1000 | 320.7 | 130.0–321.0 |

[동작 원자료](browser/checks.json). 1,000항목 선택은 167–291ms로 관찰됐다. 1,001 fixture는 일부 1,000개만 선택하며 130–321ms다. 입력 지연 인증이나 최적화 완료로 보고하지 않는다. 느린 장치·실제 디스크·지속 사용 p75는 미측정이며 더 큰 규모가 필요하면 표시 범위/가상화의 별도 명세와 측정부터 검토한다. React transition을 추가해 선택 반응을 지연시키거나 CSS 전환으로 비용을 감추지 않았다.

기존 [목록](listing/browser-checks.json)과 [2MiB 본문 미리보기](preview/checks.json)의 3회 원자료도 보관했다. 서버/API/DB/모델이 없는 현재 기능에서 해당 비용은 미측정이며 0으로 표기하지 않는다. Lighthouse는 미연결 초기 화면의 desktop/mobile 단발 기준선으로 별도 기록한다.
