# 로컬 미리보기 로그인 진입 복구 — 2026-11-11

사용자는 소개 화면에서 로그인으로 들어가면 오류가 난다고 보고했다. 로그인 route의 requireGuest→getAuthenticatedSession은 쿠키 캐시를 끄고 서버에서 세션을 확인한다. 이전 미리보기 서버 로그에는 Prisma EACCES와 library/protocol 인증 실패 뒤 ‘로그인 상태를 확인하지 못했습니다’가 기록됐다.

제한된 실행 환경에서 띄운 미리보기 서버를 종료하고, 인증 DB에 접근 가능한 실행 권한으로 동일한 production 코드를 다시 시작했다. 인증 가드·DB설정·환경변수·쿠키·제품 코드는 수정하지 않았다. DB 실패를 비로그인으로 취급하는 우회도 추가하지 않았다.

복구 검증: 쿠키 없는GET /login은HTTP200·비밀번호 필드 포함·세션 오류 없음. 기존 세션의 ego 브라우저에서/login은/로 이동하고 main표시·세션/작업공간/Application오류없음을 확인했다. 새 서버 로그의EACCES/세션실패0건. 비밀번호 제출·OAuth·새 계정 인증은 이번에 실행하지 않았다. 테스트/빌드 결과를 새 로그인 성공으로 대체하지 않는다.

현재3034는 권한을 바로잡아 시작한 production 서버다. 후속 미리보기 재시작에서도 인증 DB 연결이 가능한 실행 환경을 유지하고, EACCES가 다시 나면 인증 코드를 우회하지 말고 프로세스 실행 경계를 먼저 확인한다. 산출물 `.omx/verification/login-recovery-20261111/`. 운영 배포 변경 없음.
