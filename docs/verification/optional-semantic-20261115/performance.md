# 선택 의미 검색 비용 기록

Windows 데스크톱 Chromium의 합성 lab 측정이다. 네트워크·CPU throttling은 하지 않았으며 HTTP Cache를 공유했다. 실제 사용자 전체나 모바일 성능의 보장이 아니다.

## 빌드와 기본 방문

직전 로컬 후속 빌드의 전체 JS/CSS47개3,610,476bytes에서 최종51개4,523,292bytes로912,816bytes 늘었다. 이는 전체 경로와 지연 로딩 Worker/SDK를 합친 원본 파일 크기이며 첫 방문 전송량이 아니다. 공개 실행 파일2개21,640,503bytes는 별도이고, 모델 가중치135,138,424bytes는 앱 서버/저장소에 포함하지 않았다. 실행 파일 준비 스크립트는 고정된 설치 패키지에서 복사·hash 확인만 하며 모델을 다운로드하지 않는다.

Ego에서11게스트 경로×390/1440px×3회로66표본을 수집했다. 자동 모델/실행 파일 다운로드 요청은0개다. 인증이 필요한 경로의 도착은 로그인/소개로의 리다이렉트를 포함한다. 이 표본은 마지막 안내 문구와 본문 조건 검사의 Worker 이동 전 빌드에서 측정했으며, 최종 빌드 전체 asset 수치는 별도로 기록했다. 전후 동일 표본을 다시 만들지 않아 개선율/회귀율, 인증 검색 진입 속도나 field INP를 주장하지 않는다.

## 명시 설치와 실행

| 항목 | 관측 |
| --- | --- |
| 모델+토크나이저/설정 | 135,138,424bytes |
| ORT 실행 파일 | 21,640,503bytes |
| 선택 다운로드 합계 | 156,778,927bytes, 약149.5MiB |
| 최적화 Next Worker 설치+합성 질문 | 약6.6초, 공개 HTTP Cache/네트워크 조건 |
| 설치된 모델의 새 Worker+짧은 질문 | 약1.4~1.7초 |
| 재사용 짧은 질문19개 | 약20~35ms |
| 합성20문서 벡터 준비 | 약2.35초 |
| 긴 합성 문서64구간 준비 | 23.76초, 일부 본문으로 표시 |
| 실행 중 취소 응답 | 약82ms |
| 4,096구간 Worker 점수 계산 | 44.7ms, 관측 main long task0 |
| 4,096벡터 IDB 읽기/검증3회 | 약10.6~12.6ms, 관측 main long task0 |
| 본문10만 날짜의 조건 검사 | Worker 약237ms, 관측 main long task0 |

50ms 이상 task를 lab에서 관측하지 않았다는 뜻이며, 개별 사용자 입력의 field INP 수치가 아니다. 모델 문서 구간화·추론·전체 본문 조건/날짜 검사는 Worker에 둔다. 벡터 행의 shape/norm 검사는 현재 main의 IndexedDB 경계에도 남아 있고 위 상한에서 측정했다. 범위와 무관한 전체 본문 캐시 getAll은 쓰지 않는다.

## 메모리

검증 전용 Worker probe는 공개 ORT가 만든 WebAssembly.Memory buffer 크기만 관측했다. 짧은 질문의 관측 최댓값345,309,184bytes, 약329.3MiB다. JS heap, tokenizer, 내려받은 ONNX 응답 복사, 무결성 검사/캐시 버퍼, 브라우저 전체 메모리를 포함하지 않는다. 따라서 전체 peak RAM은 미측정이며, 실제 설치 중이나 긴 문서 처리 중에는 더 클 수 있다. Node의 이전 약449MB RSS를 브라우저 값으로 바꾸어 쓰지 않았다. UI는 수백MiB의 추가 메모리와 저사양 기기 실패 가능성을 설치 전에 안내한다.

원자료 `.omx/verification/optional-semantic-20261115/`의 routes/evaluation/memory/storage/flows/worker-evidence/production-worker JSON과 최종 최적화 Worker 결과를 함께 본다. [작은 수치/검증 요약](evidence.json)은 비밀이나 실제 개인 원문을 포함하지 않는다. 재현과 한계는 [검증 문서](README.md)를 따른다.
