# 데모 대화·자료 작업 반영

대상 기준 커밋은 `d721260cc49a6fb16d146126b241014f24e27625`이다. 아래 결과는 이번 수정과 검증이며 개인 자료 폴더나 운영 계정의 파일 작업을 검증한 결과가 아니다.

## 변경

- 데모의 고정 정리 절차를 공용 `OrganizationPreparationController`에 연결했다. 범위·하위 범위·기준·목적지 질문, 채팅 답변, 이전 질문, 작업 선택, 공통 또는 개별 확인 답변을 사용한다. 개인 폴더 권한이나 가짜 계정 소유자를 만들어 연결하지 않는다.
- 자료 질문과 정리에서 카탈로그 84개 전체를 직접 선택할 수 있다. 데모는 최대 100개·발췌 50,000자로 제한하고 정리는 20개 단위의 공용 묶음 처리로 분석한다. 방문자·전체 일일 요청 한도는 유지하며 자동 재시도하지 않는다. 정리 대기는 최대 120초, 자료 질문은 최대 60초이고 세션 만료보다 길어지지 않는다.
- 공용 큰 선택창 안의 자료 목록도 중첩 스크롤을 제거했다. 정리 계획은 공용 구조 비교를 먼저 표시하고 파일별 목적지 조정은 펼쳐서 사용한다. 샘플 변경과 되돌리기만 수행한다.
- 중요도 전용 요청에서는 원문에 날짜가 있어도 날짜 폴더를 만들지 않는다. 제외 답변은 중요도 기준을 없애지 않는다. 응답에서 빠진 자료는 임의로 등급을 매기지 않고 확인 대상으로 남긴다.
- 실제 외부 AI 응답에서 빈 질문 목록, 완성된 JSON 뒤의 표시 문자열, 중요도 전용 null 날짜 누락, 원문의 조사 변경을 관측했다. 완성된 단일 객체의 표시 문자열만 분리하고 잘린 JSON·두 개의 JSON 값은 거부한다. 중요도 계약에서만 빠진 null 날짜를 확정하며, 틀린 인용이 있는 자료는 적용 후보에서 빼고 확인 대상으로 격리한다. 다른 경로·날짜·답변 검증은 계속 수행한다.
- AI에는 서버가 만든 실제 인용 후보를 제공한다. 반환 인용은 해당 문서의 실제 발췌와 다시 비교하며 잘못된 인용을 교정하거나 만들어 내지 않는다.

## 검증

관련 회귀 검사 42개 파일·469개 테스트와 전체 제품·도메인 검사 184개 파일·1,675개 테스트를 통과했다. `pnpm typecheck`, `pnpm lint`, `pnpm build`, 서버·기능 경계 검사를 통과했다. 린트에는 기존 `_count` 경고 1개가 남아 있다. 경로를 지정하지 않은 테스트 실행은 기존 `.omx` 진단용 파일까지 발견하므로 중지하고 제품·도메인 경로를 명시해 전체 검사를 수행했다.

실제 브라우저에서 정리 시작 → 채팅 조건 지정 → 42개 자료 중 마지막 항목 선택 해제 → 전송 → 계획 검토 → 샘플 적용 → 되돌리기와, 공통 목적지 지정 → 재분석 → 정리 조건으로 돌아가 이전 계획 제거를 확인했다. 자료 질문에서는 42개 선택, 전송 전 무호출, 실제 대기 로더, 사용자 입력 표시, 출처 연결과 합성 IME 전송 방지를 확인했다. 이전 대화 32개 메시지가 같은 영역에 남고 나/모아 구역이 구분되었다.

390·768·1440·1920px에서 선택창 너비는 각각 390·724·1120·1120px이고, 본문 높이는 760·716·716·716px이었다. 내부 목록의 별도 최대 높이와 가로 넘침이 없으며 키보드로 마지막 자료까지 이동했다. 이는 합성 브라우저 자료와 실측 화면 크기의 관측이며 물리 기기·물리 IME 결과가 아니다.

최종 빌드의 전체 정적 JS/CSS는 54개·4,564,934바이트로 이전 검증 기록 4,575,932바이트보다 10,998바이트 작았다. 공용 UI를 재사용하고 예전 데모 화면을 제거한 결과를 포함한 산출물 비교다. 특정 페이지의 실제 전송량, 최초 응답 시간, 현장 INP·메모리·모델 속도 개선을 뜻하지 않는다. 인증된 운영 경로별 성능은 이번 작업에서 재측정하지 않았다.

## 실제 공급자

개인 자료 대신 제공된 안전한 데모 카탈로그만 사용했다. 운영 DB의 요청 한도 예약은 합성 대체했고 실제 공급자 생성과 응답 검증을 수행했다. 따라서 운영 초대 쿠키·실제 DB 예약·한도 경계까지 검증했다는 뜻은 아니다.

최종 `gpt-6-luna` 중요도 요청에서 84개 중 82개는 상·중·하 분류 제안, 내용이 섞인 `text-015`와 빈 `empty-note` 2개는 확인 질문으로 반환되었다. 5회 생성의 합계 사용량은 입력 42,820·출력 5,915·합계 48,735토큰이었다. 별도의 전체 자료 질문은 인용 4개가 실제 발췌 검증을 통과했으며 입력 9,179·출력 313·합계 9,492토큰이었다. 이 수치는 성공한 대표 요청의 값이며 이전 실패를 포함한 전체 비용이 아니다.

진단 중 실패한 응답도 보존하고 원인별 재생 검사에 사용했다. 실패 원문을 임의 정정하거나 통과한 것처럼 처리하지 않았다. 원시 공급자 응답·키·초대 토큰·개인 기록은 커밋 대상에서 제외한다.

## 한계

모든 자연어 요청의 정답이나 성공을 보장하지 않는다. 모호한 조건과 근거가 부족한 자료는 질문으로 확인한다. 미완료 준비 상태에서 새로고침하면 대화는 남고 조건을 다시 준비한다. 완료된 샘플 계획·자료 선택·적용·되돌리기 기록은 세션 보관 경계로 검증한다. 실제 개인 디스크·실제 운영 DB·물리 IME·실제 의미 검색 모델은 이번 작업에서 실행하지 않았다.
