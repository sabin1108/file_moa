# 정리 소개 문구와 예시의 위치 유지

사용자는 ‘정리는 가볍게. 결정은 내 손으로.’와 이어지는 설명이 위로 올라갈 필요가 없다고 지적했다. 실제 소스에서 문구 자체에 이동 애니메이션은 없었고, 설명은 일반 흐름으로 지나가고 정리 예시만 sticky로 남는 구조였다.

## 변경

- `ScrollStories.tsx`: 기존 문구를 `OrganizationDemo`의 heading 표시 영역으로 전달한다. 문구와 의미, section의 제목 연결은 유지한다.
- `OrganizationDemo.tsx`: 설명과 기존 정리 예시를 같은 sticky 영역에 배치한다. 기존 상태·observer·애니메이션 완료 순서는 변경하지 않았다.
- `onboarding-motion.module.css`: 설명을 포함한 영역의 상단을 고정한다. 낮은 화면에서는 제목 크기·여백·최소 예시 높이를 줄이고, 휴대폰 행을84px로 맞춰 처음·완료 모두 화면에 들어오게 한다. 초기390×700 검사에서는 아래가 약14px 벗어나 이를 수정했다.

새 패키지·컴포넌트 계층·이미지·파일 쓰기·AI 호출은 추가하지 않는다. 공개/체험 소개는 같은 구현을 사용한다.

## 검증 기준과 근거

- 관련 테스트2파일7개, typecheck, lint, production build22경로 통과. 마지막 CSS 수정 뒤 lint/build를 다시 실행해 통과했다. `git diff --check` 통과.
- Ego에서1440×900,1440×720,768×1024,768×720,390×844,390×700의6개 크기를 확인했다. 각 정리 전/계획 확인/완료의18상태에서 같은 문구 위치, 헤더 아래 노출, 문구와 예시의 겹침 없음, 전체 예시의 화면 내 노출, 가로 넘침 없음을 확인했다.
- 단계별 제목의 위쪽 위치 차이는0px. 데스크톱/태블릿96px, 휴대폰844높이80px/700높이72px였다.390×700의 전체 예시 끝은694.7px로 화면 안에 들어왔다. 최종6개 화면을 직접 확인했다.
- 단계는 실제 스크롤과 기존 observer로 바뀌며 CSS 전환이 끝난 뒤 검사한다. 임의의 React 상태 주입이나 실제 사용자 파일은 사용하지 않는다.
- 로컬 브라우저 근거: `.taste-skill/organization-heading-after.json`, `organization-heading-{width}-{height}.png`. Git 제외 로컬 증거다. 운영 확인 결과는 최신 인수인계에 추가한다.
- 독립 디자인 inspector는 앞선 작업에서 CDP 연결에 실패했다. 이번 수정은 직접 브라우저 기하 검사와 화면 확인으로 검증하며 전체 inspector·영상 검사 통과를 주장하지 않는다. 소스 디자인 lint는0FAIL/기존 문서 테두리1WARN이었다.

실제 모바일 장치와 필드 성능을 측정한 결과는 아니다. 제목의 별도 움직임이 원인이었다고 기록하지 않으며, 화면에 남는 예시와 문구의 소유 영역 차이를 고친 것이다.
