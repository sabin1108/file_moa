# 정리 확인 흐름과 온보딩 후속

2026-11-17. 기준 HEAD `62e2ec9`와 앞선 로컬 온보딩 변경을 보존했다. 사용자는 정리 폴더 안의 파일 확인, 모호한 목적지 답변 대신 폴더 선택, 현재 단계만 노출, 확인 자료의 간단한 목록과 공통/개별 지정을 요청했다. 같은 대화의 후속으로 안전 설명을 숨기지 말고 회의록 단독 장면의 여백을 줄이라고 정정했다.

## 변경과 코드 읽기

1. `organization-preparation-controller.ts`: `browseAnswers`가 현재 목적지 질문의 자료를 선택해 기존 picker를 연다. 기존 폴더를 고르면 최종 목적지 하위의 상대 경로로 바꾸고 공통 `applyAnswers`로 검증한다. 여러 목적지를 한 번에 반영하며 날짜 답변/제외를 보존하고 기존 제안/동의는 폐기한다. 루트/부모/다른 가지는 거절한다. 새 하위 경로 입력은 이름 검증만 하며 파일 쓰기는 하지 않는다. 다음 확인 상태는 `reviewConfirmed`가 소유하고 답변 변경 때 취소한다.
2. `OrganizationQuestionsView.tsx`: 파일명과 지정 상태의 짧은 목록을 먼저 보여 준다. 같은 폴더에 일괄 지정하거나 개별 지정으로 예외를 고른다. 공통 사유는 한 번만 표시한다. 파일을 열면 발췌/실제 날짜 근거/개별 목적지/제외를 확인한다. 채팅 문장 입력과 구별되는 폴더 선택 버튼을 사용한다.
3. `OrganizationPreparationPanel.tsx`: 공통 WorkflowStepper를 쓰고 조건/질문/전송/계획 중 현재 단계만 렌더한다. 지정 완료 뒤 전송을 다시 확인하며 자동 호출하지 않는다. 공통/개별 선택 모드는 picker 왕복 중 유지하고, 돌아온 단계의 제목에 키보드 초점을 둔다. 복구·실행 UI는 계획 단계에서 기존 엔진을 그대로 사용한다.
4. `DestinationFolderPicker.tsx`: 정리에서만 `showFiles`를 켜 기존 목록의 파일명을 읽기 전용 표시한다. 다른 화면 기본값은 유지한다. `OrganizationSnapshotView.tsx`의 준비 파일 목록은 기본으로 표시하고 개별 발췌를 확인할 수 있다.
5. `OnboardingPage.tsx`, 소개 CSS: 큰 걱정 문구를 유지하며 모든 안전 설명을 즉시 표시한다. 데스크톱 회의록은1180px까지 표시하고 본문을 키우며190svh 구간에서 꺼내기 연출을 유지한다. 기존 기록과 앞선 접기 시도는 명세에 정정으로 보존했다.
