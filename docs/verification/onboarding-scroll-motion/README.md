## 결과와 범위

Toss의 송금 장을 ego-browser에서 다시 열어 고정된 큰 제품 장면과 짧은 설명이 스크롤에 따라 이어지는 방식을 확인했다. 브랜드 영상·이미지·문구를 복제하지 않고 모아의 문서·검색·원문·대화·정리 계획으로 구성했다.

기존 공개 `/start`와 공유용 `/demo/intro`의 시작 목적지는 그대로다. 기존 파일 관리나 AI 호출·인증·샘플 세션을 수정하지 않았다. 소개용 화면만 움직이며 실제 원본 읽기·변경·모델 요청은 하지 않는다.

| 장면 | 진행 |
| --- | --- |
| 첫 화면 | 문서가 흩어진 상태 → 폴더로 모임 → 자료 작업 화면으로 전환 |
| 자료에서 답변까지 | 검색 → 원문 확인 → 자료 기반 답변. 제품 표시가 고정된 동안 설명이 대응한다. |
| 정리 계획 | 정리 전 자료 → 목적지 검토 → 확인 후 정리된 폴더 |

`ScrollStories.tsx`는 이야기와 표시 조합, `ProductScenes.tsx`는 재사용 제품 표시, `onboarding-motion.module.css`는 고정 지면·진행 구간·전환을 담당한다. 서버 렌더링과 CSS view-timeline으로 구현했으며 새 패키지나 스크롤 이벤트 처리용 클라이언트 코드는 추가하지 않았다. 스크롤을 멈추거나 되돌리면 같은 위치에서 멈추고 돌아간다.

움직임 감소·폭 360px 미만·높이 750px 미만·필요한 CSS 미지원에서는 모든 설명과 여섯 제품 장면을 순서대로 펼친다. 모바일의 두 고정 장면은 설명과 제품 표시를 따로 배치해 겹침을 막았다. 스크린리더는 움직이는 복사본 대신 항상 존재하는 여섯 단계의 설명을 읽는다.

## 시각 검토

시작/중간/끝의 데스크톱·모바일 장면과 움직임 감소 전체 지면을 직접 열람했다. 스킬의 측정 함수를 ego 페이지에서 실행한 대체 검사에서 1440·768·390·320px 모두 FAIL 0개였다. 기존 표준 Chrome 검사기의 연결 한계는 [앞선 검증](../onboarding-introduction/README.md)을 따른다.

남은 경고는 실제 사진·영상이 없다는 항목과 글자 외곽을 기준으로 한 여백 차이다. 이 페이지는 제품 표시가 증거이므로 관계없는 사진이나 영상을 채우지 않았다. 지면은 같은 좌우 padding과 중앙 정렬을 유지한다. 스크롤 장면 자체는 별도로 진행 위치·역방향·입력·가림을 검증했다. 일반 정적 화면 측정만으로 움직임 검증을 대신하지 않았다.

자체 검토는 design 8, usability 8.5, creativity 7.5, content 8, 가중 8.05/10이다. 독립 심사 점수가 아니다. 앞서 선택한 Colour chapters와 기존 브랜드를 유지하고 사용자 요청으로 등장 효과 중심에서 진행에 묶인 이야기로 보완했다. jakub better-ui·better-typography·better-writing의 조작 반응·읽기·움직임 감소 기준을 유지했다.

## 성능·제한

전체 `.next/static/chunks` JS/CSS는 49개, 3,687,905 bytes다. 직전 같은 작업 환경의 3,676,988 bytes보다 10,917 bytes 증가했다. 사이트 전체 정적 산출물의 합계이며 방문자가 모두 내려받는 크기나 체감 성능 수치가 아니다. 스크롤 제어 라이브러리·휠 가로채기·프레임마다 React 상태를 갱신하는 코드는 없다.

실제 Safari/Firefox, 물리 터치와 실사용 INP·운영 서버 성능은 미검증이다. CSS가 지원되지 않으면 효과 대신 전체 내용을 표시하도록 했다. Toss의 영상·WebGL 자산과 동일한 결과를 주장하지 않는다. 커밋·푸시·배포와 유료 모델 실행은 하지 않았다.

원자료는 Git 제외 `.omx/verification/onboarding-motion-20261111/`의 `desktop-progress.json`, `mobile-progress.json`, `assertions.json`, `fallback-and-audit.json`, `input-and-fallback.json`, 단계 PNG와 검사 로그에 있다. 이전 실패 장면과 수정 후 `mobile-fixed-*`를 구별한다.
