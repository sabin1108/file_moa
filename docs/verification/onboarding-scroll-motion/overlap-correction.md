# 스크롤 중간 위치 겹침 보정 — 2026-11-11

사용자는 사람마다 스크롤 거리와 속도가 달라 중간에 겹쳐 보이는 문제를 지적했다. 이전 검사는 비어 있는 장면만 검사해, 동시에 표시되는 두 화면을 허용했다. 따라서 이전의 통과 기록은 겹침 방지 증거로 볼 수 없다.

## 변경

- 제품 장면과 모바일 설명은 동시에 교차 표시하지 않는다. 23–29%에서 첫 장면을 감추고 29–35%에서 두 번째 장면을 표시한다. 다음 전환도 60–66%, 66–73%로 분리했다. 경계 순간의 짧은 비표시는 의도한 전환이다.
- 첫 소개 문구가 사라지는 32%까지 폴더 전체의 상승을 기다린다. 폴더 표시가 끝난 뒤 작업 공간을 표시한다.
- 작은 화면의 문서 그림을 24px 내려 공유 체험의 안내 문구와 분리했다.
- 360×750에서 마지막 고정 지면의 높이가 부족한 문제를 재현했다. 고정 연출의 최소 높이를 820px로 높이고 나머지는 기존 순차 표시를 사용한다. 스크롤 이벤트나 속도를 가로채지 않는다.

## 이번 검증

- 타입 검사, 린트, 관련 테스트 10개 통과. 마지막 CSS 변경을 포함한 production 빌드 통과.
- 실제 ego의 1440×1000, 768×900, 390×844, 360×820에서 두 이야기의 진행률 0–100%를 5% 간격으로 검사했다. 실제 프레임을 캡처한 뒤 표시 장면 수·모바일 설명 하단/제품 상단·가로 넘침을 검사한 168개 상태에서 실패 0개.
- 추가로 26/32/63/70% 중간 정지와 0/50/100/50/0% 단계 복귀를 확인했다. 35/600/-350/1200/-1200px 휠 이동에서도 제품 장면 중복 없음.
- 공유 체험 첫 장면의 정방향·역방향과 문구/문서 간격 확인. 360×750, 320×844 및 움직임 감소에서 모든 제품 지면을 순서대로 표시하며 가로 넘침 없음.
- 브라우저가 뒤에 있을 때 타이머만 기다리면 실제 애니메이션 프레임이 갱신되지 않았다. `checks.json`의 타이머 검사 결과는 완료 증거에서 제외했다. 최종 근거는 `sweep.json`과 `round-06.mjs`, 실제 프레임을 두 번 캡처하고 기대 단계까지 단언하는 `round-08.mjs`다.
