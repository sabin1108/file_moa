# 변경 계획 기능의 성능 전후 기록 — 2026-10-29

기능 추가 비용과 기존 흐름 회귀 비교다. 동일 기능의 최적화 전후가 아니다.

## 재현 조건

- Node24.22.1/pnpm12.15.0/Next16.4.3, Windows, 전후 모두 Chrome/156.0.8078.48.
- production build, 동일 http://127.0.0.1:3010, CPU/네트워크 제한 없음, HTTP cache disabled, 경로마다 새 탭, 로드 뒤1.2초 관찰. 6경로×3회×2폭×전후=72표본. 390px는 데스크톱 Chrome viewport이며 실제 모바일 장치가 아니다.
- 로그인·모델·서버 업무 API 없음. 로딩 측정은 폴더를 연결하지 않은 초기 화면이다. 연결된 파일 흐름은 별도 OPFS 검증이다.
- 변경 전 빌드를 새로 생성하고 desktop/390 측정이 모두 끝난 뒤 다음 빌드를 생성했다. **before-mobile의 sourceSha256은 그 사이 편집 중이던 작업트리 지문**이며 서빙 빌드의 정확한 revision으로 쓰지 않는다. 두 before의 staticBytes786309와 동일 서버/빌드는 유지됐다. 원자료를 수정하지 않았다.
- 도구: tests/performance/measure-settings-performance.mjs. PerformanceObserver LCP/CLS, ResourceTiming 전송량, CDP JS heap. Lighthouse/TBT/field INP·서버 부하·실물 장치 성능은 미측정이다. 임의 회귀 허용률을 도입하지 않았다.

## 공통 자원과 작업 시간

배포 전체 정적 자산 **786309 → 799820bytes(+13511bytes,13.19KiB)**. 초기 JS 중앙값은 측정한 모든 경로에서 **+2.90KiB**다. 전체 배포 크기 증가와 초기 다운로드 증가를 구분한다. 공유 chunk 전파 비용이 있지만 이번 측정은 최적화를 주장하는 근거가 아니다.

모두390×1000 합성 OPFS 고정 자료, 각3회. 선택은 CDP click+React commit+polling, 계획은 출발/목적지 열거+계획 계산+렌더까지 포함한다. p95/INP가 아니며 안정적 서비스 지연으로 일반화하지 않는다. 무작위 seed는 쓰지 않았다.

계획 팝업10회 열기/닫기 JS heap **6.88 → 6.14MiB**. 강제 GC/장시간 표본이 없으므로 누수 없음 판정은 하지 않는다. 기존 선택 시간은 전후 범위가 겹친다. 새 계획의1,000개 렌더 비용은 별도 기준선으로 보존한다.
