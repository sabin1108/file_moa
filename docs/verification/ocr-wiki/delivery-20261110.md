# ego-browser 실제 화면 확인과 커밋 전달

2026-11-10. 사용자가 ego-browser로 실제 브라우저 테스트를 시도하고 지금까지의 작업을 커밋·푸시하라고 요청했다. 기존 OCR·위키 및 후속 검증 변경을 같은 전달 범위로 묶는다. 정확한 전달 SHA·원격 상태는 커밋 뒤 프로젝트 memory 최신 절에 기록한다.

## 실제 브라우저 연결

설치된 ego lite0.6.2.7의 ego-browser 가이드2.2.0을 끝까지 읽었다. 기존 터미널 PATH에 명령이 없어 설치된 실행 파일을 직접 사용했다. 기본 sandbox에서 bootstrap 연결이 실패했으며 허용된 실행 환경에서 같은 목표의 작업 공간4에 연결했다. 브라우저 재설치·업그레이드·개인 프로필 전환·쿠키 복사·인증 우회는 하지 않았다.

실제 `http://127.0.0.1:3034`의 로그인된 제품 화면에서 다음을 확인했다.

- 일반 채팅의 입력창·자료/저장/설정 조작이 표시된다.
- 합성 한글 초안 입력과 Shift+Enter 줄바꿈이 동작한다. 실제 물리 IME 검증은 아니다.
- 파일 화면을 방문해 돌아와도 입력한 합성 초안과 줄바꿈이 그대로 남는다. 확인 뒤 이 테스트 초안은 정리했다.
- 기록함을 열어 위키 탭과 기존 편집/저장 위치 연결 흐름이 표시되는지 확인했다. 저장 폴더가 없는 상태의 연결 안내가 나온다.
- 설정과 폴더 연결 페이지에서 기존 연결의 다시 연결 안내와 OCR 설정이 표시된다. 기존 개인 폴더의 내용은 읽거나 변경하지 않았다.
- 실제 ego-browser의 HTML에도 `data-map-dyoa-ext="1.3.0"`이 존재한다. 기존 SSR 주입 재현과 일치하며 확장 설정은 변경하지 않았다.

별도 작업 공간의 UI·브라우저 자동 입력 결과이며 실제 소셜 로그인 callback·물리 키보드 입력과 구분한다. 폴더 선택·읽기 권한은 브라우저가 소유한 창에서 사용자가 처리해야 한다. 그 선택을 자동 승인하거나 다른 경로로 우회하지 않는다. 새 유료 모델 요청은 보내지 않았다.

## 커밋 전 검증

- 전체153파일·1,325개 단위 테스트 통과. 최초 병행 실행에서는 인증 설정 모듈의 첫 import 검사1개가5초 제한에 걸렸다. 해당7개 단독 검사와 이후 전체 단일 worker 실행이 통과했다. 코드나 테스트 제한 시간은 바꾸지 않았으며 최초 실패와 최종 통과 로그를 분리했다.
- 타입·린트·빌드 검사 통과. 서버 경계26·구조25/6/3·S0 모듈168개도 통과했다.
- 개발 서버를 중지한 뒤 타입·Prisma 생성·빌드를 수행하고, 허용된 네트워크 환경에서 개발 서버를 복구한다. 제품 원본 쓰기·인증 보호·현재10회 제한은 유지한다.
- 승인된 엔진7.0.0·언어 파일과 라이선스를 포함한다. 생성된 Worker/core/WASM·개인 환경 파일·실제 브라우저 원자료·개인 테스트 폴더는 커밋에서 제외한다.
- 전달 대상 전체 파일과 클라이언트 산출물에서 로컬 환경의 비밀값이 노출되는지 검사한다. 원자료는 `.omx/verification/ego-commit-20261110/`에 두고 공개 문서에 비밀·계정·원본 경로를 복사하지 않는다.

이 문서는 전달할 소스에 포함되며 원격 푸시와 자동 배포 성공을 선행 가정하지 않는다. 최종 전달 결과와 실제 권한 선택 이후 검증은 최신 인수인계와 구분해 확인한다.
