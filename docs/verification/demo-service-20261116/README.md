# 데모 사용 안내와 네 가지 작업 체험

2026-11-16. 사용자 요청: 이력서 작성은 별도로 진행하고, 여기서는 제품 완성도·서비스성·데모의 기능 표현을 개선한다. 짧은 시작 안내와 기능별 자유 체험을 함께 제공한다. [작업 명세](../../specs/demo-service-experience.md).

## 변경과 원인

기존 데모는 정식 서비스와 소개·화면 프레임 일부를 공유하지만 작업 선택을 정리 하나로 제한했다. 정식 17단계 안내는 계정·실제 경로에 묶여 있어 데모에 그대로 연결하면 정식 화면으로 이동한다. 정식 기록함도 실제 저장 폴더와 결합돼 있다.

이번에는 기존 경계를 유지하면서 다음을 연결했다.

| 기능 | 이번 체험 | 실제 처리와 예시의 경계 |
| --- | --- | --- |
| 시작 안내 | 6단계, 이전·다음·건너뛰기·다시 보기, 각 작업과 기록함 열기 | 단계 이동만으로 작업·전송·동의를 실행하지 않음 |
| 일반 대화 | 공용 대화 지면·입력·키보드로 준비된 답변 확인 | 자유 질문에 맞춘 실제 모델 답변이 아님 |
| 자료 찾기 | 정식 질문 해석·기간 확인·본문/경로 판정을 샘플 발췌에 적용, 결과에서 원문 열기 | 실제 개인 폴더/전체 원문/모델 검색이 아님 |
| 자료로 질문 | 선택한 샘플 발췌와 출처 열기 | 발췌 모음이며 질문에 대한 모델 추론·종합 답변이 아님 |
| 자료 정리 | 기본 체험에서 준비된 목적지 → 공용 계획 검토 → 적용·되돌리기 | 실제 AI가 요청별로 목적지를 생성한 결과가 아님. 기존 선택 AI 버튼의 별도 동의는 유지 |
| 기록함 | 대화 보관·열람, 결과물·위키·기억·프로필 작성/편집/삭제 확인 | 샘플 탭 임시 보관. 실제 AI 기록 폴더나 기억 주입과 연결하지 않음 |
| 상태 유지 | 모드·범위·초안·안내·결과·출처·정리 상태·기록 복원 | 같은 샘플 세션/탭 안의 보관. 초기화는 확인 후 해당 샘플만 지움 |

일반 대화에서는 자료 범위를 숨기며, 정리 완료 표시는 정리 모드에서만 노출한다. 이전 찾기 결과와 자료 답변/출처는 작업 전환 후에도 함께 유지한다. 위키는 마지막 일반 답변 대신 보존된 자료 답변을 사용한다. 검토 중 모드/범위 변경은 계획을 보호한다. 기간 확인이 필요한 요청은 기간 안내와 초안을 유지한다. 기록 저장 실패나 한도 초과는 편집 내용을 유지한다.

## 변경 파일을 읽는 순서

1. `apps/web/src/features/sample-workspace/sample-experience.ts`: 공용 검색 규칙과 명시적인 오프라인 응답 경계. 정식 `WorkspaceRequestKind` 전체를 요구하는 예시 표.
2. `sample-state.ts`, `sample-workspace-store.ts`: 기본값이 있는 상태 확장, 복원 검증, 임시 기록 한도·저장 실패, 단계/모드별 상태 전이.
3. `conversation/SampleConversation.tsx`: 공용 `ConversationStart`·`ConversationWorkspace`와 작업별 결과/출처/계획 연결.
4. `conversation/SampleExperienceGuide.tsx`, `SampleLibraryPanel.tsx`: 안전한 안내와 샘플 기록함. 미저장 편집은 기존 이탈 보호를 사용한다.
5. `shared/record-kinds.ts`, 실제 `AiLibraryPanel.tsx`: 정식/샘플 기록 종류를 한곳에서 관리. 실제 기록함의 동작은 유지한다.
6. `components/layout/ConversationWorkspace.tsx`: 메시지가 없는 첫 화면을 자동으로 아래로 스크롤하지 않도록 보완. 데모의 첫 제목이 가려지는 문제를 브라우저 회귀로 확인했다.
7. `SampleWorkspace.tsx`, `app/demo/settings/page.tsx`: 안내 재진입 연결. CSS는 기존 프레임과 토큰을 유지한다.

## 실패·차단·시각 검토

- 기존 `check-sample-workspace.mjs`: 39검사 중 38통과/1실패, exit1. 파일 탐색·미리보기·목적지 변경·적용·되돌리기·초기화·격리 흐름은 실행했다. 마지막 정식 `/files` 보호 확인은 검증용 인증 환경에서 `AUTHENTICATION_UNAVAILABLE` 503이라 정상 인증/리다이렉트 경로를 확인하지 못했다. 제품 결함을 확정하거나 통과로 바꾸지 않았다. 이 스크립트의 공급자 미설정 분기를 보강했으며 외부 AI 활성 상태의 분기는 이번에 실행하지 않았다.
- 공식 taste inspector는 두 번 모두 `Page.enable` 시간 초과로 실패했다. 성공으로 집계하지 않는다.
- 같은 공식 probe/rules를 Ego 페이지에 적용한 별도 관찰: 초기 키보드 초점 상태에서 heavy-shadow FAIL 3건, font-fallback/small-title/모바일 여백 WARN 7건. 모바일 여백을 보완했다. 이후 중립 상태에는 FAIL 0/WARN 6(각 폭의 Malgun Gothic 대체 글꼴·16px 제목)이 남았다. 초점 상태와 중립 상태를 합쳐 전부 통과로 표시하지 않는다. 초점 표시를 지우거나 기존 제목 체계를 일괄 바꾸지 않았다.
- 기존 샘플 파일 화면의 시각 관찰에도 12지적이 남았다. 위 중립 대화 화면 결과와 다른 대상이다.
- 앞선 작업의 화면 2실패·taste 20지적은 이번에 해결/통과 처리하지 않았다.

## 독립 검토와 보존

읽기 전용 architect가 공용 UI/검색 재사용을 먼저 검토했다. 구현 뒤 출처 유실·모드 간 정리 표시·기간 안내·일반 대화 범위 표시 4건을 지적했고 이를 보완했다. 후속 검토는 남은 P1 코드 결함을 찾지 못했다. 남긴 브라우저 검증 공백 2건과 이전 세션 회귀 공백은 마지막 검사에 추가해 확인했다. 이는 한 검토자의 독립 검토이며 전체 5단계 EGM 완료나 운영 안전 보장이 아니다.

시작 시 기존 변경 파일과 개인 문서 30개 해시를 보관하고 끝에 모두 일치함을 확인했다(`preservation.json`). 기존 F1–F3 소스와 개인 문서를 수정하거나 같은 재점검을 반복하지 않았다. executor 하위 에이전트는 계정의 기본 모델 미지원으로 실행되지 않아 실제 구현과 통합은 부모가 수행했다.

## 남은 범위와 다음 변경 시 기준

개인 폴더 연결·권한창, 원본 문서 편집/복사/복구 보관함, 실제 인증·운영 DB, 영구 AI 기록 저장, OCR·설치형 의미 검색, 실제 모델의 자유 답변·품질·청구는 이번 데모가 실행/검증한 기능이 아니다. 체험 화면의 ‘체험 범위와 정식 사용의 차이’에 구분했다. 따라서 제품 전체의 운영 체험이 완성됐다는 뜻은 아니다.

공용 작업 버튼·대화 지면·검색 규칙·계획 검토·기록 종류의 변경은 공유 코드로 반영된다. 새 업무 규칙·외부 기능·응답 예시는 샘플 처리와 검증 시나리오를 함께 갱신해야 한다. 모든 기능이 자동으로 데모에 구현된다고 주장하지 않는다. 새 작업 종류는 타입 검사와 네 작업 브라우저 계약의 실패로 누락을 드러내게 한다.

개인 폴더·운영 DB·유료 AI·새 모델 다운로드·배포·커밋·푸시는 실행하지 않았다. 로컬 서버의 공개 AI를 비활성화하고 실제 DB와 연결되지 않는 검증용 주소를 사용했다.
