# 데모 답변 표시 수정과 장시간 검사

2026-11-19. 사용자 요청: “다 수정해”. 기준 HEAD는 `c5fb07f`이다. 앞선 [재개 검사](../resume-stability-20261119/README.md)의 첫 줄 겹침 관측과 배포 환경의 장시간 검사에 대한 후속이다.

## 문제와 최소 수정

빠른 합성 답변 60회에서 첫 줄과 발언자 표시가 겹쳐 보이는 화면을 재현했다. DOM 좌표상 본문과 발언자 줄 간격은 10px로 정상이었다. 자동 스크롤 중 본문 opacity 애니메이션이 실행되고 있었고, 첫 프레임의 불투명도는 0.55였다. 애니메이션이 끝난 화면과 해당 효과만 끈 비교에서는 겹쳐 보이는 현상이 사라졌다. 브라우저 내부의 합성 원인까지 확정한 분석은 아니다.

최신 답변으로 자동 이동할 때는 별도 문제가 있었다. 새 답변의 첫 두 프레임에서 최신 메시지가 대화 창 위쪽 기준 약 24,496px 아래에 남았다. 기존 `smooth` 스크롤이 앞선 긴 대화를 훑어 내려가야 했기 때문이다.

읽을 순서와 변경:

1. `apps/web/src/components/layout/ConversationWorkspace.tsx`: 명시된 현재 답변으로 이동할 때 `instant`를 사용한다. 새로고침 복원과 빠른 완료 모두 최신 답변 첫 줄에 즉시 도착한다. 명시된 현재 답변이 없는 일반 따라가기 경로와 키보드·전송·취소 규칙은 그대로다.
2. `apps/web/src/components/layout/conversation-workspace.module.css`: 본문 opacity 애니메이션과 그 전용 키프레임·reduced-motion 예외 3줄을 제거했다. 받은 문장을 처음부터 불투명도 1로 표시한다. 간격·서체·색·본문 폭은 바꾸지 않았다.

공통 `ConversationWorkspace`를 사용하는 정식·데모 채팅에 같은 수정이 적용된다. 새 추상화·제품 의존성·상태·통신은 추가하지 않았다.

## 회귀와 production 화면

- 수정 전 첫 프레임 불투명도 0.55 검사 실패 → 수정 후 1·애니메이션 없음으로 통과.
- 수정 전 최신 답변 즉시 도착 검사 실패 → 수정 후 대화 창 위에서 16.42px 위치로 통과.
- 두 수정을 함께 적용한 뒤 긴 합성 답변 30회를 연속 갱신했다. 각 회차에서 불투명도 1·간격 10px·최신 답변 즉시 도착과 composer 입력 초점 유지를 확인했고 즉시 캡처한 화면도 확인했다.
- 최종 로컬 Next production에서 40개 합성 메시지를 복원했다. 390/768/1440/1920px에서 모두 본문 불투명도 1, 간격 10px, 최신 답변 위쪽 위치 약 16.2~16.3px, 가로 넘침 없음, 초안 보존을 확인했다. 네 폭의 스크린샷을 직접 확인했다.
- 로컬 production은 별도 테스트용 서명 설정과 초대 값을 사용하고 공개 AI를 비활성화했다. 메시지는 UI 표시 검증용으로 sessionStorage에 넣은 합성 데이터다. 실제 모델 응답 검증이나 운영 비밀 사용이 아니다.

## 배포 환경 관측

기존 배포의 새 데모 세션에서 예시 MD 문서를 만들고 편집·변경 전 검사·보존 후 저장을 실행했다. 채팅으로 돌아와 기존 초안과 현재 파일 본문이 유지되는 것을 확인했다. 개인 파일·계정 설정·운영 DB는 변경하지 않았다.

실제 배포된 기존 빌드에서 15분 22초 동안 관측했다. 매분 설정 패널을 5회 열고 닫았고, 시작 표본을 포함해 총 80회 왕복했다. 16개 표본 모두 같은 composer DOM 노드와 초안, 편집한 파일 본문, 보존본 1개를 유지했다. 연결된 DOM 요소는 604개로 같았으며 관측한 브라우저 오류·처리되지 않은 Promise 오류·긴 작업·AI 스트림 요청은 모두 0건이었다.

JS heap 표본은 약 8.15~9.70MiB였다. 시작과 끝의 강제 GC 뒤에는 7.56→7.68MiB였고 이벤트 리스너 수는 448→448개였다. 해당 15분 구간에서 지속적으로 쌓이는 징후는 관측하지 못했다. 모든 기기·오래된 세션·실제 AI 동시 실행에서 누수가 없다는 증명은 아니며, 패널 자동 조작 호출 시간도 사용자 입력 INP로 환산하지 않는다. 로컬 빌드와 일부 검사가 같은 컴퓨터에서 병행됐으므로 통제된 전후 속도 비교가 아니다.

관측 뒤 F5 전후 전체 저장 상태 문자열이 같았다. 기존 초안과 편집한 실제 미리보기 본문, 보존본 1개가 복원됐고 AI 요청은 없었다. 마지막 미리보기 클릭 1회는 자동 스크롤 중 화면 밖 항목 때문에 실패했으나, 현재 위치를 확인한 뒤 실제 표시된 같은 항목을 열어 본문을 확인했다. 제품 데이터 유실로 해석하지 않는다.

이 검사는 현재 배포된 기존 빌드의 안정성 관측이며, 이번 수정의 운영 배포 완료를 의미하지 않는다.

### Lighthouse와 초기 안내

Lighthouse 13.5.0을 프로젝트 의존성에 추가하지 않고 임시 CLI 캐시에서 실행했다. 최종 로컬 production `/demo`, 격리된 테스트용 쿠키, cold browser, 기본 desktop/mobile 설정의 각 1회 표본이다. 반복 중앙값이나 전후 개선율은 아니다.

| 조건 | 성능 | 접근성 | 모범 사례 | LCP | TBT | CLS |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Desktop | 89 | 100 | 100 | 843.6ms | 0ms | 0.2094 |
| Mobile | 82 | 100 | 100 | 3,782.9ms | 154ms | 0.1271 |

CLS의 실제 요소는 첫 사용 안내 dialog의 spotlight와 explanation이었다. 현재 답변 본문의 겹침이나 장시간 메모리 문제로 해석하지 않는다. 최초 안내 위치 이동의 별도 관측으로 보존하며, 이 요청에서 기존 안내 구성을 다시 설계하지 않았다. 같은 장치에서 안정적인 차이를 판단할 반복 비교는 실행하지 않았다. 점수로 장시간 안정성이나 사용자 체감을 보증하지 않는다.

후속 설명에서 이 움직임을 확정 오류처럼 필수 수정 항목에 넣은 것은 부정확했다. 기존 코드에는 안내 위치를 부드럽게 옮기는 180ms 효과가 있으며, 정상 연출과 불필요한 튐을 구분하지 못한 상태다. 따라서 추가 확인 항목으로만 남기고 자동으로 새 디자인이나 필수 수정 범위로 삼지 않는다.

새 유료 AI 요청과 배포는 실행하지 않았다. 물리 Windows IME·native 폴더 권한·새 이메일·모바일 화면 마감은 이번 범위 밖이다. 좁은 화면 검사는 공통 채팅 변경의 회귀 확인이다.
