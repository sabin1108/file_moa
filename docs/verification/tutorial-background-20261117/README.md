# 튜토리얼이 작업 화면을 가리는 오류

사용자 화면과 같은 증상을 운영 데모에서 재현했다. 작업 공간은 DOM에 남아 있었지만 전체 화면 튜토리얼 dialog의 계산된 배경색이 `rgb(237, 240, 238)`여서 내용을 덮었다. 튜토리얼과 공용 테마가 같은 우선순위의 배경 선언을 가지고 있어 스타일시트 순서에 따라 공용 테마가 이겼다.

열린 튜토리얼의 `.tour[open]`에 투명 배경을 명시했다. 안내 상자·음영·강조와 modal 키보드 동작은 같은 구조를 유지한다. 변경은 공용 튜토리얼 스타일에 적용되므로 실사용과 데모에 함께 적용된다.

회귀 검사: `tests/browser/tutorial-background-checks.mjs`를 Ego 브라우저의 실제 튜토리얼에 적용했다. 공용 테마 배경을 뒤늦게 주입하고도 dialog와 backdrop이 투명하며 작업 공간·메뉴가 함께 남는지 검사한다. 390·768·1440·1920px 모두 통과했고 스크린샷에서 작업 화면을 확인했다. 관련 onboarding 테스트 3개 파일·16개, 타입·린트·빌드가 통과했다. 린트는 기존 `_count` 경고 1개이며 새 경고는 없다.

운영 재현과 수정 전후 이미지는 `.omx/verification/tutorial-background-20261117/`에 보존한다. 배포 뒤 실제 19단계 이동 결과는 같은 위치의 운영 확인 기록에 남긴다. AI 호출·개인 폴더 읽기·운영 DB 변경은 이 오류 검증에 필요하지 않아 실행하지 않는다. 화면 배경 수정이므로 전체 AI 회귀 및 실제 IME 검사는 반복하지 않는다.
