# 다양한 데모 정리 요청 · 2026-11-17

사용자는 특정 중요도 문장 외의 많은 요청도 대비하고, 수정 뒤 커밋·푸시와 다음 날 재개용 인수인계를 요청했다.

## 수정한 동작

이전 코드는 요청에 ‘보고서’가 있으면 보고서만, ‘성능/테스트’가 있으면 실측 자료만 선택하라는 지침을 붙였다. 중요도 키워드는 상·중·하 외 목적지를 거부했다. 따라서 ‘보고서는 빼고’나 ‘중요도는 그대로 두고 회사별로’에 반대 조건이 강제될 수 있었다. 새 회귀 검사에서 9개 실패를 확인한 뒤 수정했다.

이 단어 감지와 중요도 전용 스키마·검증·누락 날짜 보정을 제거했다. 같은 범용 지침이 요청 전체의 의미에서 필터·제외·등급·사용자 지정 이름·계층을 해석한다. 중요도 기본 기준, 보고서와 성능 실측의 구분은 **사용자가 그 작업을 실제로 요청한 경우**에만 적용하는 조건부 지침이다. 상·중·하만 강제하는 기계적 검증은 제거됐으며, 다른 이름이나 복합 계층도 기존 경로 계약 안에서 제안할 수 있다.

서버 소유 자료·세션·Origin·외부 전송 동의·할당량·원문 인용·자료 ID·안전한 경로·날짜 근거·개별 확정 답변 검증은 유지한다. 의미상의 분류 정확성은 모델과 사용자 검토에 의존하며, 원문과 인용이 일치한다는 사실만으로 분류가 정답임을 보장하지 않는다. 새 호출·자동 재시도·다른 공급자로의 자동 전환은 추가하지 않았다.

계획과 보류가 모두 없는 유효 응답은 실패 메시지나 빈 계획으로 끝내지 않고, AI 요약을 표시한 뒤 기준 질문으로 돌아간다. 이때 선택 자료는 유지하고 전송 조작을 숨긴다. 사용자가 기준을 답하면 다시 자료를 확인하고 새 동의를 받는다. 실제 파일은 변경하지 않는다. 같은 제어기와 정식·데모 패널을 함께 수정했다.

## 실제 모델의 대표 의미 평가
