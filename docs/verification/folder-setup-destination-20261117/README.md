# 첫 연결 준비와 없는 목적지 복귀

2026-11-17. 사용자 제보: 제안된 하위 폴더를 목적지 선택에서 열면 존재하지 않는데도 선택된 것처럼 표시되고 같은 경로 재시도만 가능했다. 실제 묶음 검사에서는 복구 연결이 빠져 늦게 실패했다.

## 변경

- `DestinationPickerController.parent`는 마지막 성공 목록 대신 요청한 경로의 상위로 이동한다. 기존 목록이 없거나 다른 위치의 목록이 남아도 같은 규칙을 사용한다.
- 공통 선택 화면은 확인하지 못한 경로에 선택/생성 조작을 표시하지 않는다. 상위/연결 폴더 이동과 재시도를 제공한다. 기존 새 항목 폼으로 상위에서 직접 생성하고 다시 선택한다. 자동 생성은 없다.
- 첫 사용 안내의 기존 자료 연결 단계에서 실제 `SourceFolderSettings`를 재사용한다. 준비 면에서는 OCR/색인 등 고급 설정과 중복 권한 안내를 제외한다. 자료 연결 다음 복구 연결을 진행한다. 데모에는 개인 연결 조작을 추가하지 않는다.
- `FolderSetupNotice`는 채팅 시작과 정리 준비에 실제 연결 상태와 설정 창을 제공한다. 일반 대화와 제안 준비는 가능하며 실제 계획/묶음 검사에는 두 연결이 필요하다. 기존 session의 권한·보존 검사는 유지한다.
- 연결 후에도 창을 유지해 성공 상태와 완료 버튼을 확인한다. 직접 닫으면 준비 안내가 사라지고 입력으로 초점을 돌린다. 초안·선택·제안을 초기화하거나 AI를 다시 호출하지 않는다.

## 검증

- 새 반례에서 없는 `자료/영어`의 상위 이동이 `[]`로 잘못 반환되는 실패를 먼저 확인했다. 수정 후 관련 8파일 81테스트 통과.
- 타입 검사, 린트, production 빌드 통과. 린트에는 기존 `_count` 미사용 경고 1개가 있다.
- 서버 경계 26검사, 구조 검사 32 web/6 domain/3 layout 통과.
- 실제 Ego 브라우저와 합성 OPFS 폴더에서 첫 안내의 연결·취소·건너뛰기·재개, 직접 복구 생성/재연결, 창 유지·완료·키보드 초점, 제안/초안 보존과 AI 재호출 없음, 10회 화면 전환, 합성 조합 중 Enter를 확인했다.
- 없는 제안 목적지에서 선택/생성 표시가 숨겨지고, 상위로 이동해 직접 폴더 생성→선택→기존 실제 managed 계획 검사까지 이어졌다. 파일 변경 실행은 누르지 않았다.
- 390/768/1440/1920px에서 첫 연결 버튼이 스크롤 없이 보이고 안내의 고정 조작이 화면 안에 남는 것을 확인했다. 목적지 오류 복귀 화면도 네 폭에서 확인했다.

원자료: `.omx/verification/folder-setup-destination-20261117/`. 초기 검사에서는 화면 크기 전환 직후 측정, 빠른 다음 클릭의 상태 대기 누락, HMR에 따른 합성 Action/선택기 초기화 때문에 일부 검사가 실패했다. 상태 기반 대기와 합성 환경을 복원해 재확인했다. 준비 안내가 닫힌 뒤 제목으로 초점이 돌아가는 경우도 발견해 입력 우선 복원으로 수정 후 통과했다. 네이티브 선택기는 한 차례 브라우저 도구가 취소했으며 개인 폴더를 선택하지 않았다.

## 확인하지 않은 범위

개인 디스크/기존 사용자 폴더의 직접 조작, 운영 DB 변경, 유료 AI 호출, 물리 한국어 키보드/OS 권한창 경합은 실행하지 않았다. OPFS/합성 공급자 결과를 운영 파일이나 실제 AI 품질 검증으로 해석하지 않는다. 전체 테스트셋과 전체 사이트 속도 개선은 주장하지 않는다. 기존 데모 파일 작업/영구 저장 연결 범위도 확대하지 않았다.
