# 인증 확인·데모 파일 작업·검색 화면 보완

2026-11-18. 요구사항 362. 기준 HEAD `387bdab`. 변경은 로컬 작업 트리에 있으며 커밋·푸시·배포하지 않았다. 정식 **Luna 고정**, 데모 **Astra / medium** 설정을 유지했고 서버 모델 설정은 변경하지 않았다.

## 결과와 범위

### 인증은 현재 재현하지 못했다

로컬의 인증 쿠키 없는 `/login`은 폼을 표시하고 `/account`는 `/login`으로 이동했다. 기존 인증 쿠키가 있는 운영 사이트에서는 `/login`이 `/`로 이동하고 실제 작업 공간이 표시됐다. 과거 오류를 현재 오류로 확정하거나, 이번에 인증 결함을 수정했다고 주장하지 않는다. 로그인 제출·메일·OAuth·운영 계정/DB 직접 접속·쿠키 삭제/수정은 하지 않았다. 인증 소스는 변경하지 않았다.

### 데모 파일 체험을 연결했다

생성(폴더·빈 MD/TXT), 편집, 파일/하위 폴더 포함 복사·이동, 휴지통, 새 위치 복구를 연결했다. `FolderListingView`·선택 도구·`EntryCreationForm`·`ManagedFilesController/Dialog`·목적지 picker·경로 입력·비교·검토·보존본 화면을 공유한다. 생성 폼의 표시와 실제 폴더 연결 책임을 나누어 정식 `NewEntryForm`의 기존 동작도 유지했다.

실제 파일 핸들 대신 탭의 예시 자료 상태를 읽고 다음 상태를 원자적으로 반영한다. 변경 전 편집/이동/휴지통 사본은 보존하고, 복구는 새 위치에 만들며 보존본은 유지한다. 이름 충돌·자기 하위로의 복사/이동·없는 선택·오래된 계획·만료 세션·알 수 없는 자산·잘못된 복원을 차단한다. 여러 폴더에 걸친 선택은 일부만 처리하지 않고 다른 폴더의 선택을 명시적으로 해제하도록 안내한다. 가상 최상위 컨테이너는 목적지나 작업 대상으로 선택하지 않는다.

같은 샘플 세션의 `sessionStorage`에 파일 사본·선택·보존본을 함께 보관한다. 전체 선택의 연속 callback은 매번 최신 상태를 읽고, 파일/폴더 선택 해제가 질문 자료 선택을 바꾸지 않는다. 모바일 미리보기에는 직접 닫기 버튼을 제공한다. 편집한 문서는 해당 내용으로 내려받으며 복사한 PDF/XLSX는 등록 원본 자산에 연결한다.

**파일 체험의 사본과 AI 자료는 별도다.** 파일 화면을 처음 사용할 때 공개 카탈로그와 당시 정리 위치로 시작한다. 파일 사본에 저장한 편집·새 파일·복사/삭제·위치 변경은 AI 카탈로그에 전파하지 않으며 이후 채팅의 정리 결과와도 별도 상태다. AI 질문·정리는 계속 서버가 제공한 원문만 사용한다. 이 경계를 화면에 표시하고 개인 폴더나 임의 본문 전송을 추가하지 않았다. 데모 전체가 정식 파일 시스템과 같아진 것으로 보고하지 않는다.

임시 한도는 파일/폴더 합계 300개, 편집 64,000자, 보존 작업 30건이며 전체 샘플 직렬화 한도 512,000자를 함께 적용한다. 새 한도를 넘으면 기존 상태를 유지한다. 보관 실패 시 메모리 변경은 남지만 새로고침 때 사라질 수 있음을 안내한다. 탭 종료·새 세션은 영구 보관이 아니다. [계약과 실패 조건](../../specs/demo-file-workspace.md).

### 검색 화면과 회귀 검사

1440/1920px에서 이전 대화와 긴 조건 폼이 검색 버튼을 아래로 밀어내던 실패 2개를 다시 재현했다. 검색 작업의 지난 대화는 펼칠 수 있는 기록으로 보존하고, 조건 폼 마지막의 검색 버튼은 스크롤 면 아래에 계속 보이게 했다. 일반 채팅과 기존 입력창 크기는 유지한다.

실제 브라우저 검사 중 정리 대화에서 명시적인 검색 요청도 정리 답변으로 처리되는 실패를 확인했다. 자동 판별이 `find`인 경우에는 정리 후속 답변 분기로 들어가지 않게 수정했다. 명시적으로 고른 작업 모드는 기존 우선순위를 유지한다.

기존 시각 지적 중 16개는 검증 전용 위키 버튼의 대비/화면 가장자리였고, 버튼의 `hidden` 속성을 CSS가 덮어쓰고 있었다. 검증 컨트롤을 별도 wrapper로 묶어 제품 시각 검사에서 제외했다. 제품 결과 행의 체크 문자는 ‘조건 일치’로 정리했다. 새 검사에서 실패 0개, 휴대폰 공급자 안내의 14px 가장자리 여백 경고 2개가 남는다. 이를 접근성 전체 통과로 확대하지 않는다.

기존 검색 검사가 자동 자료 읽기를 가정하던 부분은 최신 대화 계약에 맞췄다. 선택 → 기준 답변 → 자료 확인 실행 전에는 읽기/전송이 없고, 확인 후 준비된 snapshot이 나타날 때까지 기다린다. 비동기 읽기 시작만 보고 완료로 판정하지 않으며 실제 비동의 전송 버튼을 검사한다.

새 파일 규칙은 구현 전 누락 모듈 실패를, 검색 대화 접기는 구현 전 SSR 실패를 기록했다. 이후 실제 화면의 검색 전환·읽기 완료 대기 실패도 남기고 수정했다. 독립 역할 모델 `gpt-5.5`가 현재 계정에서 지원되지 않아 구현/검증은 단일 담당으로 진행했으며 독립 다중 리뷰로 보고하지 않는다.

원자료는 Git 제외 `.omx/verification/resume-fixes-20261118/`에 있다. `all-final.log`, `targeted-final.log`, `typecheck-final.log`, `lint-final.log`, `build-final.log`, `auth-observation.json`, `browser-files.json`, `production-smoke.json`, `find-complete/{browser-checks,taste-checks}.json`, `performance.json`과 화면 이미지다. 앞선 `find-before`, `find-after*`, `find-final`, `find-accepted`, `find-verified`에는 중간 실패를 보존했다.

개발 서버 로그를 저장소 아래에 계속 기록하던 첫 실행은 파일 감지에 따른 반복 갱신을 일으켰다. 로그를 시스템 임시 폴더로 옮긴 뒤 개발 화면을 다시 확인했고 최종 production 빌드에서도 검증했다. 이것을 배포 장애로 판단하지 않는다.
