# 자료 질문 연결과 검색 화면 보완

2026-11-14. 사용자 요구280/281. 검색 정확도 교체 제안은 [로컬 검색 개선 설계](../../planning/local-search-improvement.md)를 따른다. 이 문서의 UI/전송 검증을 의미 검색·새 query plan·새 검색 엔진 검증으로 확대하지 않는다.

## 문제와 변경

자료로 질문은 조직 준비 controller의 snapshot이 있어야 전송되지만, 실제 파일 선택에서 질문 준비로 연결하는 조작이 없었다. 검색 결과의 유일한 준비 버튼도 정리 작업으로 전환하고 질문을 바꿨다. 이제 파일 선택→선택 자료 읽기와 검색 결과→선택한 자료로 질문을 제공하고 원래 질문 초안을 유지한다. 자료가 없으면 파일 선택/자료 찾기로 안내하며 자동 읽기·전송·원본 쓰기는 하지 않는다.

기존 reader/controller/발췌 목록을 재사용한다. 준비 상태에 `organize | grounded` 목적을 두며 질문용 발췌는 준비 당시 질문과 현재 질문이 같아야 전송할 수 있다. 질문을 바꾸면 같은 선택 자료로 다시 읽어야 한다. 읽기 실패한 선택 파일은 재읽기에도 남기고, 사용자가 제외한 읽기 성공 파일은 다시 넣지 않는다. 전체/하위 폴더의 불완전 준비를 선택 파일로 조용히 축소하지 않고 다시 명시 선택하게 한다.

일부 자료 승인, 전송 전후 원본/발췌 hash 확인, 질문별 동의, 취소와 계정/권한 변경 뒤 늦은 답변 차단을 유지한다. 새 정리 요청은 앞선 질문의 명시 범위를 reset한다. 질문용 snapshot은 이전 정리 패널에 표시하거나 조직 AI action으로 보낼 수 없다. 앱 서버의 경로/hash 등 metadata와 공급자의 파일 이름/발췌 전송을 구분해 안내한다.

준비 영역은 기존 대화의 스크롤 영역에 둬 입력창을 밀어내지 않는다. 전송 중과 답변 완료 뒤 빈 초안에서는 준비 영역을 숨겨 기존 최신 답변 따라가기가 동작한다. 본문 발췌를 펼쳐도 입력과 보내기 조작은 화면 안에 남는다.

검색 조건은 결과 확인 때 접히고 기간은 필요한 경우 펼친다. 범위 radio와 마지막 검색 버튼을 유지한다. 결과는 공통 파일 행, 짧은 상태와 접은 근거로 구성한다.0개와 날짜0개 문구를 반복하지 않고 다음 행동을 안내한다. 제외 상세는 원인별 수를 보이고20개씩 읽는다. 보조 작업 기록 표시와 결과 설명 반복을 줄였다.
