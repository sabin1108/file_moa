# 데모 사용성 보완 후 로컬 로딩 관찰

후보 기능의 비용 관찰이며 속도 개선 전후 비교가 아니다. 최종 production 빌드의 로컬 loopback 서버에서 공개/샘플 6경로 × 2폭 × 3회, 총 36표본을 수집했다. 샘플 세션을 먼저 만들었고 인증 쿠키는 넣지 않았다. 각 폭에서 순서대로 방문했으므로 전부 독립적인 cold 표본이라고 보지 않는다. CPU/네트워크 제한을 적용하지 않았다.

원자료: `.omx/verification/demo-usability-20261116/performance-after.json`, 실행 스크립트 `measure-after.mjs`. 빌드 ID와 각 요청의 실제 도착 경로·문서/자원 전송량·요청 수·탭 JS heap 관측값을 포함한다. heap 관측은 전체 브라우저/기기 peak RAM이 아니다. 모델·운영 DB·메일·실제 로그인은 사용하지 않았다.

전체 production 정적 JS/CSS 산출물은 **54파일/4,586,740bytes**다. 특정 경로의 초기 전송량과 같지 않다. 조건을 맞춘 변경 전 빌드/시간은 없어 증가량·개선율을 계산하지 않았다. 신규 경로 진입 기능의 구현/회귀 검증과 이 로딩 관찰을 구분한다.

인증 후 경로, 실제 사용자 입력의 field INP, 실제 AI 첫 응답/완료, 디스크 I/O, 서버 부하/청구 비용은 미측정이다. 개발 서버의 컴파일 대기 시간이나 일시적인 테스트 시간 초과를 production 지연으로 환산하지 않는다. 일반 사용자 환경의 성능 완료를 주장하지 않는다.
