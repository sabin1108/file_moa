# 데모 진입·자료 질문·로그인 실패 후속

2026-11-16. 사용자가 설정의 안내 링크, 체험 시작 후 안내 누락, 자료로 질문의 막힌 흐름, 정식 사용 진입의 인증 오류를 보고했다. 기존 미커밋 변경을 보존하며 이 네 경로만 수정했다. 확장 프로그램의 `data-hwp-extension` 경고는 사용자 요청대로 수정하지 않았다.

## 원인과 수정

| 항목 | 확인한 원인 | 수정과 계약 |
| --- | --- | --- |
| 설정의 안내 재생 | 일반 텍스트 링크로 별도 표시 | 기존 `SettingRow`와 `ActionLink`의 secondary 버튼을 사용한다. |
| 체험 시작의 안내 누락 | 기존 세션의 표시 기록과, Next Link 이동 후 쿠키 발급 이전의 공통 레이아웃이 남는 문제 | 샘플 시작 CTA만 문서 이동을 사용하고 진입 시 `guide=1`을 요청한다. 안내가 이를 즉시 소비해 새로고침/화면 이동에서는 반복하지 않는다. 기존 세션과 작업 내용은 유지한다. |
| 안내 저장소 거부 | 기록을 못 읽어도 자동 표시를 허용해 새로고침마다 열림 | 알 수 없는 이력은 자동 재생하지 않는다. 명시 진입과 설정의 재생 요청은 기존 안내를 연다. |
| 자료로 질문 | 선택 0개일 때 보내기를 막지만 자료 선택으로 이어지는 동작이 없고 체크박스는 선택 모드 뒤에 숨음 | 선택이 없으면 자료 패널을 열어 파일 체크를 바로 제공한다. 선택 완료는 입력창으로 초점을 돌린다. 파일만 선택하며 선택 전 완료/전송은 막는다. 기존 발췌/출처 체험을 사용하고 실제 AI 답변이라고 표시하지 않는다. |
| 무관한 자료 선택 기능 | 공통 선택 도구에 폴더 체크와 복사/이동이 함께 표시 | 질문 자료 선택에서만 폴더 체크를 숨기고, 실제 계획 기능이 없는 선택 도구에는 복사/이동을 표시하지 않는다. 정식 파일 화면은 기존 callback을 계속 제공한다. |
| 익명 정식 사용 진입 | 세션 쿠키가 없어도 인증 SDK 생성 과정의 설정 검사를 실행 | 설치된 Better Auth의 `getSessionCookie`로 세션 후보가 없으면 `null`을 반환한다. 인증을 생성하지 않은 익명 방문은 로그인 화면에 진입한다. 쿠키가 있으면 기존 SDK 검증·계정 소유권 확인·실패를 그대로 유지한다. |
| 인증 실패 후 화면 | 서버 인증 실패가 로그인 화면 전체의 처리되지 않은 오류로 노출 | 로그인 전용 오류 경계에서 공통 `AuthShell`/`StatusNotice`로 재시도와 데모 복귀를 제공한다. 내부 오류/토큰/비밀번호를 표시하지 않고 실패를 로그인 성공으로 바꾸지 않는다. 서버 진단도 숨기지 않는다. |

표시 정책은 ‘체험 시작하기로 들어올 때 한 번’이다. 같은 세션의 작업을 이어가도 명시적 시작에서는 안내를 열며, F5와 일반 화면 이동은 새 시작으로 보지 않는다. 브라우저 전체에서 평생 한 번 표시하는 정책은 아니다.

첫 production 장애 검사는 미서명 임의 쿠키를 SDK가 정상 거부해 로그인 폼을 표시했고, 기대한 오류 화면 대기에서 실패했다. 이후 인증 초기화가 명시적으로 실패하도록 합성 메일 설정을 잘못된 값으로 지정한 별도 서버에서 재실행했다. 이는 운영 인증 성공 검증이 아니다. 해당 서버의 DB 주소는 연결할 수 없는 loopback port 1이고 공개 AI도 비활성화했다. 두 실행의 로그를 모두 보존했다.

## 남은 문제와 미검증

**사용자가 보고한 자격 증명 있는 환경의 실제 인증 서버/DB 오류는 해결 완료가 아니다.** Ego 브라우저에 세션 쿠키가 존재할 때 같은 실패가 재현됐다. 쿠키를 지우거나 검증을 우회하지 않았으며, 운영 DB에 접속하지 않아 현재 환경의 정상 설정/기존 세션 유효성을 검증하지 않았다. 콘솔 진단은 남고 복구 화면만 제공한다. 실제 로그인 제출·메일·소셜 인증 성공도 미검증이다.

샘플의 자료로 질문은 선택 발췌와 출처를 보여주는 체험이며 자유 질문의 생성·추론 답변은 아니다. 실제 개인 폴더·유료 AI·모델 다운로드·물리 IME는 실행하지 않았다. 기존 정식 인증 경로 검사 1실패, 일반 대화 검사의 진입 시간 초과, 화면2실패/taste20, 이전 시각 경고/도구 차단은 이번 통과 결과로 덮지 않는다.

Better Auth에 별도 쿠키 이름이나 bearer 인증을 추가하면 쿠키 선검사도 함께 갱신해야 한다. 현재 설정과 설치된 SDK를 확인했으며 새 패키지는 추가하지 않았다.

이전 작업 전부터 존재한 변경/개인 문서 30개는 모두 해시가 같다. 이번 시작 시점의 77개 변경 파일 중 67개는 그대로이며 나머지 10개는 이 요청 범위에서 수정했다. 새로 수정한 기존 추적 파일과 새 파일은 별도로 manifest에 기록했다. HEAD는 그대로이며 배포·커밋·푸시는 하지 않았다. 이번 검증용 production 서버 3035와 Ego 작업 탭은 종료했고, 기존 개발 서버 3034는 확인용으로 남겼다.
