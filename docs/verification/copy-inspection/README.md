# 복사 전 내용 검사 검증

2026-10-30에 읽기 전용 복사 검사 단위를 구현했다. 이후 사용자의 폴더 디자인 교체/새 폴더 생성 요청은 [후속 검증](../folder-workspace/README.md)으로 구분한다.

## 구현과 경계

충돌 없는 복사 계획에서 명시적으로 검사하면 출발·도착 목록, 크기/수정 시각, Worker SHA-256, 소스 핸들 동일성 및 내용/충돌 재검사를 수행한다. 파일당 16MiB, 총 64MiB, 100개 한도. 진행·취소·오류·완료/상세 화면을 제공한다. 실제 복사 실행, 소스 쓰기, 업로드는 이 단위에 포함하지 않는다.

## 당시 실행 증거

- 미구현 서비스/컨트롤러 import 실패를 확인한 후 구현했다. 이것을 개별 assertion 실패 수로 세지 않는다.
- 당시 pnpm check: 단위 192개/20파일, 타입·린트·서버 경계21·구조25+6+3·production43페이지 통과.
- [검사 브라우저 27확인](browser/result.json): 실제 Worker/WebCrypto/OPFS, 독립 Node SHA-256 비교, 100개/64MiB 정확한 경계, 초과 거부, 취소·권한·오류·충돌, 반복 Worker 정리.
- 계획 회귀32, 목적지 회귀29 확인. 각각 `plan-regression`, `destination-regression`에 원자료 보관. 합계88은 확인 항목 수이며 독립 사용자 시나리오88개라는 뜻이 아니다.
- 390/768/1440/1920 완료와 loading/error 화면 확인. [성능](performance.md)은 6경로×2폭×3회 원자료와 검사 비용을 구분한다.

## 검증 한계

OS picker와 권한 응답은 fixture이며 네이티브 OS 권한 창, 실제 개인 폴더, 물리 키보드/IME, 실기기 iPhone 검증이 아니다. 후속 UI 수정 뒤의 최종 브라우저 회귀는 후속 보고서 상태를 따른다. 실제 복사의 무덮어쓰기·부분 실패/복구 계약을 검사 통과로 대체하지 않는다.
