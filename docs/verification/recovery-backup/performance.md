## 실제 OPFS 백업

독립 localhost probe에서 실제 session/OPFS/Worker를 실행했다.3파일 중1개가1MiB인 작은 작업을3회, source/target large.bin이각16MiB인 경계 작업을1회 수행했다. 작은 작업 source+target 총량은2097207bytes다. 보관본에는 target만 복사하므로 이 총량을 쓰기량으로 해석하지 않는다.

| 작업 | 표본 | 검사 ms | 백업·양쪽 기록·감사 ms |
| --- | ---: | --- | --- |
| 작은3파일,1MiB payload 포함 | 3 | 70.0 / 65.6 / 56.3 | 2913.7 / 1026.9 / 1174.1 |
| 16MiB 파일 경계 | 1 | 190.3 | 1503.6 |

초기 작업은 보관함/기록 폴더 생성과 cold Worker/브라우저 상태를 포함한다. 작은 작업의 검사는 중앙값65.6ms, 백업은1174.1ms지만 n=3이므로 안정적인 p95나 네이티브 디스크 처리량을 주장하지 않는다. [원자료](browser/checks.json).8개 생성 Worker가 모두 terminate된 것을 확인했다. 이 관측은 전체 브라우저 메모리 누수 부재를 증명하지 않는다.

본문 해시는 Worker, stream 요청은64KiB slice로 제한한다. source+target 합계64MiB/파일16MiB 한도와 보관본 재읽기를 적용했다. 최대64MiB batch의 실제 총 메모리, 실디스크 경쟁/권한창, 장시간 반복, field INP는 미측정이다. 추측에 따른 memo/캐시/추가 패키지는 도입하지 않았다.
