## 문제와 바뀐 동작

기존9단계는 네 작업을 한 문장으로 묶고 기록함 버튼만 가리켰다. 설명 위치는 대상의 top값 하나로 위/아래를 정해 퀵설정을 가릴 수 있었다. 경로가 준비되는 동안 강조가 사라질 때 배경의 명암도 달라졌다. 관찰 시점 이후 움직인 대상은 강조 좌표와 실제 좌표가 어긋날 수 있었다.

안내는17단계다. 일반 대화·자료 찾기·자료로 질문·자료 정리를 각각 언제 쓰고 어떤 순서로 사용하는지 설명한다. 처음의 실제 작업 버튼을 각각 강조하며 이미 대화 중이면 실제 작업 선택 컨트롤을 가리킨다. 작업 모드나 초안을 바꾸지 않고 AI 요청도 실행하지 않는다.

기록함의 대화·결과물·위키·기억·프로필은 실제 탭을 임시로 펼쳐 보여 준다. 단어를 나열하는 대신 보관 목적, 만드는 경로, 기억 승인과 내 정보 참고 조건을 설명한다. `previewKind`는 표시만 바꾸므로 기존 탭·검색·편집 값을 덮어쓰지 않는다. 숨겨진 편집기는 mount를 유지해 미저장 내용이 남는다. 임시 보기는 비모달로 펼치며 안내가 최상단의 modal을 유지한다. 폴더 선택·저장·기억 승인·원본 변경을 자동 실행하지 않는다.

설명과 대상의 실제 사각형으로 좌우/아래/위의 겹치지 않는 공간을 고른다. 넓은 대상은 아래 공간을 먼저 쓴다. 여유가 적으면 설명 본문만 스크롤하고 이전·다음·건너뛰기는 항상 보인다. 각 설명은 제목부터 읽게 본문 스크롤을 초기화한다. 읽을 공간 자체가 없는 극단적으로 작은 화면에서는 잘못된 강조를 그리지 않는다.

일반 이동은 같은 dialog를 유지한다. 배경 명암을 통일하고 강조와 설명 위치를180ms로 잇는다. 대상의 실제 움직임은 안내가 표시되는 동안 requestAnimationFrame에서 추적하며, 좌표가 달라졌을 때만 상태를 갱신한다. 닫힘/이탈 확인 중에는 overlay를 제거해 추적도 정리한다. 새 안내를 열면 이전 화면의 좌표를 재사용하지 않는다. 움직임 감소 환경에서는 CSS 전환을 제거한다.

검토에서 미저장 편집기를 둔 채 대화 설정의 다시보기로 들어가면 이탈 확인이 닫힌 drawer에 숨는 문제를 찾았다. `RecordEditor`의 공통 이탈 요청이 상위에 표시를 요청하고, `LiveConversation`이 기록 화면과 drawer를 다시 열도록 고쳤다. 취소하면 같은 안내 단계로 돌아가고, 안내를 닫아도 초안이 남는다.

## 읽는 순서

1. `workspace-tour-steps.ts`, `ConversationStart.tsx`: 실제 대상과 작업별 설명.
2. `WorkspaceTour.tsx`, workspace layout: 계정/다시보기 수명과 이탈 보호, 기록 임시 보기 context.
3. `WorkspaceTourOverlay.tsx`, `useTourSpotlight.ts`, `tour-card-position.ts`: native dialog/초점, 실제 위치 추적, 독립 검증 가능한 배치 규칙. 같은 dialog 안에서 설명만 바뀐다.
4. `LiveConversation.tsx` → `ConversationWorkspace.tsx`/`use-drawer-dialog.ts` → `AiLibraryPanel.tsx`: 임시 표시를 실제 기록함에 연결하고 원래 상태를 유지한다.
5. `RecordEditor.tsx`의 `onReveal`: 숨은 편집 확인을 실제 사용자에게 보이게 한다.

새 의존성·범용 안내 프레임워크는 추가하지 않았다. 표시 수명을 별도 overlay로 분리해 닫힌 안내의 좌표를 억지로 effect에서 초기화하던 구현도 제거했다.
