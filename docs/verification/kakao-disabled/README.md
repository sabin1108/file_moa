# 카카오 일시 제외와 Google 명시 연결 — 2026-11-06

사용자는 카카오 KOE205와 콘솔의 이메일 권한 없음/닉네임 사용 안 함을 확인한 뒤 카카오를 우선 제외하도록 변경했다. 앞선 기본 scope 축소(11eb1b6)는 이 일시 제외 지시로 대체한다. 지금 카카오 비즈 앱 전환·이메일 동의 설정을 진행하지 않는다.

## 현재 동작

- socialProviderConfiguration은 Google/네이버만 등록한다. 저장된 카카오 환경값이 있어도 새 SDK provider가 활성화되지 않는다. 실제 로그인·가입·메일 대기·소셜 가입에서 두 공급자만 표시한다. 이메일 가입·로그인과 Stepper는 유지한다.
- 계정 설정은 사용 가능하거나 이미 연결된 수단만 반환한다. 미연결 카카오 행은 숨긴다. 기존 연결이 있으면 일시 중지로 안내하며 자동 삭제하지 않는다. 기존 DB 식별자·유효한 세션·원래 작업 공간·폴더 owner 인식은 보존한다. 마지막 수단을 임의로 제거하지 않는다.
- 같은 이메일에 연결되지 않은 Google 신원이 들어오면 신규 계정/자동 연결을 거부한다. 기존 모아 계정에 로그인한 뒤 Google을 명시적으로 연결하면 같은 사용자에 두 로그인 수단을 쓸 수 있다. 사용자가 실제 연결 성공을 확인했다. 이메일 일치 자체가 두 신원 소유 증명은 아니다.

## 검증

- 카카오 키가 있어도 등록되지 않아야 한다는 회귀를 변경 전 실패로 확인하고 수정했다. 최종 단위699개/74파일, 타입·린트·build·서버경계21·기능구조 검사 통과. 실제 비밀값 변경 파일 대조0건/클라이언트37파일 대조0건.
- 일회용 PostgreSQL의 상위25개/실제 SDK·SQL 통합50개 통과. 활성 OAuth 경로를 Google/네이버로 검증했고 카카오 시작은 외부 HTTP 없이 거부했다. 저장된 카카오 계정·미확인 연락 이메일·유효 세션의 인식/설정표시/마지막수단 보존도 별도 확인했다.
- Google이 기존 이메일·비밀번호 계정과 충돌할 때 자동 가입/연결하지 않고, 그 계정에 명시적으로 Google·네이버를 연결하는 SQL/SDK 경로를 확인했다. ID token 비보관·다른 계정으로 이동 거부·세션/폴더 격리는 유지한다.
- 브라우저169개 통과, build=LDTrkRHE2c58GuQ1sFDtI. 카카오 키가 남아 있는 합성 환경에서도 실제 로그인/가입 두 버튼과 계정설정 두 행을 확인했다.390/768/1440/1920px 인증 화면, 기존 가입·복원·IME·비밀번호/이름·설정·계정연결·로컬 OPFS 검사를 재실행했다. 설정 앱 검사9개 FAIL0, 브라우저 오류0.
- [기존 인증 경로36개 로딩 표본](browser/performance-authenticated.json)과 [초기 canvas32개](browser/canvas-checks.json)는 격리 lab 원자료다. 실제 사용자 INP/운영 부하/물리IME·OS권한·GPU를 의미하지 않는다.

초기 브라우저 실행에서 버튼3→2 기대값을 수정하던 검사기 치환이36개 성능 표본의 기대값까지26으로 바꿔 실패했다. 실제36개 원자료를 확인하고 해당 검사기 오타를36으로 수정한 뒤 최종 전체 회귀를 통과했다. 실패와 최종 통과를 구분한다.

실제 사용자 계정·운영DB·메일·공급자 콘솔을 수정하지 않았다. 외부 OAuth HTTP는 합성/Google JWKS 서명 fixture이며 실제 사용자 인증은 별도다. 카카오 재개 시에는 공급자 등록과 콘솔 동의 권한을 함께 검토해야 한다.
