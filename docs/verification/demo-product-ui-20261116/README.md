# 데모를 실제 제품의 공통 화면으로 정정

2026-11-16. 사용자는 별도 게임 같은 데모가 아니라 실제 로그인 후 작업 화면을 보여 주고 폴더만 준비된 자료로 바꾸기를 요청했다. 기본 버튼/선택 UI, 설명 없는 예시, 초기 자동 체크, 별도 6단계 안내를 지적했다. 앞선 데모 확장 방향을 정정한다.

## 무엇을 고쳤는가

| 문제 | 수정 |
| --- | --- |
| 데모가 별도 선택 UI를 만듦 | 실제 `LiveConversation`과 데모가 `ConversationTaskIntro/ConversationTaskControls`를 공유한다. 기존 작업 선택 스타일·공통 action 스타일을 사용한다. |
| 예시가 기능인지 실행 버튼인지 불분명 | 현재 작업의 역할을 표시하고, 예시는 ‘입력 예시’ 안에 접는다. 누르면 초안만 채우며 자동 실행하지 않는다고 설명한다. |
| 자료/저장/설정과 기록 탭이 다른 모습 | `ConversationContextBar`, `ConversationPanelNavigation`, `RecordKindTabs`, 제목/본문 입력 `RecordFields`를 실제 화면과 공유한다. |
| 파일 행만 공유하고 목록은 별도 구현 | 실제 `FolderListingView`에 샘플 목록과 콜백을 공급한다. 공용 이름 검색·키보드 선택·선택 도구·파일/폴더 행을 사용한다. |
| 들어가자마자 세 파일이 체크됨 | 새 상태와 초기화의 선택을 빈 배열로 바꿨다. 선택 전 제안 생성을 막는다. 이미 보관된 명시 선택은 보존하고 복원 안내를 표시한다. |
| 데모 전용 6단계 안내 | `SampleExperienceGuide`와 전용 스타일을 제거했다. 기존 `WorkspaceTour`의 같은 17단계·overlay·초점·이탈 보호·기록 임시 보기를 사용한다. 경로만 `/demo` 아래로 바꾸고 폴더 연결 설명만 예시 폴더에 맞게 보완한다. |

안내는 소개 화면에서 시작하지 않는다. 실제 샘플 세션별로 이 탭에서 한 번 자동 표시하고, 기존 ‘사용 방법 다시 보기’와 `?guide=1`이 같은 17단계를 연다. 단계 이동으로 체크·작업·전송을 자동 실행하지 않는다. 기록 안내 단계에서는 실제 화면처럼 기록 패널을 임시로 열고 비모달로 표시하며, 종료 뒤 원래 상태를 유지한다.

설정의 저장 설명은 샘플 보관 방식에 맞게 입력받도록 최소 확장했다. 실제 서비스의 기본 문구와 저장 동작은 그대로다. 샘플에 ‘새로고침하면 사라진다’거나 ‘실제 폴더에 저장됐다’는 거짓 안내를 넣지 않았다.

## 읽을 파일과 책임

- `features/conversation-workspace/material-work/ConversationTaskControls.tsx`: 실제/데모의 작업 제목·설명·선택·입력 예시.
- `ConversationContextBar.tsx`, `ConversationPanelNavigation.tsx`: 자료·저장·설정과 패널 탐색. 데모 전용 텍스트 버튼을 대체한다.
- `features/ai-records/library/RecordKindTabs.tsx`, `editing/RecordFields.tsx`: 실제/샘플의 같은 기록 탭과 입력 컨트롤.
- `features/local-folders/browsing/file-list/FolderListingView.tsx`: 같은 목록 화면. 미리보기 지원과 검토 중 선택 잠금을 표시 입력으로 받는다. 기본 실제 동작은 유지한다.
- `features/sample-workspace/files/SampleFolderPanel.tsx`: 가상 카탈로그를 실제 목록 상태로 바꾸고 기존 이름 검색을 연결하는 어댑터. 개인 폴더 핸들을 만들지 않는다.
- `features/onboarding/WorkspaceTour.tsx`, `workspace-tour-steps.ts`: 같은 튜토리얼과 경로 투영.
- `features/sample-workspace/SampleWorkspaceTour.tsx`, `app/demo/layout.tsx`: 서명 샘플 세션으로 안내 수명만 연결한다. 실제 계정 claim이나 DB를 호출하지 않는다.
- `sample-state.ts`, `sample-workspace-store.ts`: 초기 체크 제거, 기존 저장 상태 검증·복원, 복원된 선택 안내.

표시 공유를 위해 실제 인증을 우회하거나 가짜 실제 폴더 provider를 넣지 않았다. `LiveConversation` 전체는 실제 owner·IndexedDB·폴더 핸들·AI 통신에 결합돼 있다. 이번 변경은 표시 컴포넌트를 양쪽에서 공유하고 샘플 데이터/동작을 연결하는 방식이다.

## 회귀와 독립 검토

초기 체크·동일 17단계/경로·설명/예시 구분 회귀 3개가 수정 전 실패하고 수정 후 통과했다. 기존 저장소 검사는 기본 체크에 기대지 않고 명시적으로 파일을 선택하도록 준비를 고쳤다. 서버 layout의 metadata를 확인하는 테스트에는 서버 전용 표식 mock을 적용했으며 실제 인증 호출로 바꾸지 않았다.

독립 architect 검토에서 아래 연결 오류를 찾아 보완했다.

1. 검색 결과 선택의 `(parentPath, name, kind)` 계약을 올바르게 받고 해당 폴더로 이동한다.
2. 이미 선택된 검색 결과를 다시 선택해도 해제하지 않는다. 브라우저 회귀를 추가해 수정 전 실패를 확인했다.
3. 검색 재시도는 질문을 지우지 않고 같은 검색어로 재실행하며 취소/늦은 완료를 분리한다.
4. 자료·설정 패널의 trigger를 공용 drawer에 전달해 닫은 뒤 초점을 복원한다.

초점 복원 추가 중 미리보기 변수 `document`가 브라우저 전역과 겹쳐 전송이 막힌 오류도 실제 브라우저에서 확인하고 `previewDocument`로 고쳤다. 실패 로그를 보존했다. 최종 독립 확인은 마지막 명시 선택 반례에 대해 CLEAR이며, 전체 5단계 EGM 완료를 뜻하지 않는다.

## 남은 차이와 미검증

화면이 공유된 것과 모든 업무 동작이 완전히 같은 것은 구분한다. 샘플 AI 답변은 아직 준비된 응답/발췌이며 외부 AI 호출이 없음을 답변에 표시한다. 샘플 기록 저장 형식은 탭 전용이고, 실제 폴더 저장·모델 품질·계정 격리·물리 IME·OS 권한창·실제 원본 편집/복사/복구는 이번에 실행하지 않았다. 샘플의 일반 파일 복사/이동 버튼과 폴더 단위 선택은 완전한 정식 동작으로 연결되지 않아 안내를 제공한다. 정리 제안의 가상 이동/되돌리기와 혼동하지 않는다.

기존 세션에서 보관된 선택은 새 자동 체크가 아니라 복원된 값이다. 새 세션/초기화는 0개로 시작하고, 기존 선택은 임의로 삭제하지 않는다. 이전 6단계 안내의 직렬화 필드는 예전 상태를 읽기 위해 남았지만 현재 안내 화면이나 단계 목록을 구동하지 않는다.

새 기능의 실제 UI/설명/튜토리얼 변경은 이제 공용 컴포넌트와 같은 단계 목록에서 반영된다. 샘플 동작 어댑터와 제공 범위가 실제 기능과 일치하는지는 계속 검증해야 하며, ‘폴더만 다르고 모든 동작이 이미 동일하다’고 보고하지 않는다.
