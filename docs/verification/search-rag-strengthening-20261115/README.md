## 1. 새 자료의 검색 품질

새 [v2 합성 자료](../../../tests/fixtures/local-rag-search-v2.json)는 20문서·20질문, seed `2026111502`다. dev 6질문과 holdout 14질문의 문서 계열을 분리하고 정답·금지 후보·사용자가 일반 필수 단어를 비우는 선택을 실행 전에 고정했다. `frozen.json`에 v1/v2 SHA-256과 배포 Worker 자산 6개의 경로·해시를 남겼다. 결과에 맞춰 정답이나 threshold 0.85를 바꾸지 않았다. 직접 작성한 합성 평가이며 독립 벤치마크가 아니다.

| holdout 지표 | 기본 검색 | 선택 의미 검색 결합 |
| --- | ---: | ---: |
| Recall@5 | 0.5833 | 0.8750 |
| MRR | 0.5833 | 0.8611 |
| 지정 오답 문서 노출 횟수 | 0 | 4 |
| 관련 문서 없는 질문의 후보 수 | 0 | 0 |

양성 질문은 holdout 12개, dev 5개다. dev Recall@5/MRR은 기본 0.6/0.6, 의미 결합 1/1이지만 지정 오답이 1회 나왔다. 오답 횟수는 질문별 top5에 지정 문서가 나온 횟수이며 독립 규칙 수가 아니다. 의미 질문의 충전지 초안·암호 복구 초안·수압 조절·결로 문서가 오답이었다. 이는 명시 제외 조건을 무시했다는 뜻과 구분한다. 결로 문서 하나와 퇴비 문서는 누락됐다. 긴 질문 h12의 기본 검색은 `invalid-find-terms`로 거부돼 결과 0으로 집계하고 오류를 보존했다. UI에서는 검색어를 줄여 확인해야 하는 제한이다.

같은 원문·문서·보호 조건을 사용하되, 의미 검색 쪽은 fixture에 명시한 사용자의 필수 단어 비우기 확인을 적용한다. 이 사용자 조작의 차이도 비교 조건이다. PDF 원문은 이 평가에서 Worker에 직접 전달했다. PDF 추출과 현재 원본 검증은 별도 실행으로 확인했다.

품질 실행은 실제 로컬 Vite Worker/WASM이다. 배포 의미 Worker를 직접 부트스트랩한 별도 진단은 handler가 초기화되지 않아 품질 수치에 쓰지 않았다. 이 진단만으로 제품의 의미 검색 장애를 판정하지 않는다. 배포 환경 전체의 의미 검색 정확도나 개인 자료 전반의 품질로 일반화할 수 없다. `quality-local.json`, `quality-production-probe.json`, `summary.json`을 함께 본다.

## 2. 배포 환경에서의 동등 캐시 비교

사용자는 로컬만의 비용 실험 대신 실제 배포 환경을 선호한다고 정정했다. `https://web-eight-rho-72.vercel.app` 페이지에서 실제 사용하는 공개 Worker 경로를 찾아 해시를 고정하고, 그 배포 Worker를 그대로 실행했다. 추출 캐시는 현재 소스의 `LocalTextIndex`를 검증용 묶음으로 로드해 별도 합성 IndexedDB에서 처리했다. 페이지 전체의 사용자 검색 지연이나 Vercel 서버 CPU 측정은 아니다.

4종 입력(짧은/긴 MD, 1쪽/24쪽 PDF) × Worker 신규/재사용 × 미변경/변경 × 7회 × 캐시 유무로 224개 관측, 112쌍을 남겼다. 각 쌍은 같은 File·원본 bytes/hash·질문 발췌·전체 추출 텍스트를 사용했다. 매 회 순서를 바꿨다. 변경 조건은 run 3과 6에서 바꿨다. 완전 무캐시 분기는 파생 본문 조회·쓰기를 모두 0회로 확인했다. 현재 캐시 분기는 매번 조회·쓰기를 포함했다. 제품 기본에 무캐시 옵션을 만들지 않았다.

Worker 재사용·원본 미변경·초기 회차 제외 6표본의 **전체 시간 중앙값**이다.

| 입력 | 완전 무캐시 | 현재 hash 검증 캐시 |
| --- | ---: | ---: |
| 짧은 MD | 1.55ms | 6.40ms |
| 긴 MD | 6.15ms | 16.90ms |
| 1쪽 PDF | 249.50ms | 8.30ms |
| 24쪽 PDF | 304.45ms | 6.65ms |

이번 조건에서는 PDF의 재추출 비용을 줄이는 이득이 크고 MD는 IndexedDB 조회·복제·쓰기 비용이 더 컸다. 모든 기기나 사용 빈도에서 캐시가 이긴다는 결론을 내리지 않는다. `summary.json`에는 초기/변경/미변경·신규/재사용별 중앙값·평균·모분산·최솟값·최댓값과 단계별 시간을 모두 남겼다. 전 조건의 논리 본문 저장량은 4,726,696bytes이며 실제 디스크 점유나 브라우저 quota 값은 아니다.

내부 호출 횟수를 세려고 Blob으로 Worker를 감싼 앞선 시도는 MD 112개에서 원본 읽기 1회·hash 2회를 관측했으나 PDF 112개가 실패했다. 같은 PDF의 원래 배포 Worker와 로컬 reader는 성공했다. 감싼 실행의 PDF 실패는 정상 비용이나 제품 PDF 오류로 세지 않았고, 최종 비용은 감싸지 않은 Worker로 모두 다시 측정해 오류 0개였다. 최종 native 실행의 내부 읽기/hash/추출 호출 횟수는 직접 계측하지 않았다. `cacheHit`와 저장소 조회·쓰기는 관측값이며, 생략한 추출 횟수를 직접 측정한 것처럼 쓰지 않는다.

입력 File은 합성 메모리 bytes다. 실제 디스크 읽기와 OS 권한 창을 포함하지 않는다. 초기 회차는 파생 추출 캐시가 비어 있다는 뜻이며 HTTP cold나 첫 모델 다운로드가 아니다. 기존 브라우저 캐시는 비우지 않았다. CDN 청구·첫 방문 전송량·서버 CPU·전체 peak RAM·전력·배터리는 미측정이다.

## 3. RAG 전체 과정

격리 브라우저의 검색→선택→원본 재읽기→질문 변경 뒤 재읽기·발췌→동의→합성 답변·인용 16개, 기존 자료 질문 33개, 검색/RAG 회귀 37개, 필드 검색 21개를 통과했다. 취소·원본 변경·권한 실패·부분 범위·위조 인용·동의 무효화는 기존 회귀로 확인했다.

사용자가 이번 세션에 별도로 **합성 본문 1회 전송**을 허용했다. 운영 페이지에서 별도 OPFS 합성 폴더를 연결하고 다음 한 파일만 검색·선택했다.

- 파일: `가온센터 이력서.md`, 46bytes
- 본문: `가온센터 이력서 양식과 지원 경험`
- 질문: `이 자료에 어떤 내용이 담겨 있어?`
- 전체/발췌 SHA-256: `1d3110e24328df3ab29722df152cd061943684557e79abfa3d62dbcd009fcbff`

질문 변경 후 원본을 다시 읽었고, 발췌와 해시를 화면에서 확인했다. 동의가 꺼진 동안 보내기 비활성·전송 0회를 확인한 뒤 동의를 선택해 **한 번** 제출했다. 승인된 질문·발췌를 담은 Server Action HTTP 200 한 건과 반환 모델 `gpt-6-luna`를 관측했다. 실제 답변은 “제공된 발췌문에 따르면, 자료에는 가온센터 이력서 양식과 지원 경험이 담겨 있습니다. 발췌가 짧아 세부 내용은 확인하기 어렵습니다.”였다. 인용은 원문과 같았고, 인용에서 `/files`의 실제 합성 원문이 열렸다. 감시한 파일 읽기 이름은 모두 이 합성 파일 하나였다.

브라우저 UI의 실제 서버 요청/답변을 확인한 것이며 공급자 청구서나 서버 토큰 원장은 조회하지 않았다. 기존 총 1달러 한도는 유지하며 추가 제출은 하지 않았다. OS 폴더 선택은 OPFS를 반환하는 검증용 picker로 대체했으므로 실제 OS 선택 창 성공으로 세지 않는다. `production-*-preview.json`, `production-rag-answer.json`, `production-answer-text.json`, `production-citation.json`이 근거다.

## 4. 기기·입력과 정리

접근한 호스트는 Ryzen 5 5600, 논리 프로세서 12개, RAM 31.91GiB다. WPD 휴대기기와 배터리는 조회 결과 없었고 adb도 없었다. 이것만으로 모든 외부 기기가 없다고 단정하지 않으며, 이번 도구에서 저사양/실제 모바일·물리 한국어 IME·실제 OS 권한 UI·실제 메모리 부족·배터리 계측을 실행하지 못했다. 합성 IME나 좁은 viewport를 그 결과로 대체하지 않았다. 로컬 컨트롤러의 설치 즉시 취소→오류 안내→캐시를 이용한 재설치는 ready로 복구됐다. 다운로드 중간 취소나 실제 메모리 압박 검증과 구분한다.

검증용 운영 연결과 OPFS 합성 폴더, 별도 캐시 실험 DB 3개 및 진단 중 생성된 빈 DB는 제거했다. 기존 연결 3개와 활성 메타데이터가 이전과 같은 것을 비교했다. 기존 운영 모델 Cache는 보존했다. 로컬 모델 Cache는 시작 시 소유 상태를 기록하지 못해 보존했다. 생성한 브라우저 작업 공간과 서버는 정리한다. `cleanup.json`, `devices.json` 참조.
