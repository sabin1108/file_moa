이 문서는 최초 두 요청의 기록이다. 후속의 [일상 의도 평가 확장](../everyday-evaluation-cleanup/README.md)에서는 새 6요청을 별도로 실제 평가했다.

사용자가 요청한 다음 단계로 request-v1의 development 대표 두 요청을 실제 서버 유스케이스로 평가했다. 공개 카탈로그 84개에서 기존 후보 함수를 적용했다. 정답·유보 문서·개인 파일은 전송하지 않았다. `reviewStatus: unreviewed`인 기대값에 대한 제한된 확인이며 전체 AI 정확도를 뜻하지 않는다.

## 발견·수정과 호출 수

수정 전 지침 v2에서도 두 실제 응답의 ID·인용·날짜·경로 판정은 통과했다. 그러나 소스 점검에서 `/날짜|기간|…/` 키워드 분기가 ‘날짜별 정리는 하지 마’를 날짜별 정리 요청으로 단정함을 확인했다. 모델은 이번 표본에서 사용자 부정문을 따랐지만 서버 지침은 반대 조건을 공급했다.

1. ‘날짜별 정리 거부’와 ‘10월로 제한하면서 날짜별 정리 거부’ 두 회귀 검사를 먼저 추가해 모두 실패함을 확인했다.
2. 날짜 키워드 분기를 제거하고 지침 v3에서 부정문 존중·기간 필터·날짜별 그룹을 독립 조건으로 제공했다. 요청이 그룹을 요구하지 않으면 주제 경로/date:null을 사용하고, 긍정적으로 요구할 때만 확인된 날짜를 폴더 마지막에 넣는다. 기존 결정적 응답 파서·후보 함수·세션/동의/Origin·한도는 유지했다.
3. 회귀 검사 통과 뒤 두 실제 요청을 새 지침으로 각각 한 번 다시 검증했다. 생성 자동 재시도·모델 변경·한도 우회는 없었다.

## 재현과 변경 파일

실행 전 기존 서버용 `.env.local`의 키·DB 설정이 필요하다. 기본 `pnpm test`는 이 `.checks.ts` 파일을 실행하지 않는다. 한 실행은 development의 한 요청만 허용하며 유보 요청은 거절한다. 출력은 저장소 내 고정 경로의 시각별 JSON이라 기존 실패 기록을 덮어쓰지 않는다.

```powershell
$env:MOA_RUN_ORGANIZATION_LIVE='1'
$env:MOA_ORGANIZATION_CASE='october-reports'
pnpm exec vitest run --config tests/database/vitest.organization-live.config.mts
Remove-Item Env:MOA_RUN_ORGANIZATION_LIVE
Remove-Item Env:MOA_ORGANIZATION_CASE
```

다른 대표 요청 ID는 `measured-web-performance`다. 한도 거절·오류는 그대로 실패로 기록하고 자동 재시도하지 않는다. 공급자 입력을 가로채는 점검은 실제 fetch를 그대로 호출하며, 정확히 선정된 서버 자료만 포함하는지·허용 모델 endpoint인지·정답/키가 본문에 없는지 확인한다. 환경변수 값·쿠키·DB 접속 정보는 보고서에 기록하지 않는다.

읽는 순서:

1. [sample-organization.ts](../../../apps/web/src/server/sample-organization.ts): 날짜 키워드 단정 제거와 지침 v3.
2. [sample-organization.test.ts](../../../apps/web/tests/server/sample-organization.test.ts): 두 부정문 회귀 검사와 기존 서버 경계 검사.
3. [organization-live.checks.ts](../../../apps/web/tests/server/organization-live.checks.ts): 현재 후보/평가기 재사용, 실제 DB 예약·공급자 호출·안전한 결과 기록.
4. 위 실제 응답 JSON: 입력 경계와 출력·토큰·시간·판정의 실행 증거.

## 한계와 다음 작업

최종 지침에서 평가한 것은 대표 2요청 각 1회다. 나머지 development 14요청과 holdout 4요청, 임의 한국어 표현, 기간만 제한하는 요청의 실제 모델 출력, 보안 공격 저항 전체, PDF/XLSX 범용 파싱, 실제 사용자 환경은 검증하지 않았다. 부정문 회귀는 지침 구성을 확인하는 검사이며 모델의 모든 의미 해석을 결정적으로 보장하지 않는다.

최종 요약에는 ‘분류했습니다/정리했습니다’라는 완료 시제가 남았다. 실제로는 계획을 반환했으며 파일 적용은 실행하지 않았다. 이번 평가 함수는 요약의 시제·표현 품질을 채점하지 않는다. 기존 계획 검토 UI의 상태와 별개로, 후속 응답 문구 품질 검토 시 확인할 항목이다. 보류 이유는 날짜 없음/충돌 설명을 확인했으나 독립 사람 평가가 아니다.

다음 정식 TXT/MD 연결에서는 선택 문서·전송 내용·동의와 취소/늦은 응답·계획 검토·기존 충돌/복구 계약을 먼저 연결한다. 개인 파일 전송, 실제 파일 적용, 외부 배포는 이번 작업에 포함하지 않았다.
