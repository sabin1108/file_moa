# 인증 화면 프로토타입 형태 복원 — 2026-11-06

사용자의 최종 정정은 **디자인만 변경**이다. 가입 Stepper가 남아 있음을 확인했으므로 단계·search params·초안·인증·계정 연결 코드는 수정하지 않았다.

실제 화면에만 붙은 `.live` CSS가 소개 영역을 숨기고 카드 배경/테두리를 제거하며 전체 너비를504px로 바꾸고 있었다. 이 덮어쓰기를 삭제해 `AuthShell`과 기존 `LoginPrototype`/`WelcomePrototype`의 공통 배치·규격을 다시 사용한다. 소셜3행과 공식 브랜드 자산은 유지하고 높이48px·행 간격12px로 맞췄다. 가입 필드가 늘어날 때의 상단 고정도 유지한다.

## 확인 결과

- `pnpm typecheck`, `pnpm lint`, `pnpm build`: 통과.
- 390/1440/1920px에서 원본 프로토타입2개와 실제 로그인·가입 방법·이름 입력·이메일 확인 화면을 비교했다. 총18개 화면에서 가로 넘침이 없었다.
- 1440/1920px: 두 화면 모두 최대1120px 프레임, `546px 420px` 열,420px 카드,32px 안쪽 여백,1px 테두리,8px 모서리,22px 블록 간격으로 일치했다.
- 390px: 소개 숨김·단일 열,350px 카드,25px 안쪽 여백으로 일치했다. 실제 소셜 버튼은 세 해상도 모두48px였다. 가입 단계 표시도 보인다.
- 기능이 연결된 화면의 입력 항목 수에 따른 카드 높이는 다르다. 프로토타입의 문구·데모 동작을 실제 기능에 덮어쓰지 않았다.

화면과 수치는 [browser](browser)에 있다. 실제 화면은 새 production build를 별도 루프백 서버와 격리 Chrome에서 렌더했고, 서비스 접속값은 합성 값으로 덮어썼다. 원본 프로토타입은 실제 TSX/CSS를 정적 렌더해 비교했다. 실제 DB·메일·OAuth 제출은 하지 않았다.

이번 변경의 기능 회귀 테스트는 사용자 지시로 생략했다. 캡처와 geometry 측정은 화면 확인이며 가입·발송·인증 성공을 증명하는 테스트가 아니다. 이전 기능 검증은 [이전 기록](../auth-entry-and-account-connection/README.md)과 구분한다.

## 읽기 순서

`DESIGN.md` 최신 정정 → `auth-shell.module.css` → 이 문서와 `browser/geometry.json`. 실행 코드 변경은 공통 CSS 한 파일뿐이며 새 의존성·추상화를 추가하지 않았다.
