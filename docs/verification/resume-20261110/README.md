## 다음 실제 환경 확인 순서

아래는 준비된 체크리스트이며 아직 통과 결과가 아니다. 자동 검증의 합성 권한·조합 이벤트로 대체하지 않는다.

1. 위 로그인 주소에서 사용자가 직접 로그인한다. 소셜 로그인이라면 callback 이후 원래 작업 공간으로 돌아오는지 확인한다. 비밀번호·인증 코드·세션 쿠키는 기록하지 않는다.
2. 입력창에서 한글 조합 중 Enter와 Shift+Enter를 실제 키보드로 확인한다. 모델 호출을 추가하지 않도록 전송 버튼을 누르지 않고 초안으로 확인한다.
3. 자료 연결에서 폴더 선택을 한 번 취소한 뒤 기존 합성 테스트 폴더 `.taste-skill/s0-fixtures/source-a`를 선택한다. 이 폴더의 존재와 준비된 파일2개를 확인했으며 개인 폴더 전체를 탐색하지 않았다. Windows/브라우저의 권한 선택은 사용자가 직접 수행한다.
4. 대화에서 자료 찾기 → 조건 확인 → 원문 보기 → 대화 복귀를 확인한다. 초안과 대화가 유지되고 파일 원본이 바뀌지 않는지 확인한다.
5. 사용자가 선택한 별도 테스트 저장 폴더에서 대화 저장 → 기록함에서 재열기 → 자료 근거 열기를 확인한다. 실제 원본 이동·덮어쓰기·삭제는 이 확인 순서에 포함하지 않는다.
6. 권한 철회·다른 앱의 파일 변경·브라우저 완전 재시작은 각각 별도 관찰로 기록한다. 확인이 안 된 항목은 미검증으로 남긴다.

사용자 전체 지연·장기 사용량/메모리 관찰은 기존 [1~5 후속 보고서](../first-five/README.md)의 측정 한계를 유지한다. 새 유료 모델 호출, 운영 DB 변경, 실제 계정 삭제, 커밋·푸시·배포는 이번 재개에서 수행하지 않았다. Fallow 진단의 일괄 삭제/숨김과 새 의존성도 추가하지 않았다.
