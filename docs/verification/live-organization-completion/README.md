# 정식 AI 정리 1~10 진행 결과

2026-11-08. 사용자가 앞서 나열한 열 가지 작업의 진행을 승인했다. **1~9 구현과 자동 검증은 완료했으며, 10의 실제 Windows 전체 사용자 여정은 일부 남아 있다.** 이전 문서의 'AI 적용 미연결'은 당시 상태다. 개인 자료 자동 전송/배포/커밋은 하지 않았다.

| 작업 | 결과/근거 |
| --- | --- |
| 1 날짜 의미 질문 | 발췌의 실제 날짜/라벨/근거로 후보 구성. 없는 생성일을 추가하지 않음 |
| 2 혼합 자료 마지막 확인 | 문서별 질문을 묶고 보류 문서 누락/가짜 ID/질문 중복 거부 |
| 3 답변 반영 | 날짜/목적지/이번 제외 답을 명시 전송에 포함. 수정 시 제안/동의 폐기, 자동 재전송 없음. 확인한 답도 편집 가능 |
| 4 범위/기준/목적지 분리 | 이미 알려진 폴더와 명확한 표현만 추론. 모호하면 미정, UI 명시 선택·해제 우선 |
| 5 실제 참고 구조 | 깊이3/80방문/200대기/5초/16KiB 이내 디렉터리 메타데이터. 부분 여부 표시·전송 전 동일 구조 재검사 |
| 6 최종 검토 | 사용자가 copy/move 선택 후 출발 부모/목적지별로 기존 ManagedFilesDialog에 연결 |
| 7 원본/권한/충돌 검사 | 제안 당시 파일 hash/크기/mtime과 현재 managed 검사 결과 대조. 변경 시 모든 옛 묶음 차단 |
| 8 실행/보존/복구 | 기존 session/managed 엔진과 vault/journal/복구 재사용. AI만의 파일 writer 없음. 묶음별 명시 실행·실패 결과 유지 |
| 9 전체 해제 | 전체 해제는 선택 도구 유지, 마지막 개별 해제는 종료. 별도 선택 모드 종료 제공 |
| 10 실제 환경 | 실제 DB 경합1검사와 실제 Google 합성 호출2회 통과. 로그인/테스트 폴더/보관함 연결은 사용자 보고. 실제 Windows 보관함 생성·식별 형식은 읽기 전용으로 확인. 실 Windows 파일 작업·복구/물리 IME와 인증된 UI→공급자 전체 여정은 미완료 |

새 목적지는 공통 picker/생성 폼에서 사용자가 명시적으로 만든다. AI 응답만으로 폴더 생성/실행을 하지 않는다. F5는 초안·동의·제안을 초기화하고 디스크 작업 기록은 기존 조회/복구로 확인한다. 서버는 브라우저의 로컬 파일 소유나 전체 hash를 증명하지 못하며 OS 외부 쓰기와 원자적 잠금을 제공하지 않는다.

## 실행한 검증

- 전체 **995검사/102파일**, `pnpm typecheck`, `pnpm lint`, `pnpm build` 통과. 서버 경계21, 기능 경계25web/6domain/3layout 통과. 최종 빌드 `A8UUyGVs7Odfss2_iK1gR`.
- [완성 흐름24](browser-checks.json): 실제 Provider/session/Worker/OPFS/managed/vault/복구 + 대체 owner/권한/공급자/Next 라우팅. 질문/답 수정/새 동의, 자연어 조건, 참고 구조, 원본 copy/move/보존/복구, 같은 크기 변경 후 쓰기0/옛 묶음 전체 차단, 선택 모드, 외부 요청0/예외0.
- 기존 [전송 회귀23](transfer-regression/browser-checks.json) 및 [로컬 준비 회귀28](preparation-regression/browser-checks.json) 통과. 이전 전송 검사의 즉시 좌표 클릭은 스크롤/초점 frame 이후 hit target을 확인하도록 보완했다. 실패 시도 원자료는 별도 보존하고 최종 결과와 구별한다.
- 사용자 신고의 빈 폴더 레이아웃은 [별도 실패→수정→25검사](../folder-workspace-height/README.md)로 검증했다. 공통 높이 연결과 오래된 반응형 열 설정 수정이며 파일 처리와 별개다.
- 실제 DB: 명시 opt-in `tests/database/vitest.sample-ai.config.mts` **1검사 통과**, 원자 예약/중복/한도/경합 확인. 테스트 키만 정리하고 실제 사용량을 초기화/우회하지 않았다. 기본 sandbox의 연결 실패 뒤 승인된 네트워크 실행으로 확인했다.
- 실제 Google `gemini-3.5-flash-lite`: 합성2문서, 합성 인증 guard + 실제 DB 예약 + countTokens/generation **2회**. [최초](provider-initial.json) 날짜/혼합 질문2개, 입력1201/출력225토큰. [명시 답변 후](provider-answer.json) 보류/질문0·제안2개, 입력1257/출력227토큰. 인증 사용자의 HTTP 전체 여정과 구별한다. 초기 CA 경로 설정 실패는 공급자 호출 전이며 [원자료](provider-setup-failure.json) 보존. 청구 금액은 확인하지 않았다. 자동 재시도/모델 교체/쿼터 환불 없음.
- 최종 파서로 저장된 실제 응답2개 [재생 통과](provider-replay.json). 추가 DB 예약·모델 호출0회. 재생 명령은 `MOA_RUN_LIVE_REVIEW_CHECKS=1`, `MOA_LIVE_REVIEW_PHASE=replay`로 `pnpm exec vitest run --config tests/database/vitest.live-review.config.mts`.

## 실제 Windows 확인의 현재 위치

사용자가 “로그인하고 테스트 폴더를 연결했어”라고 보고했고 `source > 참고`의 실제 화면을 제공했다. 준비된 `.omx/manual-organization-test/source`만 대상으로 진행한다. 실제 로그인 재요청은 필요 없다. 현재3034 dev 서버는 사용자 확인용으로 유지한다. 다음 세션에는 서버 생존을 새로 확인한다.

브라우저 host는 이용 불가였고 개인 Chrome 창 연결은 자동 승인 검토가 작업 무관 탭 노출 우려로 거부했다. 사용자의 로그인 후 작업 전용 Chrome 창 연결도 Windows의 현재 URL을 검증할 수 없다는 도구 제한으로 중단했다. 사용자 창을 CDP/쿠키 추출로 우회하지 않았다. 로그인/네이티브 권한/물리 IME를 자동 검사로 통과 처리하지 않는다.

남은 순서는 `.omx/manual-organization-test/README.md`의 보관함 연결 → 실제 한글 조합/줄바꿈 → 발췌 확인·초기 명시 전송 → 질문 답변·새 동의/전송 → 복사/보존 이동/복구다. 각 단계의 실제 결과를 확인한 뒤 10을 완료 처리한다. 별도 사용자 조작이 필요한 지점만 요청한다.

### 다음 작업 재개 시 확인

서버의 `/api/health`는 다시200으로 확인했다. 새 서버 시작 시 포트 사용 중 오류가 발생해 기존 서버를 그대로 사용했다. 브라우저 도구의 새 상태 조회에서도 연결 host를 이용할 수 없었다. 개인 창 접근이나 기존 제한을 우회하지 않았다.

사용자에게 `/settings?tab=folders`에서 준비된 `vault-parent`에 새 보관함을 생성하고 권한창을 직접 허용하도록 요청했다. 로그인·자료 연결 완료 보고를 반복 요청하지 않았다. 실제 디스크의 합성 문서2개를 읽기 전용으로 확인하고 [기준 해시](manual-summary.md)와 [현재 관측](manual-summary.md)을 기록했다. 이는 브라우저의 권한·실행 완료를 증명하지 않는다. 기준 기록용 첫 PowerShell 진단의 경로 API 호환 오류는 경로 접두 확인 후 상대 경로를 구하는 방식으로 바로잡았고, 파일2개가 있는 올바른 기록으로 교체했다. 제품 코드/원본 쓰기/추가 모델 요청은 없다.

사용자가 “연결했어 위치 식별 확인됨도 된것 같은데”라고 답했다. 지정된 테스트 위치에서 새 보관함 하나와 식별 파일을 확인하고 제품의 `parseVaultIdentity()`로 실제 파일의 형식을 검증했다. [보관함 확인](manual-summary.md)에 생성 시각/형식 통과/원본2개 해시·크기 불변을 기록했다. 계정 식별값을 보고서에 복사하지 않았다. 현재 브라우저의 소유자·권한 상태를 직접 관측한 것으로 확대하지 않는다. 이어 실제 한글 조합 중 Enter/Shift+Enter와 로컬 자료 준비를 요청했고 응답을 기다린다. 이 단계의 새 AI 요청과 제품을 통한 원본 쓰기는0회다.

구현 읽기 순서: [설명](../../reports/live-organization-completion-reading.md) → shared review → preparation controller → session → operation projection → execution controller → 기존 managed 엔진. 독립 에이전트 검토는 설치 역할 모델 미지원으로 실행되지 않았으며 직접 검토/검증했다.

### 사용자 첫 AI 결과와 화면 개편 피드백

사용자는 두 자료가 준비 목록에 보이고 AI 제안을 기다린다고 보고한 뒤, 일치0개/확인 필요2개와 실제 날짜·혼합 이유를 전달했다. [사용자 보고 원자료](manual-summary.md)에 기록했다. 제한된 서버 로그에는 처리되지 않은 오류/인증서 오류가 보이지 않았으나 HTTP200을 모델 결과 성공의 독립 근거로 삼지 않는다. 물리 한글 입력 결과는 아직 명시적으로 확인되지 않았다.

이어 사용자는 정보량·토큰·스크롤·정리 모습 부재·오른쪽 창 중심 구조를 지적하며 전면 개편을 요청했다. 이후 답변 재전송 안내는 지금 수행하지 않아도 된다고 알리고, [대화 중심 개편 시안](../chat-first-design/README.md)을 우선했다. 기존 질문/답변 기능 검증과 사용성 개선을 구별하며, 실제 응답 후 파일 실행·복구는 미완료로 유지한다.
