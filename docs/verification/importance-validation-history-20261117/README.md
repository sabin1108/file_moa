## 확인한 원인과 한계

같은 중요도 요청과 개인정보 없는 합성 문서7개를 기존 실제 OpenAI 공급자(`gpt-6-luna`)에 보냈다. 첫 생성은 완료 응답의 텍스트 JSON을 읽는 단계에서 실패했다. 이 실행의 원시 응답과 사용량은 수집하지 못했으므로 잘못된 JSON의 구체적 바이트/원인은 미확정이다. 두 번째 생성은 형식/근거 검사를 통과했지만 중요도 기준이 없다는 이유로 전부 보류했다. 기존 정책은 일반 주제/날짜 정리 규칙이 중심이었고 등급별 기본 기준과 전용 출력 계약이 없었다.

개인 폴더 원문을 외부로 재전송하지 않았으므로 운영 실패와 합성 재현이 완전히 같은 응답이라는 주장은 하지 않는다. 사용자 지정 폴더의 읽기/크기/UTF-8만 로컬에서 확인했으며 원문을 기록하지 않았다. 폴더 연결 오류와 응답 검증 오류는 다른 단계다.

[OpenAI 구조화 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs)의 출력 계약과 오류 처리 설명을 확인했다. 형식 제약과 별도로 실제 문서 ID·인용·날짜·목적지를 검사하는 기존 경계를 유지했다.

## 변경과 읽을 순서

1. `shared/organization.ts`: 명시된 중요도 상·중·하만의 요청에 기존 목적지 세 등급/날짜 없음 계약을 적용한다. 부정 요청이나 날짜/주제 조합, 사용자 개별 답변에는 전용 제약을 강제하지 않는다.
2. `server/organization/organization-generation.ts`: 상=보안·개인정보·원본 보호·필수 동작, 중=신뢰성·성능·사용성·일반 구현, 하=선택 개선·장식·후속 기능이라는 기본 기준을 제안한다. 주관적 제안이며 개별 등급 미지정만으로 전부 보류하지 않도록 한다. 출력은 세 경로 enum과 null 날짜로 제한하고 인용은 계속 해당 원문의 정확한 문구여야 한다.
3. AI 어댑터/묶음 검증/공통 안내: JSON, 인용, 날짜, 계획 경로·자료, 확인 답변 충돌을 구별한다. 운영 로그에는 안전한 오류 코드만 추가한다. 원문·사용자 경로·공급자 응답을 로그에 추가하지 않는다. 형식 검사를 우회하거나 자동 재시도하지 않는다.
4. `ConversationWorkspace`/CSS/`LiveConversation`: 이전 메시지 접기를 제거하고 모든 발언을 같은 스크롤 면에 표시한다. ‘나’와 ‘모아’의 이름·배경·테두리·간격을 나누고 과거 정리 질문의 조작은 반복하지 않는다. 완료 내용 갱신이 위에서 읽는 위치를 바꾸지 않게 했다.
