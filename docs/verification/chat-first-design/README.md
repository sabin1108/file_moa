# 대화 중심 자료 정리 개편 시안

후속: 사용자 방향 확인 뒤 [정식 채팅과 공통 비교를 실제 연결했다](../chat-first-live/README.md). 아래는 연결 전 시안 작성·검토 기록이다.

2026-11-08. 실제 사용 중 사용자는 정보량, 토큰/기술 설명, 긴 스크롤, 정리될 모습의 부재와 오른쪽 창이 주가 된 구조를 지적했다. 기능 검증 통과를 좋은 사용 경험의 근거로 삼지 않고 흐름부터 다시 설계했다.

시안: `http://127.0.0.1:3034/preview/screens/chat-first`. 기본은 폴더 비교이며 ‘처음부터 보기’로 자료 확인→묶음 질문→변경 구조→실행 검토를 볼 수 있다. 기존 로그인된 브라우저에서 연다. 이 단위는 실제 채팅 교체/AI 요청/파일 실행을 구현한 것이 아니다.

## 결정과 책임

- [DESIGN.md](../../../DESIGN.md)의 최신 개편 절과 [CF-001~010](../../specs/chat-first-organization.md)이 기준이다. 시안의 상태는 Draft이며 사용자 사용성 검토 전이다.
- `LiveConversation`의 제출 때 자료 창 자동 열기와 `OrganizationPreparationPanel`의 긴 세로 조합을 원인으로 확인했다. 대화는 텍스트 상태 안내, 실제 질문/결정은 보조 창이라는 책임 배치를 개편한다.
- 대화 안에 필요한 질문과 자료/기준 요약, 현재/도착 폴더 구조와 다음 행동을 둔다. 자료 창은 선택적 원문 확인으로 제한한다. 토큰/해시는 상세로 옮기되 전송 대상·보내는 내용·외부 서비스·명시 동의·원본 검사는 보존한다.
- 같은 합성 두 파일을 모든 상태에서 재사용한다. 날짜와 분리 선택이 예시 경로에 반영된다. 복사는 원본과 새 사본을, 이동은 도착 구조를 보여 준다. 예시 경로는 실제 AI 결과가 아니다.
- 실제 전환에서는 기존 preparation/execution controller와 공통 picker/managed/복구를 재사용한다. 자연어 답변 연결과 기능 실패 검증은 후속이다. 이 시안은 선택지의 표시/비교만 제공하고 임의 채팅을 해석하지 않는다.

## 스타일과 검토

새 방향을 추첨하지 않고 기존 `achromatic-ledger`, seed2044201404, 팔레트/한국어 서체를 유지했다. 제품 고유 요소는 두 파일의 현재/도착 구조와 그 옆의 결정이다. 공통 메뉴·MoaMark/Icon·actionClasses·CSS 변수를 재사용하고 새 의존성은 추가하지 않았다.

첫 캡처에서 모바일의 조작이 비교 아래로 밀리고 제목에 자동 초점 테두리가 생기는 점을 확인했다. 조작을 비교 위로 옮기고 중복 기준 설명을 줄였으며 모바일은 현재/도착 구조 전환으로 바꿨다. 기존240px 메뉴와 새 grid의 너비도 맞춰 겹침을 없앴다. 중첩 폴더와 현재 두 파일의 행 수가 다른 비교는 데이터 구조 자체의 차이이며 장식 정보로 채우지 않았다.

## 재현과 읽기 순서

1. `node tests/browser/serve-chat-first-design.mjs`가 출력한 격리된 로컬 주소를 사용한다.
2. `node tests/browser/capture-chat-first-design.mjs <주소>`로24개 화면을 기록한다.
3. `node tests/browser/inspect-chat-first-design.mjs --app <주소> --widths 1440,768,390 --out <새 결과 폴더>`로 설치된 앱 검사 진입점을 실행한다.

읽기 순서: `prototypes/organization/chat-first-data.ts` → `ChatFirstPrototype.tsx` → `chat-first.module.css` → preview 화면 등록. 실제 소스/서버의 동의·쓰기 경계를 수정하지 않았다.
