# 로컬 이메일·소셜 로그인 시작 실패 복구

최신 재발과 복구: [2026-11-09 개발 서버 실행 권한·세션 API 확인](runtime-permission-20261109.md). 아래의 예전 서버 세션 번호보다 최신 보고서를 우선한다. 화면이 보여도 세션 API를 확인해야 한다.

2026-11-09. 사용자가 로컬에서 이메일과 소셜 로그인이 모두 실패한다고 보고했다. 현재 기준 주소는 `http://127.0.0.1:3034/login`이다.

## 원인과 복구

로그인 화면과 서버 health는 정상이었지만, 인증 요청마다 `Authentication operation failed`가 발생했다. 작업자가 띄운 개발 서버가 네트워크 제한이 있는 실행 환경에 있어 인증 DB 접속이 `EACCES`로 거부됐다. 이메일/소셜 로그인 모두 기존 DB 기반 요청 제한과 인증 상태를 사용하므로 공통으로 실패했다.

실제 앱의 `databasePoolConfig`·CA·runtime 역할을 사용한 `BEGIN READ ONLY` → `SELECT 1` → `ROLLBACK` 검사 결과는 다음과 같다. DB URL·비밀번호·호스트·계정 정보·원본 오류는 출력하지 않았다.

| 실행 환경 | 결과 |
|---|---|
| 기존 서버와 같은 제한 환경 | EACCES,29ms |
| 네트워크가 허용된 환경 | SELECT1 통과,2,056ms |

작업자가 실행한 기존3034 서버58698만 정상 종료하고, 같은 프로젝트·설정·주소의 `pnpm dev`를 네트워크가 허용된 환경에서 다시 실행했다. 현재 서버 세션은27380이다. 인증 코드·DB 권한·Origin/CSRF·TLS·요청 한도·비밀값을 변경하거나 보호를 끄지 않았다. Next가 생성한 dev 타입 참조를 그대로 유지한다.

## 실제 인증 경계 확인

[관측 요약](auth-observations.json)은 실제 로컬 서버 HTTP 응답에서 확인한 최소 필드다. 사용자 비밀번호나 실제 계정 cookie를 사용하지 않았다.

| 요청 | 결과 | 확인 범위 |
|---|---|---|
| 합성 `.invalid` 이메일·가상 비밀번호 | HTTP401,INVALID_EMAIL_OR_PASSWORD | 서버 장애가 아닌 정상 자격 증명 거부. 실제 사용자 로그인 성공 증거는 아님 |
| Google signin 시작 | HTTP200,accounts.google.com,정확한 로컬 callback,state cookie 발급 | 로그인 시작 단계만. 제공사 화면과 실제 계정 인증은 미실행 |
| 네이버 signin 시작 | HTTP200,nid.naver.com,정확한 로컬 callback,state cookie 발급 | 로그인 시작 단계만. 제공사 화면과 실제 계정 인증은 미실행 |

일반 계정을 만들거나 개인 사용자 정보를 조회하지 않았다. 인증 시작 검증은 기존 요청 제한 카운터와 만료되는 OAuth 임시 state를 생성하므로 전체 검사를 read-only라고 부르지 않는다. 실제 외부 소셜 인증·이메일 발송·유료 모델 호출은 하지 않았다.

같은 [개발 모드 안정성 회귀](login-stability.json)도 다시 통과했다. 6초간 로그인 요청1회·HMR 강제 새로고침0·폼 유지6/6·브라우저 예외0이다. 앞선 HMR 반복 로딩과 이번 DB 네트워크 차단은 별도 문제였으며, 설정과 버튼 표시만으로 실제 인증 경로의 정상 동작을 판정해서는 안 된다.

제품 소스 변경이 없어 전체 단위·타입·린트·빌드를 반복하지 않았다. 실제 계정의 로그인 완료·callback 복귀·세션 유지는 사용자 확인이 남았다. 소셜로만 가입한 계정에 이메일 비밀번호가 있다고 가정하지 않으며, 별도 이메일 가입 계정이 있는 경우에만 이메일 로그인 완료를 확인한다.
