# 대화로 자료 찾기·정리 — 2026-11-07

사용자 요구: 정식/테스트의 메인·채팅·파일 구성은 같게 유지하고 테스트는 가입과 자료 준비를 간소화한다. 공통 Stepper/전환을 재사용해 자연스럽게 이동하며, 제목이 아닌 내용과 요청 의도로 자료를 찾고 검토 후 정리한다. 튜토리얼은 후속이다.

현재 로컬 구현/검증은 [최종 검증 기록](../verification/conversation-organization/README.md)을 따른다. 정식 개인 파일의 AI 전송은 활성화하지 않는다.

## 이번 구현과 변경 경계

- CO-001: 동일 ConversationWorkspace/입력/메시지/자료 패널과 WorkspaceShell을 정식/샘플 메인에서 조합한다. 샘플도 대화·내 폴더 메뉴를 제공한다. 실제 폴더 Provider/인증을 샘플에 주입하지 않는다. 현재 정식 채팅은 미구현이므로 공통 표현을 연결하되 개인 자료 AI를 구현한 것으로 표시하지 않는다.
- CO-002: 공통 WorkflowTransition과 Stepper의 이동 표시를 샘플 계획·정식 복사/이동 계획에서 함께 쓴다. 입력/대화 상태를 animation 목적으로 unmount하지 않는다. reduced-motion과 키보드/초점·스크롤을 보존하며 실제 API 지연을 애니메이션으로 가리지 않는다.
- CO-003: 샘플 자료를 다수의 중첩 폴더와 30개 이상으로 늘린다. 내용에만 성능 테스트가 있는 자료, 제목만 관련 있고 내용은 다른 자료, 9/10/11월 보고서, 본문 날짜/파일명 충돌, 빈 내용·애매한 자료를 포함한다. 실제 PDF/XLSX 자산/검증 발췌는 유지한다.
- CO-004: 자연어 요청과 동의한 후보 범위만 1회 모델 요청으로 분석한다. 서버 등록부에서 내용을 구성하고 요청·ID·토큰·Origin·세션·원자 한도를 검증한다. 사용자 본문/경로/handle/키를 샘플 API가 받지 않는다. 결과는 선택한 문서 ID 부분집합과 본문 인용, 목적지, 날짜 근거, 보류 설명이다.
- CO-005: 인용은 해당 문서 내용의 실제 부분 문자열이어야 한다. 자료 밖 ID/중복/없는 인용/경로 탈출·실행문·없는 날짜는 거부한다. 날짜/월이 모호하면 보류/추가 질문을 표시한다. 제목만으로 내용 일치를 확정하지 않는다. 모델의 의미 판단 정확도는 별도 실제 평가로 확인한다.
- CO-006: 새 날짜/주제 폴더도 가상 작업 공간에만 추가하고 기존 변경 계획 검토/목적지 수정/충돌/명시 적용/되돌리기를 재사용한다. 무관한 자료는 이동하지 않는다. AI 결과를 받은 즉시 쓰지 않는다. 취소/새요청/만료/초기화 뒤 늦은 응답은 버리고 새로고침은 API/쓰기를 재실행하지 않는다.
- CO-007: 무료 API 대응은 버전 관리하는 정리 지침·작은 발췌/후보·토큰 계산·평가 fixture로 시작한다. 파인튜닝/새 SDK/모델 도구/유료 fallback은 추가하지 않는다. 계정별 무료 사용량과 정확도를 보장하지 않는다.
- CO-008: 목적지의 ISO 날짜는 선언 날짜와 같고 본문에서 유일하게 확인되어야 한다. date:null로 날짜 폴더를 만들 수 없다. 복원된 폴더 ID/라벨 충돌을 거부하며 승인 대상이 참조하는 신규 폴더만 커밋하고 되돌림을 대화에도 표시한다.
- CO-009: 요청별 평가셋은 범위, 기대 일치/보류/제외 ID, 인용 예시, 날짜, 명시 목적지, 금지 결과를 기록한다. 공개 84개 자료의 development와 기존 8개 유보 문서의 holdout을 분리하고 본문·파일명·출처 경로 해시로 버전을 고정한다. 후보 누락과 최종 응답 오판을 분리해 평가하며 기대 응답 자체의 통과를 모델 정확도로 보고하지 않는다. 합성 기대값은 사람 검토 전 초안으로 표시한다.
- CO-010: 기간 필터와 날짜별 폴더 정리는 별도 의도다. 날짜 관련 단어만으로 정리를 요청했다고 단정하지 않으며 부정문을 존중한다. 예: ‘10월 자료를 모으되 날짜별 정리는 하지 마’는 기간만 제한하고 주제 폴더/date:null을 사용한다. 새 지침과 실제 응답은 버전·본문/프롬프트 해시·입출력 토큰·지연·호출 수와 함께 평가한다. 실패 후 자동 재시도나 한도 우회는 하지 않는다.
- CO-011: 일상 요청 평가는 회사·학습·연구·개발·개인 일정·수치·기간·선택 범위·보류/결과 없음·안전으로 나누어 지원 범위와 실패 기준을 만든다. 예시 두 개의 통과를 전체 품질로 보고하지 않는다. 지원하지 않는 중복 삭제·최종본 판정·상대 날짜·개인정보 가림·OCR·허용 범위 밖 탐색 후보는 실행 완료 사례나 실제 모델 품질 분모에 넣지 않는다. 후보의 선정 근거·그룹·개발/유보·실제 호출된 부분집합을 기록한다.
- CO-012: 날짜가 없어 확인이 필요한 문서와 요청 기간 밖임이 본문 날짜로 확정된 문서를 구별한다. 후자는 보류하지 않고 제외한다. 실제 파일 작업 전의 요약은 검토할 제안임을 표시하며 정리 완료를 주장하지 않는다. 지침 v4의 실제 실패→수정과 표현 변형 평가는 [검토 기록](../verification/expectation-review/README.md), 정식 사용자 확인 흐름은 [LT 명세](live-txt-md-consent.md)를 따른다.

## 작업 순서와 검증

1. 기존 공유 계획/샘플 상태 회귀를 유지하고, 의도/인용/날짜/가상 목적지의 실패 테스트와 기대 fixture를 작성한다.
2. 서버의 공통 Gemini 전송/사용량/한도 경계는 두 실제 소비처에서 재사용한다. 새 조직 결과 검증과 샘플 상태 전이에 연결한다.
3. 공통 대화 표시·입력, 폴더 탐색, 전환을 정식/샘플 진입에 연결한다. 새 의존성 없이 현행 디자인/토큰을 유지한다.
4. 단위·타입·lint·경계·빌드, 브라우저 4폭/키보드/합성IME/취소/복원/reduced-motion/폴더·정식 접근 보호, 한도 내 실제 두 예제와 내용 인용을 확인한다. 실모델 검사는 mock/fixture 성공과 구분하고 자료 수·호출 수·품질 한계를 기록한다.
