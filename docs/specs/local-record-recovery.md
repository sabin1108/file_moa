# S0 중단 저장 복구 계약

2026-10-25. 대상은 전용 AI 기록의 단일 record 디렉터리다. 개인 원본 자료나 전체 폴더 정리는 대상이 아니다.

## 복구 방식

복구는 손상된 폴더를 수정하지 않고, 확인된 정상 버전들을 사용자가 선택한 별도 위치의 새 하위 폴더에 복사한다. 기존 파일 삭제·덮어쓰기·손상된 metadata 임의 재구성은 하지 않는다. 성공 후에만 새 폴더를 연결할 수 있으며 중간 실패 폴더는 자동으로 활성화하지 않는다.

미리보기에서 정상 최신 버전, 정상 이력 수, 비어 있는 metadata와 고아 MD를 표시한다. 0 byte JSON은 정상 JSON을 읽는 데서만 제외한다. 다른 정상 버전이 해당 revision을 부모로 참조하면 복구를 거부한다. 비어 있지 않은 잘못된 JSON, 본문 hash 변조, 버전 분기, 누락된 부모는 추측으로 건너뛰지 않고 실패한다. 정상 버전이 하나도 없으면 복구할 수 없다.

미리보기는 원본의 MD/JSON 파일명·원시 바이트 hash를 포함한 fingerprint에 연결된다. 실행 직전과 복사 후 fingerprint를 재확인하고 바뀌면 성공으로 표시하지 않는다. 같은 origin의 저장·복구는 동일 Web Lock으로 직렬화한다. 외부 프로그램의 검사 사이 변경을 완전히 차단하는 파일 시스템 트랜잭션은 아니다.

복구 폴더는 source와 겹치지 않는 대상 아래 새 UUID 이름으로 만든다. 정상 metadata/body만 복사하고 다시 loadLatest로 검증한다. 미완료·고아 파일은 원래 폴더에 그대로 남긴다. 복구 정보는 .txt로 남기며 기존 JSON 스키마를 오염시키지 않는다. API의 마지막 성공 반환 전에는 새 연결을 저장하지 않는다.

S0 한도: 원본 디렉터리 항목 500개, 게시 버전 100개, MD 2MiB, JSON 16KiB, MD/JSON 합계 50MiB. 미리보기는 파일 내용을 서버로 보내지 않는다.

## 수용 사례

1. r1 정상 + r2.md + 빈 r2.json → r1 미리보기 → 새 복구 폴더 → r3 수정 저장. 기존 폴더의 모든 파일·hash 동일.
2. 고아 MD는 기록이 아닌 미완료 파일로 표시하고 원래 위치에 보존.
3. 잘못된 비어 있지 않은 JSON / 변조 본문 / 분기 / 부모 누락 → 복구 실패, 새 활성 연결 없음.
4. 미리보기 후 원본 변화 → stale-recovery-preview, 복사 시작 안 함.
5. 복사 중 원본 변화 / 대상 권한·용량·close 실패 → 성공 반환 없음, 원본 그대로, 부분 대상 자동 연결 없음.
6. 복구가 실패해도 정상 원본 버전을 지우지 않고, 다시 미리보기부터 시도 가능.
7. source와 같거나 상하위로 겹치는 destination → 쓰기 시작 전 거부.

이 계약은 자동 수선 기능이 아니라 명시적인 새 폴더 복구다. 제품 UI와 계정 격리 연결은 후속이다.
