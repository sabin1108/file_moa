# 샘플 작업 공간

작성일: 2026-11-07. 상태: 로컬 production 빌드에서 진입·샘플 보관·Gemini/준비 제안·검토·적용/되돌리기·초기화와 PDF/XLSX 미리보기 연결. 운영 배포·정식 개인 파일 AI·일반 PDF/XLSX 파싱은 후속이다. [최신 연결 검증](../verification/sample-gemini/README.md).

## 진입과 세션 — SAMPLE-001

- `/demo`에서 유효한 샘플 세션을 확인하고, 없으면 `/demo/start`에서 샘플 쿠키를 발급한다. 실제 가입·로그인이나 운영 User/Workspace 생성은 하지 않는다.
- 별도 `moa.sample-session` 쿠키는 HttpOnly·SameSite=Lax·Path=/demo, HTTPS에서는 Secure다. 기존 서버 키로 `moa-sample-v1` 목적을 구분해 HMAC 서명하며 실제 인증 쿠키를 대체하지 않는다.
- 세션은 1시간이다. 서버 노드 간 시계 오차는 미래 범위 검사에서 최대 60초를 허용하고 만료한 세션은 거부한다. 브라우저의 만료 안내는 서버가 계산한 남은 시간과 단조 시계를 사용해 장치의 날짜/시간 설정에 의존하지 않는다. 실제 자료 제공은 서버가 다시 확인한다.
- 진입 완료는 상대 주소 `/demo`로 이동한다. 내부 서버 hostname을 사용해 브라우저 origin을 바꾸지 않는다. 서명 설정이 없으면 짧은 503 안내로 닫힌다.

## 자료와 보관 — SAMPLE-002

- 공개 후보 10개만 앱의 독립 카탈로그로 옮긴다. 평가용 holdout·정답 메타데이터는 앱 카탈로그나 모델 입력으로 가져오지 않는다.
- 서버의 샘플 세션과 탭별 `sessionStorage`의 `moa.sample.v1.<session-id>` 공간을 사용한다. 서버에는 방문자별 변경 자료를 저장하지 않으며 같은 브라우저의 쿠키를 공유하는 탭도 변경 상태는 따로 보관한다.
- 정식 `SourceFolderProvider`·IndexedDB·로컬 폴더 핸들·계정/작업 공간 소유권과 연결하지 않는다. 샘플은 원본 다운로드 파일이 아니라 브라우저의 가상 폴더 위치를 변경한다.
- 세션 만료 뒤 새 진입은 새 ID의 샘플 공간을 사용한다. 이전 탭 보관 값은 새 세션으로 이관하지 않으며 탭 종료 때 브라우저의 임시 보관 수명을 따른다. 초기화는 현재 샘플 기록만 덮어쓴다.
- 보관 불가/잘못된 기록은 안내하고 메모리에서 계속 체험한다. 상태를 읽었다는 이유로 이동·복구·외부 호출을 재실행하지 않는다.

## 제안·목적지·계획 — SAMPLE-003

- 준비된 제안과 실제 Gemini 요청을 별도 버튼으로 구분한다. 실제 요청은 선택된 가상 샘플 전송 동의 뒤에만 가능하며 AIC-009~012의 서버 권한·원자 한도·취소 계약을 따른다. [공통 분류 계약](ai-classification.md)의 입력/결과 검증은 서버와 화면이 함께 쓰는 `src/shared/ai-classification.ts`에 있다.
- 자료 선택 → 준비 제안 또는 동의 후 Gemini 제안 → 문서별 목적지 수정 → 계획 검토 → 명시적 적용 순서다. 목적지가 정해지지 않은 자료는 사용자가 선택하기 전까지 적용하지 않는다. 실제 제안의 이유·검토 필요·모델·사용량도 탭에 보관한다.
- 빠른 목적지 선택과 기존 `DestinationFolderPicker`·`DestinationPathForm`·`DestinationPickerController`의 경로/하위 폴더/상위/최상위/취소 흐름을 재사용한다. 읽기 콜백만 샘플 카탈로그의 폴더 목록으로 공급한다.
- 목적지 탐색을 여는 동안 기존 계획의 적용을 막는다. 폴더를 확정하거나 탐색을 취소한 뒤에만 현재 목적지의 계획을 적용한다.
- 샘플 목적지는 등록된 회의·재무·개발·학습·생활·여행 폴더로 한정한다. 임의 생성으로 허용 집합을 바꾸지 않으므로 기존 picker의 `allowCreation=false`를 사용한다. 중간/최상위 폴더는 탐색할 수 있지만 목적지로 확정하지 않는다.
- `buildFileChangePlan`·`FileChangePlanView`로 전후 경로와 이름 충돌을 확인한다. 여러 출발 위치의 중복 도착도 함께 검사한다. 실제 파일 작업의 검토/복구 흐름을 제거하거나 새 가짜 운영 결과로 바꾸지 않는다.

## 적용과 복구 — SAMPLE-004

- 명시적 적용은 샘플 위치 맵만 변경한다. 확인된 계획·문서별 변경 전/후를 보관한다. 같은 적용을 다시 실행하거나 충돌 있는 계획을 적용하지 않는다.
- 되돌리기는 마지막 샘플 정리 1건의 위치를 복원한다. 운영 파일 journal/백업 복구나 여러 단계의 영구 작업 이력을 구현한 것으로 보고하지 않는다.
- 보관된 복구 기록은 문서 ID 집합, 허용 폴더, 현재 상태와 after 일치, 실제 변경 ID 집합과 기록된 대상 수를 검증한다. 상태 복원이 임의 위치나 거짓 대상 수를 만들지 않도록 한다.
- 처음부터 다시는 샘플 위치·선택·계획·마지막 복구와 미리보기를 처음으로 돌린다.

## 만료·새로고침·접근성 — SAMPLE-005

- 새로고침은 검토 중/적용 후 상태를 되살리며 적용을 반복하지 않는다. 탭 저장소 읽기/쓰기 실패는 별도 안내한다.
- 남은 시간이 지나면 변경 버튼을 막고 새 세션 진입을 제공한다. 서버 자료 경로는 쿠키를 독립 검증한다. 클라이언트의 가상 위치 편집 자체를 서버 운영 자료 권한으로 취급하지 않는다.
- 공통 Stepper를 쓰고 단계 전환·문서 열기·목적지 선택/취소 후 초점을 연결한다. 경로 입력의 기존 IME 조합 중 Enter 차단을 유지한다. 실제 물리 IME는 자동 검증과 구분한다.
- 기존 `WorkspaceShell`에 표시용 sample 모드를 추가했다. 기본 live 모드의 메뉴·프레임과 실제 인증 guard는 유지한다. 표시 prop은 권한이 아니다.

## PDF·엑셀 — SAMPLE-006

- 서버는 샘플 쿠키를 확인한 뒤 `/demo/assets/<등록-id>`만 제공한다. 알 수 없는 ID·잘못된/만료된 쿠키는 거부한다. 파일과 미리보기는 no-store·nosniff로 제공한다.
- PDF 원본 다운로드와 준비된 두 페이지의 이미지 미리보기를 제공한다. 모든 페이지는 확인한 PDF에 연결된 별도 SHA-256 자료로 잠근다. 작은 화면에는 분류에 사용한 텍스트 발췌도 제공한다. 이는 사진 분류나 일반 PDF 렌더러 지원이 아니다.
- 엑셀은 확인한 셀 표와 실제 XLSX 다운로드를 제공한다. 읽기 검증 스크립트로 시트의 표시 값·수식·합계를 앱 미리보기와 대조한다. 일반 XLS/XLSM·매크로·임의 업로드는 지원하지 않는다.

## 검증과 남은 단계

실행 증거는 [검증 보고서](../verification/sample-workspace/README.md), 데이터 출처/기대값 상태는 [자료 안내](../../tests/fixtures/classification/README.md)를 따른다. 정식용 TXT·MD 제한과 개인 자료/운영 계정은 그대로다.

다음은 실제 AI의 서버 권한·전송 동의·토큰/전체 예산 예약·실패·취소·중복/늦은 응답 처리와 실제 모델 평가다. 샘플 쿠키는 `/demo` 경로 전용이므로 후속 샘플 Server Action/호출 경계도 이 수명을 유지한다. 배포 및 실제 로그인 계정과의 운영 통합 확인은 별도로 수행한다.
