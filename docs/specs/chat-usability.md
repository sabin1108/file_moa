# 첫 사용과 대화 작업의 사용성 보완

2026-11-14 사용자 피드백. 기존 색상과 저장·권한·동의·복구 계약을 유지한다.

## 이번 변경과 완료 조건

1. 비로그인 첫 진입은 `/start` 소개를 거쳐 로그인한다. 로그인 화면과 설정에서도 소개/사용법을 다시 열 수 있다.
2. 첫 대화 진입에 일반 대화·자료 찾기·자료 정리·선택 자료 질문을 먼저 보여 준다. 선택은 요청을 실행하거나 입력 초안을 지우지 않는다. 같은 표시 계약을 샘플에서도 사용한다.
3. 왼쪽 폴더 탐색과 대화의 참고 자료 선택은 서로 다른 책임임을 표시한다. 같은 폴더 트리를 양쪽에 반복하지 않는다.
4. 기록함의 저장 위치 선택은 즉시 기존 picker로 연결한다. 저장 동의·권한·현재 대화의 저장 여부는 따로 유지한다. 긴 관리 설명은 추가 설정으로 접는다.
5. 대화 설정의 기본 화면은 저장 여부와 선택적인 내 정보 사용만 보여 준다. 프로젝트/한도/내역은 고급 설정에 둔다. 기억·위키·프로필은 짧은 설명과 명확한 목록 복귀를 제공한다.
6. 포커스는 기존 입력 테두리의 색과 은은한 배경으로 표시한다. 추가 검은 외곽선과 sticky 저장 버튼의 입력창 겹침을 없앤다. 키보드/강제 색상 환경의 표시는 유지한다.
7. 처음 방문한 계정/작업 공간의 이 브라우저에만 기능 안내 완료를 보관한다. 주요 부분을 강조하는 안내는 건너뛰기·이전·다음·닫기와 설정의 다시보기를 제공한다. 자동 파일 연결/AI 전송/저장 승인은 하지 않는다.
8. 검색 조건은 검색어·날짜·범위·검색 실행 순서로 표시한다. 범위 선택과 후보 상태는 명확하게 구분하고 근거는 필요한 후보에서 펼친다. 파일 최종 수정일과 본문 기록 날짜를 지원하며, 브라우저가 제공하지 않는 OS 생성일을 추정하지 않는다.
9. 새 비밀번호는 UI·서버·인증 공급자에서8~30자로 검증한다. 기존 로그인/계정 연결 자격 확인은 과거 비밀번호로 로그인할 수 있도록 기존 입력 경계를 유지한다.
10. 메일 재요청 실패는 발송 문제임을 안내하고 내부 응답을 노출하지 않는다. 운영 로그의403과 로컬 테스트 발신 주소는 확인했으나 운영 발신 값은 비밀 설정이라 확인하지 못했다. 발신 도메인 설정과 실제 발송 재검증은 사용자 추가 지시로 제외한다.

## 명시적으로 보류

미리보기의 독립 창 전환과 브라우저 Back/Forward의 복귀 계약은 이번에 변경하지 않는다. 현재 미리보기는 로컬 controller 상태이고 브라우저 history와 같은 단위가 아니므로 별도 설계가 필요하다. 전체 작업 흐름의 재설계도 사용자가 작성할 후속 구조를 기다린다.

## 검증

비밀번호7/8/30/31자와 서버 경계, 온보딩 redirect, 선택 전 요청 없음·입력 보존, 검색 수정일 경계·본문 날짜 분리, 저장 실패/취소 보존, 안내 완료/다시보기/계정 분리부터 검사한다. UI는1440/390px·키보드·한글 입력·포커스/저장 버튼 겹침·실제 브라우저에서 확인한다. 기능 변경 후 타입·린트·전체 테스트·빌드를 실행하고 전후 성능과 추가 비용을 구분한다.
