# 자료 없는 일반 AI 대화

## 대화 도구와 기록함 표시 — 2026-11-09

기본 입력 위에는 자료 연결·저장 상태·대화 설정만 둔다. 전송 공급자는 한 줄로 표시하고 상세 정책/사용량/프로젝트 식별자는 같은 옆 패널의 설정에서 펼친다. 자료의 실제 발췌와 외부 전송 동의는 요청 시점의 기존 검사를 유지한다. 기록함은 목록·검색·새 항목을 우선하고 저장 폴더 관리를 분리한다. 원본 자료 폴더와 기록 저장 폴더를 구별한다.

옆 패널의 기록/자료/설정 및 저장 위치는 DOM과 controller를 유지해 작성 중인 대화·편집을 잃지 않는다. 제목 행을 눌러 열고 별도 관리 메뉴에서 삭제 확인한다. 삭제는 현재 연결 revision을 다시 검사하며 저장 실패 때 내용을 유지한다. 임시 대화는 명시적으로 보관을 켜기 전까지 디스크에 저장하지 않는다. [UX 검증](../verification/workspace-ux-rebuild/README.md).

## 저장한 자료 근거 복원 — 2026-11-09

완료된 자료 답변의 turn에 선택적인 `evidence`를 저장한다. owner/작업 공간, 안정적인 자료 연결 ID, 상대 경로, 전체 바이트 SHA-256·크기, 실제 인용문만 허용하고 원본 전체 발췌·핸들·권한·전송 동의를 복제하지 않는다. 기존 기록은 필드가 없어도 열린다. 일반 모델 문맥에는 자료 답변과 근거를 포함하지 않는다.

새로고침/과거 대화 열기 뒤에도 같은 `GroundedCitations`와 공통 원문 미리보기를 사용한다. 현재 owner와 선택한 연결이 일치해야 하며 다른 연결을 자동 활성화하거나 이름으로 대신 찾지 않는다. 실제 파일을 Worker에서 해시·인용문 검증하고 권한을 확인한 뒤, 재취득한 파일도 해시해 같은 크기/시각의 교체를 차단한다. 검증에 성공한 경우에만 파일 화면으로 이동한다. 질문 변경·대화 전환·owner 변경·새 근거 요청은 이전 읽기와 이동을 함께 취소한다. 모든 파일 시스템에는 검증 직후 다시 바뀔 가능성이 있으므로 원본을 잠그거나 이후 변경까지 보장한다고 표현하지 않는다.

실패 조건과 증거: `saved-evidence.test.ts`, `saved-citation-preview.test.ts`, `source-file-preview.test.ts`, `check-grounded-chat.mjs`. [1~5 후속 보고](../verification/first-five/README.md).

2026-11-09 최신 사용자 기준: 일반 질문·자료 찾기·정리를 하나의 대화와 공통 입력으로 통합했다. 아래 일반 전송 경계는 유지하며 모드별 화면 교체 설명은 이 기준으로 대체한다. [단일 대화 구현·검증](../verification/unified-conversation/README.md), [확정 계획](../planning/unified-conversation.md).

2026-11-09. [남은 작업 7번](../planning/completion-roadmap.md)을 한 검토 단위로 다룬다. 대화 기록의 영구 저장·복원은 8번이며 이번 범위에 포함하지 않는다.

## 범위와 전송 경계

- 폴더를 연결하지 않아도 기존 대화 지면과 입력창에서 질문한다. 로컬 파일·폴더 경로·발췌·선택 자료는 이 요청에 포함하지 않는다.
- 질문과 이번 화면의 완료된 앞선 대화만 표시된 AI 공급자에게 보낸다. 연결 폴더가 있더라도 일반 대화는 검색·정리·파일 작업을 실행하지 않는다.
- 같은 입력의 요청을 판별하고 애매할 때만 확인한다. 일반/자료 turn은 기록과 전송 문맥에서 구분하고 기존 조건 확인·새 동의·실행 검토를 유지한다.
- 사용자 실시간 스트림 선택을 반영해 `services/chat-stream.ts`의 같은 origin `POST /api/chat`만 직접 fetch 예외로 허용한다. 다른 제품 요청은 기존 Server Action 계약을 유지한다. 키·인증·작업 공간·사용량·공급자 원본 응답 검증은 서버 책임이다.

## 상태와 검증 한계

사용자의 실시간 스트림 선택에 따라 일반 채팅과 기존 자료 작업을 분리하고 실제 제품 경로에 연결했다. 자동 검증의 공급자·소유자는 모의 응답이다. 이후 사용자는 로컬의 이메일·소셜 로그인과 일반 채팅 송수신 성공을 확인했다. 이는 수정 후 속도 실측이나 배포 스트림 전달/취소 검증은 아니다. 질문·부분 응답은 화면 수명에만 보관하며 새로고침·경로 이탈 후 이어가기와 실제 토큰 정산 원장은 후속이다. [초기 검증](../verification/general-chat/README.md), [표시·지연 개선](../verification/chat-smoothness/README.md).

전송 입력은 질문 최대800자, 완료된 앞선 대화 최대3쌍, 합계12,000자·32KiB 이내다. 브라우저는 최근 대화 중6,000자 이내의 완성된 쌍을 고르며 서버는 role·순서·총량·예상 밖 필드를 다시 검증한다. 입력 토큰은 기존4,096개, 출력은1,600개, 답변은8,000자, 전체 SSE는1MiB로 제한한다. 공개 검사 시작 기준은500ms에서100ms로 줄이며 실제 간격에는 DB 대기가 더해진다. 각 공개 전 세션·소유권은 계속 최신 조회로 확인한다. 마지막 본문과 완료 신호는 한 번의 검사로 함께 승인한다. 빠른 공급자 실패 때도 세션이 유효하면 받은 버퍼를 미완료로 공개한다. 세션 오류·클라이언트 취소 뒤에는 새 본문을 공개하지 않는다.

최초 인증은 새 Headers로 전체 세션·작업 공간을 확인한다. 이후 생성 전·각 공개 전에는 서버에만 보관한 세션 ID/token/로그인 사용자·만료, 검증된 이메일 또는 허용 소셜 계정, 이름, 정확한 작업 공간/대표 소유자·연결 관계를 매번 확인한다. 같은 짧은 transaction에서 RLS caller를 설정하고 SELECT하며 작업 공간 생성/준비와 전체 구성원 조회를 반복하지 않는다. 새 세션 캐시나 권한 유효 기간을 추가하지 않는다.

최초 확인한 실제 session user는 서버 전용 workspace helper로 전달해 같은 쿠키 인증의 중복 조회를 피한다. 기존 외부 wrapper는 여전히 직접 인증한다. 여러 한도 예약은 같은 transaction의 parameterized multi-row UPSERT로 수행하고, 기존 순서·HMAC key·정확한 반환 집합 검증·거부 시 전체 rollback을 유지한다. 이는 SQL 왕복 절감이며 한도나 권한 재확인 계약 변경은 아니다.

공급자 소비와 공개 권한 대기는 분리한다. 공개할 본문과 완료 상태를 검사 전에 고정하며, 검사 중 받은 본문은 다음 새 검사를 받아야 한다. 동시에 공개 검사를 여러 개 시작하지 않는다. 공급자는 기존8,000자 총량 안에서 계속 읽고 권한 실패/취소는 공급자도 중단한다. 늦은 본문·완료가 검사 중 고정한 묶음에 섞이지 않게 한다.

브라우저는 승인되어 도착한 본문만 requestAnimationFrame으로 나누어 표시한다. 표시 시간은 남은 글에 따라120~650ms로 정하며 완료 신호가 도착해도 아직 보이지 않은 본문을 한꺼번에 펼치지 않는다. 원래 completed 이벤트를 잠시 보관했다가 받은 본문 표시가 끝난 뒤 한 번 확정한다. SSE 순서와 표시 길이는 별도 상태다. 중지·세션 오류는 아직 표시하지 않은 본문을 폐기한다. 접근 철회/owner 변경/이탈은 frame과 HTTP를 취소한다. 움직임 감소 설정은 즉시 표시한다. 이모지의 surrogate pair 중간을 표시하지 않는다. 공통 입력창은 안쪽 사각형 대신 바깥 둥근 focus outline을 사용한다.

요청 본문 읽기는10초, 생성은기존25초 및 세션 만료/요청 시작45초 예산 중 남은 시간으로 제한한다. Route Handler 최대 실행 설정은60초다. DB/인증 조회 자체의 즉시 취소나 배포 한도를 실측했다고 주장하지 않는다.

## 구현 전 확인한 제약

2026-11-09 공통 입력 크기: 일반 대화와 자료 찾기는 `ConversationWorkspace`의 같은 form/textarea와 `composer.module.css`를 사용한다. 자료 상호작용 영역 유무로 입력 줄 수를 바꾸지 않고 3줄을 유지한다. 검색 결과와 안내 영역은 내용에 맞춰 표시하며 입력 상자의 크기와 구분한다. 390/768/1440/1920px에서 textarea와 입력 상자 경계를 비교한다.

- 기존 `getAuthenticatedSession`은 React `cache`를 사용한다. 진행 중 재검사를 같은 요청의 캐시 조회로 대신하지 않으며, 스트림 안에서 요청 컨텍스트에 의존하는 `headers()`를 새로 호출하지 않는 인증 경계를 따로 검증한다.
- 기존 전역 한도는 1분 1회, 1시간 12회다. 채팅을 추가하며 한도를 묵시적으로 늘리거나 별도 경로로 우회하지 않는다. 제한 안내 뒤 사용자 재제출만 허용한다.
- 2026-11-09 사용자 요청으로 일반 채팅/자료 정리의 계정·작업 공간별 시간 한도를3→10회로 조정했다. 기존 카운터/요청 중복 키는 유지하며 전역 한도와 샘플 세션3회 제한은 변경하지 않는다. 예약 뒤 실패·중지 반환 없음과 거부 시 원자 rollback도 유지한다.
- 공급자 연결 중지는 HTTP 취소 요청이며 즉시 과금 종료나 최종 사용량 수신을 보장하지 않는다. 불명확한 사용량을 0으로 확정하지 않는다.
- OpenAI의 `response.output_text.delta`만 본문에 누적하며 전문인 `response.output_text.done`을 다시 더하지 않는다. `response.completed`와 정상 상태를 확인해야 완료다. Gemini는 `STOP`을 정상 종료로 구분하며 거절·토큰 제한·정상 종료 없는 EOF를 성공으로 처리하지 않는다.
- 원본 공급자의 상세 오류·응답 ID·reasoning·도구 이벤트를 브라우저로 그대로 보내지 않는다. 서버에서 검증한 최소 대화 이벤트만 전달한다.
