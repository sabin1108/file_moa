# 실제 작업 화면과 시안의 경계 — 2026-10-26

2026-10-28 현재: `/settings`와 `/files`가 실제 연결 상태를 공유하며 `/files`에서 파일·하위 폴더를 탐색하고 선택한 MD/TXT 원문을 읽는다. `/`, `/files`, `/settings`는 `app/(workspace)` 공통 layout 아래에 있다. 실제 인증·대화는 미구현이다. 수용 기준은 [연결 명세 §7](source-folder-connection.md#7-작업-화면의-연결-상태-공유--2026-10-27), [목록 UI 명세](source-folder-listing.md), [미리보기 명세](source-file-preview.md), 최신 근거는 [미리보기 포함 회귀](../verification/source-file-preview/README.md)다. 아래 과거 범위·검증·다음 작업은 당시 이력이며 현재 상태보다 우선하지 않는다.

사용자 요청: 구현된 기능을 바로 사용하고 결과에 피드백할 수 있어야 한다. 임의의 대화·파일·계정·성공 결과가 기본 화면에서 실제처럼 보이면 안 된다. 필요한 시안은 별도 보관한다.

## 이번 변경의 범위와 수용 기준

- `/`, `/files`, `/settings`, `/login`, `/welcome`는 실제 작업 경로다. 예시 대화·파일 목록·사용자 이름·파일 수·모의 로그인/성공 동작을 표시하지 않는다.
- 현재 구현된 폴더 연결은 `/settings`에 바로 표시한다. 상태는 기존 실제 controller/session/IndexedDB에서 읽는다. 시안 탭과 자료 전송 예시는 이 경로에서 제외한다.
- 채팅·파일 목록·인증·가입은 아직 구현되지 않았다. 실제 데이터가 없다는 뜻의 ‘0건’이나 ‘빈 폴더’ 대신 미구현 사실과 현재 가능한 폴더 연결 진입을 표시한다. 전송·로그인·저장 성공을 흉내내지 않는다.
- 승인된 팔레트·서체·공통 조작·채팅 입력창 배치는 유지한다. 새 테마나 장식은 추가하지 않는다. 채팅 입력과 전송은 구현 전임을 밝히고 비활성화한다.
- 기존 전체 화면 시안 5개는 `/preview/screens/{chat,files,settings,login,welcome}`로 보관하고 기존 `/preview/{scene}`은 유지한다. 모든 preview에는 합성 데이터 안내와 실제 작업 화면으로 돌아가는 링크를 제공한다.
- 시안은 실제 폴더 picker/권한/저장소를 호출하지 않는다. 설정 시안에는 실제 연결 컴포넌트를 넣지 않는다.
- 실제 화면에는 사용 가능한 조작만 노출한다. 구현되지 않은 기능의 상태는 즉시 읽을 수 있으며 실제 연결의 진행·취소·실패·재시도 피드백은 유지한다.
- 이번에는 설정/파일 간 연결 상태 공유, 파일 읽기, 인증 구현을 추가하지 않는다. 개발용 소유자·DB·localhost 제한의 교체 조건은 기존 연결 명세 §6을 따른다.

## 변경과 검증 순서

1. 기존 실제 경로에 시안이 노출됨을 브라우저 검사로 확인한다.
2. 기존 화면은 preview 경로로 보관하고 실제 경로를 데이터 없는 정직한 상태와 실제 폴더 연결로 구성한다.
3. 실제 경로의 합성 데이터/가짜 조작 부재, preview의 명확한 표시와 실제 연결 I/O 부재, 좁은 화면·키보드·링크를 검사한다.
4. 기존 폴더 연결의 선택·취소·저장 실패·재연결·해제 실패 검사를 새 화면에서 다시 실행한다. 제거된 가짜 설정 입력과 시안 탭 보존 검사는 현재 제품 범위에서 제외한다.
5. 전체 단위 테스트·타입·린트·빌드, 경로별 production 성능을 확인한다. 기능 집합이 달라졌으므로 전후 수치를 순수 최적화 성과라고 부르지 않는다.

검증 데이터: 격리된 브라우저, 고정 합성 이름과 OPFS 파일. 제품 화면에 이 데이터를 자동 주입하지 않는다. 브라우저 검사의 picker/권한 대체는 실제 OS 선택창 검증이 아니다.

## 직접 확인

1. `http://127.0.0.1:3001/`에서 예시 대화·최근 대화·사용자 이름이 없는지 확인한다. 입력창은 구현 전으로 비활성화되어 있다.
2. ‘자료 폴더 연결하기’를 누르면 `/settings`에서 실제 연결 조작이 바로 나온다. 테스트 폴더를 선택하면 실제 이름과 결과가 표시된다. 선택 취소 시 기존 연결 유지, 새로고침 시 재연결 필요, 해제 시 원본 보존은 기존 계약과 같다.
3. `/files`에서 직접 자식 목록과 하위/상위 탐색을 확인한다. 실제 읽기에 성공한 빈 폴더에만 0개를 표시한다. MD/TXT 버튼은 원문 미리보기를 열며 다른 확장자는 열지 않는다. 읽기 실패·재시도·취소·권한 상실과 목록으로 돌아갈 때 초점/스크롤 복구를 확인한다.
4. ‘시안 보관함’에서 전체 화면 시안을 연다. 상단 합성 데이터 안내와 실제 폴더 연결로 돌아가는 링크가 있어야 한다. 설정 시안의 버튼은 실제 폴더 선택창을 열지 않고 호출 기록만 바꾼다.

3000 개발 서버와 3001 production 검증 서버는 저장소가 분리되는 서로 다른 origin이다. 사용 중인 주소를 유지해서 새로고침·복원을 확인한다.

## 코드 읽는 순서

1. `apps/web/src/app/settings/page.tsx`: 기존 실제 `SourceFolderSettings`를 바로 배치한다. 이 변경에서 연결 controller·session·repository는 수정하지 않았다.
2. `apps/web/src/features/workspace/WorkspaceShell.tsx`: 실제 경로의 메뉴와 시안 보관함 링크를 조합한다. 예시 최근 대화·프로필·검색 dialog를 가져오지 않는다. desktop/mobile은 같은 navigation 배열을 쓴다.
3. 같은 폴더 `UnavailableFeature.tsx`: 반복되는 미구현 안내와 실제 연결 진입만 공유한다. 데이터 0건/조회 실패를 만들어내지 않는다. `live-workspace.module.css`는 기존 토큰과 간격을 사용한다.
4. `/`, `/files`, `/login`, `/welcome`의 `page.tsx`: 각 기능이 미구현임을 정확히 설명한다. 채팅은 승인된 읽기 폭과 하단 입력창을 유지하되 예시 대화와 모의 전송을 제거했다.
5. `app/preview/layout.tsx`는 시안 경계를 공통 표시하고, `preview/screens/[screen]/page.tsx`는 기존 전체 화면 5개를 조합한다. `SettingsPrototype`은 실제 연결 대신 `FolderConnectionDemo`를 사용한다. prototype 내부 메뉴와 인증 시안 링크도 preview 경로로 연결한다.
6. `scripts/check-live-screens.mjs`는 실제 라우트를 브라우저로 연다. `scripts/check-settings-folder-connection.mjs`는 기존 실제 연결 실패 경로를 검사한다. 검사 안의 합성 입력은 제품 코드에 들어가지 않는다.

새 파일은 제품용 메뉴/공통 미구현 표시와 보관 경로의 책임을 분리하기 위해 추가했다. 기존 시안 내부의 조건 분기에 제품 상태를 섞거나 화면마다 메뉴를 복사하지 않았다. 공통 CSS·ActionLink·아이콘은 기존 구현을 재사용하며 위치 이동이나 대규모 폴더 정리는 하지 않았다.
