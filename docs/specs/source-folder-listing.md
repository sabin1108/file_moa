# 자료 폴더 목록 읽기

2026-10-28. `/files` 화면 통합과 목록 정렬 수정을 완료하고 아래 UI 계약을 재검증했다. 이후 MD/TXT 버튼의 본문 읽기는 별도 [미리보기 계약](source-file-preview.md)으로 구현했다. 목록 열거 자체는 본문을 읽지 않는다. [목록 실행 근거](../verification/source-folder-browser/README.md), [미리보기 포함 최신 회귀](../verification/source-file-preview/README.md). 이전 로직 검증과 이번 화면 검증을 구분한다.

## 입력과 결과

`FolderConnectionSession.listSourceFolder(path, signal?)`에 연결 루트 기준 이름 배열을 전달한다. `[]`는 루트, `["자료", "하위"]`는 그 하위 폴더다. 연결 핸들은 반환하지 않는다. 결과는 요청 경로, 바로 아래 파일/폴더의 이름·종류, `truncated`다. 폴더 먼저, 같은 종류는 이름의 코드 단위 순서로 정렬한다. 본문·크기·수정 시각을 읽지 않으며 미지원 확장자도 목록에서는 숨기지 않는다.

한 폴더에서 최대 1,000항목을 보관하고 1개를 더 조회해 초과 여부를 확인한다. `truncated: true`는 전체가 아닌 일부 목록이다. 브라우저 열거 순서는 보장되지 않으므로 제한된 일부의 구성은 갱신마다 달라질 수 있다. 페이지 커서나 전체 파일 수를 추측하지 않는다. 이 임시 목록 한도는 문서 처리의 파일당 2MiB/500문서/텍스트 50MiB와 별개다. 본문 미리보기·선택 자료 처리에서 해당 한도를 적용한다.

## 수용·실패 계약

| ID | 조건 → 결과 |
| --- | --- |
| LIST-001 | 연결 완료 → 바로 아래 파일/폴더만 읽고 정렬된 표시값 반환. 본문/하위 전체 자동 탐색 없음 |
| LIST-002 | 정상 열거 완료·0항목 → 빈 목록. 이것은 해당 조회의 결과이며 전체 스캔/삭제 증거가 아님 |
| LIST-003 | 미연결·복원 후 재연결 전 → 거부, 파일 I/O 없음 |
| LIST-004 | 조회 전/후 read 권한이 prompt/denied 또는 열거 중 NotAllowedError → 실패, 세션은 다시 연결 필요. 권한 자동 요청/저장 참조 삭제 없음 |
| LIST-005 | 대상 폴더 누락·열거 실패 → 원래 오류 반환, 부분 목록을 성공으로 반환하지 않음. 삭제 확정/빈 폴더로 변환 금지 |
| LIST-006 | 1,000개 이하 → truncated=false. 1,001개 이상 → 최대 1,000개와 truncated=true, 추가 재귀 탐색 없음 |
| LIST-007 | 취소 신호 → AbortError. 이미 진행 중인 브라우저 호출은 강제 취소할 수 없고, 완료 후 결과를 버리며 다음 I/O를 시작하지 않음 |
| LIST-008 | 새 목록 요청·연결 변경·해제·소유자 변경 → 이전 성공과 오류 모두 stale-connection-operation. 기존 연결 세대/순번을 재사용하며 목록 순번은 연결 조작과 분리 |
| LIST-009 | 빈 이름, `.`, `..`, 슬래시, 역슬래시, NUL이 있는 경로 → I/O 전 거부. 입력 배열은 복사해 대기 중 호출자 변경으로 탐색 범위가 바뀌지 않음 |
| LIST-010 | 원본 쓰기·생성·삭제·이동·본문 읽기·외부 전송·목록 저장 없음. getDirectoryHandle은 create:false만 사용 |

목록 API에서 현재 요청의 권한 상실이 확인되면 목록 controller는 오류를 게시하고 연결 controller도 연결 view를 갱신한다. 갱신 실패 시 마지막 목록을 오래된 정보로 보존하되 계정/연결 변경 시에는 즉시 비운다. 새 요청 시작 시 이전 결과를 쓸 수 있는지 결정하는 것은 목록 controller의 책임이다.

## 검증 자료와 경계

테스트는 직접 작성한 합성 핸들/이름/지연 Promise를 사용한다. 개인 폴더를 스캔하지 않는다. 출처는 저장소 자체, 외부 데이터/다운로드 없음. seed는 고정 순번 생성(무작위 없음), 전부 개발 회귀셋이며 holdout/사람 검토 완료를 주장하지 않는다. case ID는 테스트 이름에 연결한다. OS 권한창과 파일 시스템 구현은 단위 테스트가 대체하므로 실제 브라우저 검증과 구분한다.

공식 API 확인: [WHATWG 디렉터리 열거](https://fs.spec.whatwg.org/#api-filesystemdirectoryhandle), [getDirectoryHandle](https://fs.spec.whatwg.org/#dom-filesystemdirectoryhandle-getdirectoryhandle), [읽기 권한](https://wicg.github.io/file-system-access/#permissions). 열거는 원자적 스냅샷이 아니며 디스크 변경이 도중에 반영되거나 누락될 수 있다. `values`/`getDirectoryHandle`에 AbortSignal을 넘기는 API는 없다.

화면 질문: ‘지금 연결한 폴더 안에 무엇이 있고 어느 하위 폴더로 들어갈 수 있는가?’ 주 대상은 실제 이름·종류이며 목록 아래에 가짜 최근 작업/파일 수를 채우지 않는다. 대상 사용자·기기는 기존 개인 작업 공간과 동일하다. 기존 achromatic-ledger(seed2044201404), 네이비/회백 팔레트, 시스템 서체, 4/8/12/16/24px 간격, 40/44px 조작 크기를 유지한다. 현재 폴더 경계 안에 직접 자식 항목을 놓아 포함 관계를 보여준다. 새 방향 추첨/채팅 재설계는 하지 않는다.

검증 자료는 직접 만든 합성 폴더2개/하위 폴더/한글·공백·긴 이름, 100/1,000/1,001항목 고정 순번 fixture다. 개인 노트/외부 데이터 사용 없음. 수명 테스트는 실제 controller/session/reader에 브라우저 경계만 대체한다. UI는 실제 IDB/Web Locks/OPFS, 합성 picker/권한/실패로 검사한다. OS 권한창·실제 계정은 별도 미검증 범위다. 입력창이 없어 IME 조합 검사는 해당 없음.
