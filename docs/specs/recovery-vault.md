## 사용 흐름

1. 선택 파일과 목적지를 검사한다. 정확히 같은 이름의 기존 **파일**이 있으면 충돌 파일별 새 원본/현재 목적지를 보여주고 `계속`/`작업 중단`을 제공한다. 계속은 즉시 쓰지 않는다.
2. 복구 보관함이 없다면 사용자가 처음 한 번 위치를 지정하고 `모아 복구 보관함`을 생성한다. 기존 이름 폴더는 임의 재사용하지 않으며 유효한 보관함인지 검사하거나 새 이름을 고른다. 기록 폴더 선택이 아니라 사용자 데이터의 복구본 전용 위치다.
3. 경고에서 ‘기존 목적지 파일을 복구 보관함에 저장한 뒤 새 내용으로 바꿉니다’, 대상 목록/위치/용량/보관 기간을 확인한다. 기본 초점은 중단. 최종 버튼은 `복구 사본을 남기고 덮어쓰기`이며 별도 사용자 제스처에서만 실행한다.
4. 완료 뒤 기존 작업 기록과 복구 보관함 목록에서 원래 위치·보관 시각·원인·상태·보관 만료를 확인한다. 복원과 영구 삭제는 독립 행동이다.

대소문자/유니코드 모호 충돌, 폴더와 파일 충돌, 불완전한 목록, 같은 출발/도착, 중복 도착은 계속 차단한다. 첫 구현은 현재 선택 기능과 같은 파일 범위다. 폴더는 재귀 목록·부분 실패·복원 구조·삭제 범위를 별도 검증한 뒤 확장한다.

## 책임과 연결

복구 보관함은 owner/workspace별 `recovery` capability다. 브라우저 handle/IndexedDB와 명시적 재연결을 사용하고 초기화/조회에서 권한을 요청하지 않는다. 과거 `ai-records`를 바꿔 쓰지 않는다. 목적지 `.moa-history`는 기존대로 작업 기록만 저장한다. 보관함은 원본/목적지와 같거나 위험한 포함 관계이면 거부하며 실제 API로 관계 확인 가능성을 검증한다.

UI는 보관함 선택과 결과 표시, 별도 controller는 연결/진행/취소, service는 백업/검증/쓰기, lib는 manifest·상태 전이·보존 정책을 맡는다. 기존 copy v1은 유지하고 replace/recovery용 versioned record family를 만든다. 이름/날짜만으로 보관본을 식별하지 않고 operation/item ID와 hash를 쓴다.

## 백업이 선행하는 쓰기 계약

원본과 기존 목적지 identity/metadata/hash 검사 → immutable bytes 고정 → 두 저장소 prepared 기록 → 보관함의 고유 항목에 기존 목적지 bytes 저장 → close/재열기/identity/hash 검증 → backup-verified 기록 재읽기 → 목적지가 승인 당시와 같은지 재검사 → target-started 기록 → 덮어쓰기/close → 대상 hash/identity 검증 → target-verified → stopped.

backup-verified 이전 실패는 기존 목적지 변경0. 그 이후 대상 변경을 시작한 항목의 실패/취소는 미확인으로 남기고 후속 항목은 실행하지 않는다. 백업 자동 삭제/rollback/자동 재시도0. 연결/owner 교체 후 구 결과를 새 UI에 게시하지 않는다. 권한 상실·공간 부족·record mismatch이면 중단한다. 두 폴더의 저장은 원자적이지 않으며 기록 불일치는 미확인이다. UUID 이름과 Web Locks는 외부 OS 경쟁까지 잠그는 보장이 아니다.

보관본 필수 정보: operation/item/recovery ID, owner, 원래 상대 경로, source/target 승인 size/hash, 백업 size/hash, 보관 시각, 보존 정책/만료 시각, 상태. 본문/절대 경로를 일반 로그에 넣지 않는다. 실제 보관 bytes와 작업 기록을 구분한다. 초기 한도는 기존 복사의 파일16MiB/작업64MiB를 후보로 하되 원본+기존 목적지+백업 readback의 메모리·시간을 따로 측정한다.

## 복원·보존·삭제

- 복원 전 manifest/현재 보관본 hash를 다시 검증한다. 원래 위치가 비었을 때 새로 복원하고, 같은 이름이 이미 있으면 새 이름 복원을 기본안으로 한다. 원래 위치의 현재 파일을 임의로 덮어쓰지 않는다.
- 복원 성공 후에도 보관본은 자동 삭제하지 않는다. 사용자가 선택한 복구 항목의 즉시 삭제는 대상 수/용량과 복구 불가 경고 후 실행한다. 보관함 밖 경로를 삭제하지 않으며 임의 사용자가 넣은 파일을 삭제 대상으로 추정하지 않는다.
- **30일 기본값은 제안이며 사용자 확정값이 아니다.** 최초 설정에서 보관 기간과 자동 정리 여부를 고른다. 브라우저가 닫혀 있거나 권한이 없으면 정확한 날짜에 OS 파일을 삭제할 수 있다고 약속하지 않는다. 초기 구현 후보는 만료 표시→사용자 `만료 항목 정리`, 후속은 동의한 경우 앱 실행 중 자동 정리다.
- 미확인·손상·복원 진행 중 항목은 자동 정리에서 제외한다. 동시 복원/삭제는 같은 항목 잠금과 세대 검사로 직렬화하며 실패한 삭제 항목은 목록에 남긴다.

미정: 보관 기간 선택지/기본값, 자동 정리 기본 상태, 복원 충돌 시 현재 파일 재백업 후 교체까지 허용할지, 폴더 재귀 범위. 이 결정은 파일 작업 UI 개선을 막지 않지만 영구 삭제 구현 전에 확정해야 한다.
