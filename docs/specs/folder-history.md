# 현재 폴더 작업 기록 조회

2026-10-31. 사용자가 다음 구현으로 승인한 범위는 `.moa-history` 읽기 전용 조회다. 실제 파일 존재 재확인, 자동 복구, 삭제/복사/이동 실행은 이번 범위에 포함하지 않는다.

## 동작과 책임

HISTORY-001: 현재 목록의 `작업 기록` 버튼에서 native dialog를 연다. 현재 연결 폴더/상대 경로와 기록 조회 시점을 표시한다. 닫기/Escape는 호출 버튼으로 초점을 돌린다. 폴더 이동/연결 교체/사용 불가 시 이전 조회를 폐기한다. 검색·파일 선택·미리보기 상태는 변경하지 않는다. 목록/새로 만들기는 기존 구성과 토큰을 유지한다.

HISTORY-002: 열기/새로고침에서만 현재 부모 아래 `.moa-history`를 읽는다. 모든 directory/file 조회는 create:false이며 requestPermission·쓰기·삭제·서버 전송을 하지 않는다. 기록 폴더가 없으면 기록 없음이다. 부모가 사라짐, 기록 위치가 파일임, 읽기 거부는 각각 오류로 표시한다. 기록이 없더라도 마지막 권한/연결 확인을 생략하지 않는다.

HISTORY-003: 현재 writer의 `moa-folder-*.json` 파일만 읽는다. version1의 id/path/status/time/owner/kind를 검증한다. 과거 kind 없는 기록은 folder로 해석한다. 현재 owner와 다른 기록은 표시하지 않는다. path는 현재 부모의 직접 자식이어야 한다. 기록 내용은 일반 텍스트로 표시하며 HTML이나 경로 명령으로 실행하지 않는다. sourceName은 표시 기준이나 보안 경계로 사용하지 않는다. 개발 owner는 실제 인증을 뜻하지 않는다.

HISTORY-004: 같은 작업 ID를 하나로 묶는다. pending + 단일 일관 terminal ready는 `완료 기록`, failed는 `실패 기록`이다. pending만, terminal만, uncertain, 상충하는 terminal, 경로/종류 불일치, pending보다 이른 terminal은 `결과 미확인`이다. 기록상 완료는 현재 파일 존재나 이 앱이 배타적으로 생성했다는 보장이 아니다. 경로가 충돌하면 임의의 한 경로를 정답처럼 표시하지 않는다. 시간 내림차순, 동률은 ID로 안정 정렬한다.

HISTORY-005: 손상 JSON/잘못된 UTF-8/알 수 없는 버전/읽지 못한 개별 파일/크기 초과를 합계 경고로 표시한다. 다른 owner 기록은 제외 개수만 표시한다. 읽기 일부 실패나 상한 초과가 있으면 전체 기록을 읽었다고 하지 않고 읽힌 작업도 결과 미확인으로 표시한다. 인식 못한 기록을 삭제하거나 고치지 않는다.

HISTORY-006: 직계 항목 탐색 최대1000개, 기록 파일 읽기 최대200개, 파일당64KiB, 총2MiB를 이번 조회의 명시적 상한으로 둔다. 상한 도달 시 일부 조회임을 표시하며 최신200개 전체를 보장하지 않는다. 다른 확장자/디렉터리로 재귀 진입하지 않는다. 전체 읽기를 마친 뒤에만 완전한 조회로 표시한다. 작고 제한된 JSON만 해석하며 새 의존성/Worker 계층은 추가하지 않는다.

HISTORY-007: controller는 close/dispose/새 요청으로 이전 결과를 무효화하고 AbortSignal을 전달한다. session은 owner·연결 세대·root 핸들을 확인한다. 조회 중 연결 변경/취소를 개별 손상 기록으로 삼키지 않는다. 오류나 취소 후 과거 결과를 현재 결과로 표시하지 않는다. 조회가 실패했다고 원본 파일 삭제를 추정하지 않는다.

## 구현 전 확인할 실패 경로

- reader 미구현 → 없음/정상 묶기/legacy/중복·충돌/순서/owner 격리/잘못된 경로·버전·UTF-8·크기/읽기 상한/권한·연결·취소 테스트 실패.
- controller 미구현 → 닫기·재요청 후 늦은 응답/오류 차단, 취소 및 재시도 실패.
- 실패 테스트 후 순수 해석 → 읽기 service → session → controller → UI를 연결한다.
- 브라우저에서 실제 OPFS 기록 생성 후 조회, 빈 폴더에서 기록 폴더 미생성, 권한/picker/원본 쓰기 호출 변화 없음, Escape/Tab, 390/768/1440/1920 폭, 연결 교체·새로고침·손상 기록을 확인한다. OS 권한창·개인 디스크 검증과 구별한다.

## UI 구성

기존 ZIP 폴더 시안·시스템 서체·색상/44px 조작을 유지한다. 이 화면의 질문은 “이 폴더에서 어떤 생성 작업이 기록됐는가?”다. 기록은 한 작업당 이름·종류·경로·시각·결과를 갖는 목록으로 표시한다. 개별 ID는 details 안에 둔다. 조회 중/빈 상태/일부 조회/실패를 기존 StatusNotice로 표현한다. 목록의 `작업 기록` 진입은 검색·선택 도구 옆에 두고 열기 전 기록 본문을 읽지 않는다. 상태 문구 공간을 확보해 새로고침 시 도구 줄바꿈으로 파일 행이 이동하지 않게 한다.
