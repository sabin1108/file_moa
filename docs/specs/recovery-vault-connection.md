# 복구 보관함 생성·연결 — 2026-11-04

이번 단위: 설정/폴더 연결 창에서 전용 보관함 생성, 기존 보관함 연결, 명시적 재연결, 연결 해제. 백업·덮어쓰기·복원·삭제는 후속이다.

- RV-001: recovery는 source/ai-records와 별도 owner/workspace 키로 저장한다. 초기화는 핸들만 복원하며 권한 요청/본문 읽기 없이 재연결 대기한다.
- RV-002: 자료 폴더 연결 후에만 설정한다. 현재 목적지는 자료 루트 내부이므로 전체 자료 루트를 보호한다. 보관함과 자료 루트의 동일/상하위 관계를 isSameEntry/resolve 양방향으로 차단한다. 관계 확인 실패/권한 거부도 차단한다. 향후 외부 목적지 도입 시 그 루트도 보호 목록에 추가해야 한다.
- RV-003: 기존 연결은 식별 JSON의 owner/버전/형식/재읽기 검증 후 저장한다. 일반 폴더를 자동 보관함으로 채택하지 않는다. 재연결도 위치/식별 정보를 다시 검증한다.
- RV-004: 생성 버튼은 쓰기 모드 picker로 부모 위치를 선택하고 UUID가 붙은 새 하위 폴더를 만든다. 부모가 자료 폴더 자체/하위면 생성0. 부모가 자료 폴더의 상위이면 새 자식과 자료 루트의 관계를 다시 확인한다. 기존 이름/식별 파일을 재사용하거나 덮어쓰지 않는다. 식별 JSON close/재읽기 검증 후에만 연결을 저장한다.
- RV-005: 취소/owner 변경/자료 연결 변경/해제 이후 늦은 성공을 게시하지 않는다. 매 await 전후 수명을 확인한다. 쓰기가 시작된 뒤 취소/실패하면 새 폴더나 식별 파일이 남을 수 있으며 자동 삭제/rollback하지 않는다. 저장 실패를 연결 성공으로 표시하지 않는다.
- RV-006: 연결 해제는 브라우저 참조만 제거한다. 생성은 동일 origin Web Lock으로 직렬화한다. File System Access API는 외부 프로그램의 원자적 exclusive 생성/경쟁 차단을 보장하지 않으므로 UUID·사전 충돌 검사·재읽기의 제한을 보고한다. 백업 안전성을 연결 성공으로 표현하지 않는다.

실패 테스트: 동일/상하위/같은 이름 다른 핸들, 관계 오류, 권한 거부, 일반 폴더/타 owner, 생성 write/close/readback 실패, 취소, 저장 실패, owner 교체, 명시적 재연결. 합성 폴더 core와 Chromium OPFS/UI를 구분해 검증한다.
