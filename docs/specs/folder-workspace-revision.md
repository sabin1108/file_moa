# 폴더 작업 화면 개정 · 2026-10-30

사용자 제공 `최종안_시안.zip`의 데스크톱 경로 열/목록/미리보기와 모바일 목록/하단 미리보기를 새 기준으로 삼는다. 이전 폴더 화면 구성을 대체하며 채팅은 변경하지 않는다. 원본 참고 자료는 `docs/design-reference/final-folder-20261030`이다.

- 선택 버튼은 파일 다중 선택을 시작한다. 선택 취소는 체크와 선택 도구를 함께 해제한다. 체크박스, 선택 개수, 행의 선택됨 표시로 색상에만 의존하지 않는다.
- 목적지는 실제 폴더 이름과 전체 연결 상대 경로로 확인한다. 탐색 취소와 파일 선택 취소를 구별한다.
- 데스크톱은 방문한 상위 폴더 열, 현재 목록, 실제 MD/TXT 미리보기를 함께 표시한다. 모바일은 목록을 유지하고 native dialog 하단 미리보기를 제공한다. 예시 즐겨찾기/개수/파일을 제품에 넣지 않는다.
- 목록과 목적지 탐색에서 새 폴더 이름을 입력하고 명시적으로 생성한다. 사용자가 실제 디스크 생성까지 승인했다. 이동/복사/분류 실행은 여전히 계획 검토 범위다.

## 새 폴더 계약

2026-10-30 후속 사용자 정정: 생성 위치 기본값은 현재 탐색 폴더다. 별도 기록 폴더 선택 창을 열지 않는다. 기록은 현재 폴더의 `.moa-history`에 자동 보관하며 사용자에게 위치를 표시한다. 아래 별도 기록 폴더 지정 계약은 이 개정이 대체한다. 기존에 지정했던 기록 폴더는 삭제/이동하지 않는다. 생성 버튼의 최초 쓰기 권한 요청은 유지한다.

MKDIR-001 이름은 단일 경로 조각이며 빈 이름, 상대/절대 경로, 제어문자, 예약 이름, 끝 공백/점은 거부한다. 부모는 연결 루트 아래 기존 경로만 허용한다.

MKDIR-002 생성 버튼의 사용자 제스처에서 즉시 readwrite 권한을 요청한다. 거부하면 쓰지 않는다. 연결 세대가 바뀌면 쓰기 전 중지한다.

MKDIR-003 동일 앱의 생성은 Web Lock으로 직렬화한다. 직계 항목 이름을 정규화 비교하여 파일/폴더 충돌을 거부한다. 외부 앱의 경쟁까지 원자적으로 배제할 수 없으므로 생성 API 완료는 ‘폴더 준비 완료’로 보고한다. 기존 항목을 삭제/덮어쓰기하지 않는다.

MKDIR-004 변경 직전 현재 폴더의 `.moa-history`에 pending JSON을 확정한다. 별도 기록 폴더 연결은 요구하지 않는다. 기록 실패 시 요청한 새 폴더를 생성하지 않는다. 생성 호출 이후의 실패/앱 종료는 결과 미확인으로 남긴다. 완료 기록 실패 역시 성공으로 단정하지 않는다. 자동 재시도·롤백·삭제는 하지 않는다. 각 상태는 독립 UUID 파일이며 이전 기록을 갱신하지 않는다. 작업 기록은 파일 탐색기로 열어 확인할 수 있다. IndexedDB는 핸들만 저장하며 장기 기록의 유일한 사본으로 쓰지 않는다. `.moa-history`라는 기존 파일이 있으면 덮어쓰지 않고 오류를 표시한다. 같은 이름의 폴더는 기록 보관에 사용하며 사용자가 생성할 새 폴더 이름으로는 예약한다.

기록에는 버전·작업 ID·상대 경로·상태·시간·개발 소유자 구획·연결 폴더 이름을 넣는다. pending에 대응하는 ready/failed가 없으면 미확인으로 취급한다. 기록 폴더는 생성 위치 안에 자동으로 준비하는 앱 기록 보관 위치다. 외부 프로그램과의 원자적 배타 생성은 브라우저 API가 보장하지 않으며 무작위 기록 파일명은 충돌 가능성을 줄이는 수단이다. 파일 이동/복사 실행의 강한 무덮어쓰기 계약으로 확대하지 않는다.

API 근거: [WHATWG File System](https://fs.spec.whatwg.org/#dom-filesystemdirectoryhandle-getdirectoryhandle), [WICG 권한 요청](https://wicg.github.io/file-system-access/#api-filesystemhandle-requestpermission). create:true는 기존 같은 이름 폴더를 반환할 수 있으므로 준비 완료와 생성 주체 보장을 구분한다.

MKDIR-005 부모 핸들 동일성·권한·연결을 생성 직전 재확인한다. 폴더 생성에는 파일 본문/해시 읽기가 필요 없다. 생성 후 목록을 다시 읽어 목적지로 선택할 수 있다.

## 검증

### 2026-10-31 추가 요청 재개: 연결 위치와 명시적 확장자

- CONNECT-UX-001: 연결 관리 버튼은 전역 우측 상단에서 현재 폴더 목록의 새로고침 옆으로 이동한다. 미연결/권한 오류/하위 폴더에서도 접근 가능하며 기존 native dialog의 Escape 닫기와 호출 버튼 초점 복귀를 유지한다. 390/768/1440/1920px에서 목록 안에 있고 조작 크기 44px 및 가로 넘침 없음을 확인한다. 기존 ZIP 시안·색상·서체는 유지한다.
- NEW-005: 입력 마지막 확장자가 `.txt` 또는 `.md`이면 대소문자 구분 없이 선택 종류보다 우선한다. `folder + aaa.txt → txt/aaa.txt`, `txt + 기록.MD → md/기록.MD`. 입력한 대소문자를 보존하고 NFC 정규화한다. 두 확장자가 없으면 기존 선택 종류와 확장자 자동 보완을 유지한다. 알 수 없는 확장자를 지원 파일 종류로 추측하지 않는다.
- NEW-006: 폼은 최종 이름과 파일/폴더 종류를 생성 전에 표시한다. controller의 완료 문구, service의 API 선택, journal의 kind는 같은 해석을 따른다. 이름 검증·충돌 거부·권한 요청·원본 파일 비절삭·기록 실패/미확인 처리 계약은 유지한다.
- 검증 순서: 확장자 우선 규칙/실제 파일 API/기록/완료 문구의 실패 테스트 → 구현 → 기존 생성 회귀와 전체 check → 합성 OPFS 브라우저에서 실제 결과·목적지 폼·키보드·좁은 화면 → production 성능 기록. 사용자가 보고한 `aaa`로 잘리는 현상은 기존 코드에서 아직 재현되지 않았으며 폴더 생성 분기 오류와 구분한다.

### 후속 NEW-001~004: Windows식 새로 만들기

사용자가 폴더/TXT/MD를 선택해 생성하는 익숙한 흐름을 명확히 요청했다. `새로 만들기` 안의 종류 선택은 폴더(기본), 텍스트(.txt), 마크다운(.md)이다. 이름을 직접 입력하며 선택 확장자는 없을 때만 붙인다. 확장자를 포함한 최종 이름도 동일한 경로/길이/예약 이름 검증을 통과해야 한다. 입력 중 한글 조합 Enter는 제출하지 않는다.

현재 위치에서 폴더 또는 0바이트 파일을 생성하고 같은 위치에 기록을 남긴다. 파일 본문 편집은 이 기능에 포함하지 않는다. 기존 파일/폴더 이름 충돌은 실행 전에 막는다. 빈 파일 생성에는 getFileHandle(create:true)만 사용하고 원본 파일에 createWritable/write/truncate를 호출하지 않는다. 외부 프로그램이 동시에 파일을 만들면 그 내용을 보존하며, 비어 있지 않거나 entry가 바뀌면 미확인 결과로 남긴다. journal에는 선택 종류를 추가한다. 이전 kind 없는 폴더 기록은 그대로 보존한다.

실패 테스트 → 서비스/상태/UI → 단위·타입·린트·빌드 → 브라우저 실제 OPFS 생성 및 충돌/권한 거부/기록 실패/선택 취소/키보드/모바일 확인. OS 권한 창과 사용자 실제 디스크의 물리 조작은 자동화 fixture와 구분한다.
