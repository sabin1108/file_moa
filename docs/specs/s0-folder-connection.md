# S0 폴더 재연결 계약

2026-10-25. 독립 검증 도구의 연결 수명주기이며 제품 인증·계정 격리 완료를 뜻하지 않는다.

1. 시작할 때 IndexedDB의 테스트 폴더 핸들을 메모리에 준비한다. 시작·새로고침으로 권한 창을 자동 호출하지 않는다. 준비 중에는 관련 조작을 막는다.
2. 명시적 복원/미리보기/합성 기록 조작 클릭에서 메모리 핸들에 `requestPermission`을 먼저 호출한다. 그 전에 IndexedDB 조회를 기다리지 않는다. 읽기에는 read, 합성 쓰기에는 readwrite만 요청한다.
3. 권한 거절·철회는 연결 삭제가 아니다. 핸들을 보존하고 재시도할 수 있다. 원본 파일을 삭제하지 않는다.
4. 새 테스트 폴더/복구 폴더는 저장 및 검증, IndexedDB 게시가 모두 성공한 뒤 활성 연결로 교체한다. 게시 실패 시 기존 활성 연결을 유지한다.
5. 자료 폴더 교체는 읽기 전용 목록 검사가 성공한 뒤 반영한다. 취소·실패 시 기존 자료 연결을 유지한다. 파일 내용은 읽거나 전송하지 않는다. 숨김 항목 제외, 총 디렉터리 500/파일 5,000 한도를 넘으면 부분 결과로 연결을 교체하지 않는다.
6. 지원하지 않는 환경은 picker 버튼 실행 전 안내한다. 폴더 선택 취소는 실패와 구분한다. 원본과 테스트 저장 위치의 동일/상하위 겹침 검사는 유지한다.

핵심 자동 검증: 시작 시 권한 요청 없음, 핸들 미준비/잘못된 핸들 거부, 권한 요청의 동기 호출, read/readwrite 구분, 거절 후 재시도, 게시 실패 시 연결 보존, 목록 실패/한도 처리. 합성 fixture만 사용한다.

근거: [MDN requestPermission](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemHandle/requestPermission)의 transient activation 조건, [Chrome File System Access 안내](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)의 핸들 저장·권한 재확인 규칙. IndexedDB 완료까지 클릭 activation이 유지된다는 보장이 없으므로 핸들 복원을 클릭 이전에 끝낸다. 이미 허용된 권한에서도 매 명시적 접근 직전 현재 권한을 확인하며, 시작 때 권한 요청은 하지 않는다.

실제 외부 폴더의 선택·권한 철회·재허용·브라우저 재시작은 별도 수동 증거가 필요하다. fake 권한 반환값이나 OPFS로 이를 완료 처리하지 않는다. 제품 통합 전 계정/장치별 핸들 저장소와 연결 해제·삭제 계약을 별도로 적용한다.
