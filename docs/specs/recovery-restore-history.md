# 복원 작업 기록 조회 — 2026-11-04

후속 사용자 지시: 기능1~6 구현 뒤 테스트 재개를 승인했다. 아래 최초 보류는 이번 범위에서 해제했고 완료된 복원 기록의 현재 대조는 [추가 계약](managed-files.md)을 따른다.

- RH-001: 현재 폴더의 작업 기록에 ‘복원’ 분류를 추가한다. 목적지 `.moa-history/moa-restore-UUID`의 기존 JSON만 읽어 파일명·원래 위치·복원 위치·기록 시각·용량·완료/중단/실패/확인 필요를 표시한다. 하위 폴더 전체 또는 보관함을 전수 검색하지 않는다.
- RH-002: 기존 `parseRestoreRecord`로 외부 JSON을 검증하고 owner/workspace·작업 폴더 UUID·공통 식별 정보·정확한 목적지 부모·레코드 종류/파일명을 대조한다. 완료 기록은 prepared/target-started/target-verified/stopped가 일치해야 한다. 누락/손상/기록 변경은 완료로 표시하지 않는다. 다른 소유자 기록은 제외한다.
- RH-003: 조회 한도는 history 루트1000항목/복원100작업, JSON 하나는 기존 기록 쓰기와 같은1MiB/누적2MiB(재읽기 포함)다. 허용된4개 JSON만 읽고 본문/payload는 읽지 않는다. 읽기 권한 확인만 하며 권한 요청·생성·쓰기·삭제·재실행0이다. 취소/연결 교체는 기존 history 요청 수명으로 전파한다. 부모/기록 위치/파일 교체도 조회 중 검사한다.
- RH-004: 여기서 완료는 목적지에 저장된 과거 완료 기록이다. 현재 파일 존재/내용이나 보관함 쪽 기록의 현재 일치를 보장하지 않는다. 보관함이 연결되지 않아도 목적지 기록을 읽을 수 있다. 현재 파일/양쪽 기록 대조, 보관함 기록과 병합, 복원 재실행은 이번 범위에 추가하지 않는다.
- RH-005: 기존 기능별 컴포넌트 설계, history controller/dialog/버튼/StatusLabel/CSS를 재사용한다. 별도 순수 요약 함수·읽기 서비스·표시 컴포넌트로 책임을 나눈다. 새 의존성을 추가하지 않는다.

사용자 최신 지시로 단위/브라우저 테스트 작성·실행과 성능 측정은 요청 전까지 보류한다. 이번 결과에는 타입·린트·빌드 정적 검사만 기록하고 이전514테스트/204브라우저 결과를 이번 변경의 검증으로 사용하지 않는다.
