# 복구 보관함 목록·상세와 권한 안내 — 2026-11-04

- ARCHIVE-001: 연결된 보관함의 앱 백업 기록을 명시적으로 읽어 파일명/원래 상대 위치/보관 시각/용량/기록 상태를 표시한다. 목록에서는 payload 본문/해시를 읽지 않고 ‘검사 전’을 표시한다. 백업 작업 폴더만 복구 항목으로 표시하고 overwrite JSON이나 임의 파일을 복구 사본으로 중복 표시하지 않는다.
- ARCHIVE-002: 상세 확인은 현재 목록의 내부 snapshot에서 선택한 항목만 검사한다. vault/owner/연결 세대·작업 폴더/식별 기록/경로/UUID/strict JSON·실제 payload size/SHA-256·양쪽 백업 기록을 재검증한다. 모든 확인이 맞을 때만 정상이다. payload 누락/해시 불일치는 손상, 권한/기록 부족/변경은 확인 필요다. 과거 성공과 현재 관측을 구별하고 기록 시각과 검사 시각을 나눈다.
- ARCHIVE-003: queryPermission(read)만 사용하고 권한 요청/폴더·파일 생성/쓰기/삭제/복원/대상 내용 읽기0. 소스·목적지는 기록 위치만 읽는다. 원래 위치의 파일 부재나 권한 상실을 보관본 삭제로 판정하지 않는다. 정보가 없는 값은 —, 부분 목록은 명시적으로 일부임을 표시한다.
- ARCHIVE-004: 보관함 루트 최대500항목/백업 작업100개/표시500개, JSON 파일당1MiB·읽기8MiB, payload 파일당16MiB. 과다/손상/불완전/외부 owner 기록은 정상 항목으로 신뢰하지 않고 본문을 읽지 않는다. 읽기 중 취소·연결/owner 변경·새로고침은 늦은 목록/상세를 버린다. 상세는 매번 현재 파일을 읽으며 이전 정상 상태를 재사용하지 않는다.
- ARCHIVE-005: 파일 화면과 연결 설정에서 같은 보관함 dialog를 연다. 기존 native dialog/버튼/평면 행/경고/간격 토큰을 재사용하고390/768/1440/1920px·키보드·Escape/초점 복귀·로딩/빈/실패/취소를 확인한다. 복원·삭제·보존 정책 설정은 이 단위에 포함하지 않는다.
- PERMISSION-001: 브라우저/OS의 실제 권한창은 앱에서 꾸미거나 대체하지 않는다. 기존 사이트와 맞춘 짧은 앱 안내를 연결 버튼 위에 배치하고, 클릭은 기존 사용자 제스처에서 실제 picker/권한 API로 바로 이어진다. 추가 승인 팝업/자동 권한 요청0. 보관함 생성/백업/덮어쓰기의 명시적 쓰기 승인 계약은 유지한다.

공식 브라우저 경계: [Chrome File System Access security/permissions](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access#security_and_permissions). 실제 권한창은 브라우저가 표시하고 사용자 제스처에서 요청한다. 앱 안내의 모양과 실제 권한 승인을 구별한다.
