# AI 문서 분류 입력·결과 계약

## 2026-11-07 Gemini 샘플 연결의 추가 수용 기준

- AIC-009: 서명된 샘플 세션·신뢰 Origin·명시 동의·등록 ID만 받는다. 서버 등록부에서 발췌를 구성하며 개인 파일/경로/기대 정답은 전송하지 않는다.
- AIC-010: 같은 요청 ID, 세션 3회/시간, 전체 1회/분·12회/시간의 네 가지 한도는 DB 트랜잭션 하나로 예약한다. 하나라도 거부되면 전체를 롤백한다. 키 순서를 고정하며 모델 호출은 트랜잭션 밖에서 한다. 승인된 요청은 실패/취소되어도 예약을 환불하지 않는다.
- AIC-011: 반복된 임의 requestId가 한도 거부 뒤 새 행을 누적하거나 정리 쿼리를 반복하지 않아야 한다. 공통 SQL 한도 검사 기존 동작을 회귀로 고정한 뒤 원자 예약을 추가한다. 실제 DB 동시성 확인과 mock 검사를 구분한다.
- AIC-012: 선택 집합이 바뀌거나 초기화하면 전송 동의를 다시 받는다. 취소/만료/다른 작업 뒤 늦은 응답과 새로고침은 AI 재호출/적용을 일으키지 않는다.

작성일: 2026-11-07. 상태: 입출력 검증·합성 테스트셋과 [샘플 세션/화면](sample-workspace.md), Gemini 가상 샘플 호출 연결. 정식 개인 파일의 AI와 일반 PDF/XLSX 파서는 후속이다. 최신 근거는 [Gemini 연결 검증](../verification/sample-gemini/README.md).

## 범위

정식 사용은 TXT·MD를 대상으로 한다. PDF·엑셀의 일반 문서 지원은 후속이다. 테스트 사용에서는 등록된 가상 TXT·MD·PDF·XLSX만 사용한다. 사진·이미지 분류, 스캔/OCR, XLS/XLSM, 임의 PDF·엑셀 업로드 파서는 이번 범위에 포함하지 않는다.

테스트용 PDF·XLSX는 실제 파일과 확인된 내용 발췌를 함께 준비한다. PDF는 두 페이지의 한글 텍스트, XLSX는 한 시트의 학습 항목·숫자·합계 수식을 확인했다. 페이지/셀 위치와 파일 SHA-256을 데이터셋에 기록하며, 이 준비 작업을 앱의 범용 파서 구현이나 AI 정확도 검증으로 보고하지 않는다.

## 입력

권한이 확인된 호출자가 아래 데이터를 구성한다. 원본 경로·핸들·인증 정보·기대 정답은 모델 입력에 포함하지 않는다.

```json
{
  "documents": [{ "id": "note-1", "name": "회의.md", "excerpt": "출시 일정과 담당 업무를 회의에서 정했다." }],
  "folders": [{ "id": "meeting", "label": "업무/회의" }]
}
```

- AIC-001: 정식 입력은 TXT·MD만 허용한다. 기존 실제 읽기의 UTF-8·파일당 2MiB·권한 검증은 유지한다. 파일명을 바꾸는 것만으로 파일 읽기 검증을 대신할 수 없다.
- AIC-002: 테스트 입력은 서버가 제공한 샘플 등록부의 문서 ID·파일명·발췌와 정확히 일치해야 한다. 등록부에 없는 자료나 변경한 발췌는 거부한다. 등록부에 있어도 사진은 거부한다.
- AIC-003: ID는 영문/숫자/밑줄/하이픈 1~64자다. 파일명에는 경로 구분자·제어문자를 허용하지 않는다. 문서·폴더 ID 중복, 스키마 밖 필드, 클라이언트가 주장하는 mode/workspaceId 등은 거부한다. 요청한 대상 폴더 ID·이름은 서버가 확인해 제공한 허용 폴더 목록과 대조하고, 범위 밖 대상이나 변경한 이름은 거부한다.
- AIC-004: 한 요청은 문서 1~20개, 대상 폴더 1~30개, 발췌별 최대 2,000 UTF-16 코드 단위, 총 발췌 최대 20,000 UTF-16 코드 단위다. 이는 코드의 `.length` 제한이며 바이트/토큰 한도가 아니다. 실제 모델 호출 전 별도의 토큰·과금 한도와 전체 예산 예약이 필요하다.

모드·허용 폴더 목록·샘플 등록부는 서버 권한 확인 결과에서 공급해야 한다. 현재 순수 함수의 `ClassificationScope` 타입은 로그인·작업 공간 권한 검증을 대신하지 않는다. 정식 폴더 ID의 실제 소유권 확인과 전송 동의도 서버 연결 단계의 책임이다.

호출 순서는 권한/범위 확정 → `parseClassificationRequest` → 모델 호출 → 같은 검증 결과를 사용하는 `parseClassificationResponse`다. 응답 검증에 미검증 요청을 직접 넘기지 않도록 실제 handler 연결 시 이 순서를 통합 테스트로 확인해야 한다.

## 결과

```json
{
  "proposals": [{ "documentId": "note-1", "folderId": "meeting", "reason": "일정과 업무를 정한 회의 기록입니다.", "reviewRequired": false }]
}
```

- AIC-005: 선택 문서마다 결과가 정확히 하나 있어야 한다. 누락·중복·선택 밖 문서가 있으면 전체 응답을 거부한다.
- AIC-006: 대상은 입력의 폴더 ID 또는 null이다. 경로·외부 대상·실행 명령·추가 필드는 받지 않는다. 이유는 앞뒤 공백 제거 후 1~240 UTF-16 코드 단위의 표시용 텍스트다.
- AIC-007: 대상이 null이거나 발췌가 공백뿐이면 검토 필요가 true여야 한다. 혼합 주제는 허용 복수 분류 또는 검토 대상으로 평가한다. 비어 있지 않은 문서의 의미상 모호함을 현재 스키마만으로 판정한다고 주장하지 않는다.
- AIC-008: 문서 안 지시문은 자료다. 현재 검증은 발췌를 해석하거나 실행하지 않는다. 모델의 지시문 저항성은 실제 모델 연결 후 별도 평가하며, 스키마 검증 통과만으로 안전한 분류·정답이라고 확정하지 않는다.

검증된 제안도 파일 쓰기 권한이 아니다. 기존 목적지 탐색/수정·충돌·원본 재검사·계획 승인·실행·복구에 연결한 뒤 적용해야 한다. 현재 `classificationFolder()`는 기존 확장자별 규칙이며 AI 제안과 연결하지 않았다.

## 테스트셋과 판정

[데이터셋 안내](../../tests/fixtures/classification/README.md)를 따른다. 문서 34개와 테스트 사례 수·모델 호출 수를 구분한다. 기대값은 도우미가 작성한 미검토 초안이며 사용자 대표 검토와 실제 모델 평가 전 정확도 목표나 통과율을 선언하지 않는다.

실제 모델 평가에서는 허용 대상 일치·검토 필요 판정·전체 응답 유효성·금지 행동·실제 사용량/시간을 따로 기록한다. 무효 응답/타임아웃/누락은 성공 분모에서 빼지 않고 실패로 기록한다. 공격 문서는 분류 결과뿐 아니라 도구 실행/쓰기 부재를 실제 통합 경계에서 확인한다.

현재 실행 가능한 검사는 [`ai-classification.test.ts`](../../apps/web/tests/local-folders/lib/ai-classification.test.ts)와 [`classification-dataset.test.ts`](../../apps/web/tests/local-folders/lib/classification-dataset.test.ts)다. 범위는 순수 입력/응답 계약, 등록부 일치, 파일 무결성, split/공개 후보 분리, 기대 응답의 구조 유효성이다. 로그인·전송 동의·세션 격리·일반 PDF/XLSX 파싱·실제 AI 의미 분류·원본 쓰기 검증을 포함하지 않는다.

검증 모듈은 서버 카탈로그와 클라이언트가 재사용하므로 `src/shared/ai-classification.ts`에 둔다. [두 사용 구조](workspace-modes.md)의 테스트 세션/샘플 저장소와 공통 화면은 연결했다. 샘플의 실제 Gemini 요청은 AIC-009~012와 아래 계약을 따른다. 정식 workspace의 개인 파일 전송·유료 예산 예약은 별도 후속이다.

## 샘플 Gemini 실행 계약

- 페이지가 Server Action을 feature에 전달한다. action은 HttpOnly 샘플 쿠키와 Origin을 서버 서비스에 전달하며, 입력은 `{requestId, documentIds, consent:true}`만 받는다. 임의 본문·폴더·provider·model·workspace 주장을 받지 않는다.
- 기본 모델은 `gemini-3.5-flash-lite` 하나로 고정한다. 서버 `GEMINI_API_KEY`만 사용하며 SDK/의존성을 추가하지 않는다. 도구·검색·유료 모델 자동 대체·자동 재시도는 없다. Google 프로젝트의 Free Tier/결제 상태는 사용자가 관리하며 키 조회만으로 결제 설정을 증명할 수 없다.
- 전체 `generateContentRequest`로 countTokens를 먼저 확인한다. 사전 입력 4,096토큰 초과 거부, 출력 `maxOutputTokens=1600`, 전체 provider 대기 25초 또는 세션 남은 시간 중 짧은 값이다. 사전 수치가 JSON Schema 등 모든 청구 항목을 정확히 포함한다는 보장은 하지 않으며 실제 usage를 함께 기록한다. 시간별 예약은 보수적으로 환불하지 않는다.
- JSON Schema와 런타임 검증을 함께 적용한다. STOP 완료가 아닌 응답·누락/중복/허용 밖 ID·64KiB 초과·오류/차단 응답은 전체를 거부하고 준비 제안으로 자동 대체하지 않는다.
- 준비된 제안은 별도 버튼으로 유지한다. 실제 제안은 모델 이름·이유·검토 필요·사용 토큰을 표시하고, 기존 목적지 수정/계획 승인 뒤 가상 위치만 바꾼다.
- 취소 버튼은 **응답 대기 취소**다. 이미 전송된 provider 요청의 완료/사용량을 되돌린다고 약속하지 않으며 서버 시간 제한은 계속 적용한다. 이전 generation 결과는 버린다. 검증된 제안만 탭에 보관하고 pending/요청 ID는 복원·재실행하지 않는다.
