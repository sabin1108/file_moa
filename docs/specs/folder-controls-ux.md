# 목적지 선택·새로고침 UX 수정 — 2026-10-30

사용자는 목적지의 `연결 폴더` 버튼 의미와 선택 확정 동작이 불명확하고, 파일 목록 새로고침 아이콘이 깨져 보이며 클릭 때 화면이 흔들린다고 지적했다. 기존 읽기 전용 계획·팔레트·서체·작업 화면 구조를 유지한다.

- PICK-UX-001: 목적지 탐색 중에는 계획 입력과 생성 조작을 숨겨 탐색에 집중한다. 닫기·취소는 유지하며 입력값과 선택 수명은 기존 계약을 따른다.
- PICK-UX-002: 의미가 모호한 `연결 폴더` 독립 버튼을 제거한다. 최상위에서는 폴더 이름을 현재 위치로 표시하고, 하위에서는 경로의 최상위 이름으로 돌아갈 수 있다. `상위 폴더`는 하위에 있을 때 제공한다. 없는 경로에서도 최상위 복귀가 가능하다.
- PICK-UX-003: 확인한 현재 폴더 이름과 `이 폴더를 목적지로 선택`을 목록 위의 한 주 동작에 함께 표시한다. 긴 이름은 줄바꿈하며 390px에서도 버튼이 보인다. 로딩·실패·이전 목록에서는 선택 불가. 선택 후 상대 경로와 입력 초점을 복원한다.
- REFRESH-UX-001: 새로고침 아이콘은 24×24 viewBox 안의 끊김 없는 원형 화살표로 표시한다. 조작은 같은 44px 위치에서 새로고침↔읽기 취소로 바뀌며 추가 버튼으로 toolbar를 밀지 않는다.
- REFRESH-UX-002: 정상 목록의 동일 경로 갱신 중 기존 파일·선택·검색·스크롤을 유지한다. 목록 위에 새 안내 블록을 끼우지 않고 기존 항목 수 자리에 `갱신 중`을 표시한다. 반복 갱신의 파일 행/toolbar 위치 변화는 1px 이내, 콘솔 오류는 0이어야 한다. 데이터 변경으로 행 수가 달라지는 경우는 별도다.
- REFRESH-UX-003: 최초 읽기와 다른 폴더 탐색은 기존 로딩 안내를 유지한다. 취소·읽기 실패·권한 상실·일부 목록 경고를 숨기지 않는다. 초점 복구가 필요해도 스크롤을 강제로 움직이지 않는다.

검증: 기존 controller 회귀를 유지하며, 명세를 브라우저 검사에 먼저 추가해 이전 구현에서 실패함을 기록한다. 동일 합성 폴더로 390/768/1440/1920px 표시·키보드와 갱신 좌표를 측정하고 pnpm check 및 목적지/계획/목록 회귀를 실행한다. 동일 production 조건의 6경로 성능 원자료와 상호작용 좌표는 구분해 기록한다. 새 의존성·원본 쓰기·로그인은 추가하지 않는다.
