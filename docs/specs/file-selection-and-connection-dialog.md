# 파일 다중 선택과 연결 관리 팝업

2026-10-28 사용자 요청: 다음 기능 구현, 설정 아이콘으로 여는 연결 관리 팝업, 필요한 곳에 절제한 transition/box-shadow. 기존 minimalist-ui·팔레트·파일 탐색 구성을 유지한다. 원본 쓰기와 외부 전송은 구현하지 않는다.

## 사용자 결과와 수명 계약

후속 UI: [VIEW-001~003](file-browser-navigation.md)에 따라 기본 checkbox/선택 도구는 접는다. `선택`으로 펼치고 `선택 완료`로 접어도 선택을 유지한다. 연결 관리는 동일 accessible name의 compact 설정 아이콘으로 제공한다. 브라우저 방문 기록 복원은 이전 방문의 선택을 실제 목록과 대조해 복구한다.

2026-10-29 검색 확장: [SEARCH-001~006](file-name-search.md). 검색 밖 기존 선택은 유지한다. 아래 ‘표시된 파일’은 검색 후 보이는 파일이며 전체 선택 checkbox 해제는 표시 파일만, 별도 ‘선택 해제’ 버튼은 모든 선택을 비운다.

| ID | Given / When / Then |
| --- | --- |
| SELECT-001 | 현재 폴더의 조회 성공 목록에서 파일 체크 → 그 파일 선택/해제. 확장자는 제한하지 않고 폴더는 선택하지 않는다. 미리보기 버튼과 checkbox는 별도 조작이다. |
| SELECT-002 | 표시된 파일 전체 선택 → 표시된 파일만 선택. 일부 선택은 전체 checkbox의 indeterminate. 1,000개 제한 목록은 ‘표시된 파일’ 범위를 명시하며 재귀 탐색하지 않는다. |
| SELECT-003 | 선택 개수는 상태로부터 계산. 선택 해제는 모두 비움. 본문 읽기·권한 요청·쓰기·전송을 유발하지 않는다. |
| SELECT-004 | 미리보기 열기/닫기, 동일 Provider 내 화면 왕복 → 선택 보존. 하위/상위 폴더로 이동 시도 → 즉시 초기화(실패하더라도 이전 선택이 새 경로에 적용되지 않음). |
| SELECT-005 | 같은 폴더 새로고침 성공 → 목록에 남아 있는 파일만 선택 유지. 실패·읽기 취소·권한 상실 → 이전 선택 유지하되 새 선택/전체 선택 차단, 전체 해제는 허용. |
| SELECT-006 | 연결 교체 성공(같은 이름 포함)·해제 시작·소유자 교체/종료 → 선택 초기화. 교체 취소/실패는 이전 선택 보존하되 재조회 전 선택 변경 차단. 재연결은 같은 폴더 재조회 후 유효 선택 유지. |
| DIALOG-001 | 파일 화면의 설정 아이콘+‘폴더 연결 관리’ 버튼 → native modal dialog. 설정 화면의 기존 연결 조작과 동일 컴포넌트를 사용한다. 자동 팝업 없음. |
| DIALOG-002 | 열린 팝업에 이름·닫기 버튼 제공. 배경 조작 차단, Tab 이동은 팝업 안, Escape/닫기로 종료, 초점은 시작 버튼으로 복귀. 바깥 클릭은 닫지 않는다(실수로 권한/오류 상태를 숨기지 않음). |
| DIALOG-003 | 팝업에서 연결/재연결 성공 → 닫고 기존 /files에서 목록 표시. 취소/실패/해제는 팝업 유지. 진행 중에도 닫을 수 있으나 진행 중 작업을 취소했다는 의미가 아니다. 닫은 후 늦은 완료가 다시 팝업을 열거나 화면을 이동시키지 않는다. |
| DIALOG-004 | 재연결 필요/해제 실패는 팝업 밖 연결 관리 옆에 짧은 상태 표시. 팝업을 닫아도 문제를 숨기지 않는다. |
| DIALOG-005 | 팝업 열림은 짧은 opacity/작은 이동, 배경은 약한 dim, 그림자는 팝업에만 사용. 선택 강조는 색/테두리 전환만. reduced-motion이면 효과 없음. 애니메이션을 위해 작업/초점/닫기를 지연하지 않는다. |

선택은 현재 폴더 범위의 메모리 상태이며 페이지 새로고침/전체 브라우저 종료 뒤 복원하지 않는다. 상한이 있는 목록의 재조회에서 빠진 선택은 현재 표시 범위에서만 제외하며 원본 삭제로 판정하지 않는다. 사용자가 팝업을 직접 닫았으면 늦은 성공·실패가 다시 열지 않는다. ‘실패 시 유지’는 아직 열린 팝업에만 적용한다. 초기 초점은 실행 버튼이 아닌 제목에 둔다. 고정된 연결 관리 버튼은 파일 화면 수명 동안 유지한다.

AI 참고 자료 선택·실제 원본 이동/복사는 별도 계약이다. 2026-10-29 읽기 전용 이동/복사/확장자 분류 계획은 [PLAN-001~008](file-change-plan.md)으로 구현했다. 선택 경로는 현재 목록 path + 선택된 파일 이름으로 해석하며 OS 절대 경로·핸들을 UI에 전달하지 않는다.

기본 모달 동작은 [HTML dialog 표준](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element)을 따른다. 시작 전환은 [CSS starting-style](https://developer.mozilla.org/en-US/docs/Web/CSS/@starting-style)의 점진적 향상이며 지원하지 않으면 즉시 표시한다. exit 애니메이션용 overlay/display 지원에 의존하지 않는다.

## 구현과 검증 계획

1. 선택의 경계·실패 테스트를 추가하고 red 확인. 기존 listing controller가 현재 경로와 함께 선택을 소유하도록 확장한다. 별도의 선택 저장소나 중복 경로 상태는 만들지 않는다.
2. checkbox/전체 선택·개수 표시는 UI에서 조합한다. checkbox와 미리보기 button의 중첩을 금지한다. 파일 내용·권한 접근 로직은 변경하지 않는다.
3. 연결 관리 전용 dialog 컴포넌트는 열림/닫힘/초점을 소유하고 기존 SourceFolderSettings를 재사용한다. 라우팅 결과와 dialog 완료 callback을 구분한다.
4. 단위 실패 경계, 실제 브라우저 선택/팝업/키보드/재연결/지연 응답, 기존 목록/미리보기/연결/이동 회귀, 390/768/1440/1920px, 100/1,000개 표시 선택 비용, reduced-motion, type/lint/build 및 경계 검사를 확인한다.

화면의 질문은 ‘현재 폴더에서 어떤 파일을 정리 대상으로 고를까’이다. 파일명과 체크가 주요 내용이며 연결 설정은 보조 팝업으로 물러난다. 기존 스타일을 유지하므로 새로운 스타일 추첨/전면 재설계는 하지 않는다. 실제 자료는 연결한 폴더의 직계 항목이며 검증에는 격리된 합성 OPFS만 사용한다.
