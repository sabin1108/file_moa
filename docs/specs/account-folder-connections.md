# 계정별 로컬 폴더 연결 — LOCAL-008 기반

2026-10-25. 최초 구현 범위는 브라우저 핸들 저장소와 연결 수명주기다. OAuth/서버 세션/제품 화면 연결은 미완료이며 아래 가상 A/B 검증은 실제 로그인 검증을 대신하지 않는다.

- 인증 계층이 확인한 내부 userId/workspaceId를 주입한다. URL·문서 내용·임의 폼 입력으로 현재 계정을 설정하지 않는다.
- 장치별 IndexedDB 키는 `[userId, workspaceId, source|ai-records]`의 구조화 배열이다. 문자열 구분자 조합으로 다른 계정 키가 충돌하지 않도록 한다. 폴더 핸들만 저장하며 서버 전송·절대 경로·대화 본문·비밀키는 저장하지 않는다.
- 한 작업 공간당 자료 폴더와 AI 기록 폴더 각 1개를 다루는 첫 단계다. 다중 자료 폴더 UI는 후속 확장이다.
- 로그인/계정 전환은 메모리 연결을 즉시 비우고 세대 번호를 올린다. 저장 핸들을 읽어도 자동 권한 요청/파일 열기는 하지 않는다. 명시적 재연결 클릭이 필요하다.
- source는 read만, ai-records는 readwrite 권한을 요청한다. 권한 요청 전 IndexedDB 읽기를 기다리지 않고 미리 준비된 핸들을 사용한다.
- 늦게 끝난 A의 핸들 조회·picker·권한 응답은 B의 화면/활성 연결로 반영하지 않는다. 새 폴더 선택과 재연결·연결 해제 사이의 오래된 응답도 거부한다.
- 연결 해제는 해당 계정·종류의 IndexedDB 참조만 제거한다. 폴더/기록 삭제나 브라우저 권한 철회가 아니다. 해제 시작 즉시 메모리 연결은 중지한다. 저장소 제거 실패는 오류를 반환해 사용자에게 재시도 필요를 알린다.
- 이미 시작된 IndexedDB 저장은 원래 A의 키에서 완료될 수 있다. 계정 변경 후 B의 키에 쓰거나 B로 활성화하지 않는다. 이미 시작된 OS I/O를 취소하거나 다른 origin/외부 앱의 접근을 막는 기능은 아니다.
- 같은 계정·작업 공간·종류의 참조 저장/제거는 IndexedDB를 열기 전 Web Lock으로 직렬화한다. 저장 직후 해제 요청이 온 경우 이전 저장이 나중에 완료되어 참조를 되살리지 않도록 한다. 이 잠금은 UI의 다른 탭 로그인 상태 동기화를 구현한 것이 아니다.
- 같은 origin의 악성 스크립트나 같은 OS 사용자를 격리하는 보안 장치가 아니다. 실제 인증·로그아웃 시 작업 취소·다른 탭 동기화와 함께 제품에 연결하기 전 완료로 보고하지 않는다.

검증: 가상 A/B 및 작업 공간 분리, 준비 시 권한 요청 없음, 늦은 A 조회/권한/picker 결과 거부, 연결 해제 중 응답 거부, 취소 시 기존 연결 보존, 쓰기 실패 시 미게시, read/readwrite 구분, 실제 브라우저 IndexedDB structured clone과 해당 키만 삭제.
