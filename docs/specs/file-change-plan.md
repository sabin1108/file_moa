# 선택 파일의 읽기 전용 변경 계획

2026-10-29. 어제 인수인계의 다음 구현 단위. FILE-001 중 선택→계획→검토→취소를 구현한다. 원본 적용은 포함하지 않는다.

후속: 목적지 상대 경로는 직접 입력하거나 폴더에서 선택한다. 탐색 수명·취소·권한·부분 목록과 경고 색상 계약은 [목적지 선택 명세](plan-destination-picker.md)를 따른다.

2026-10-30 후속: 계획 생성 자체는 이름만 읽는 아래 계약을 유지한다. 충돌 없는 복사 계획에서 명시적으로 누르는 [복사 전 검사](copy-inspection.md)를 별도로 제공하며, 이 동작만 파일 크기·내용 hash를 읽는다. 실제 복사·쓰기 권한·영구 기록은 아직 없다.

## 사용자 흐름과 계약

- PLAN-001: 현재 폴더에서 선택한 파일로 `변경 계획 검토`를 연다. 선택 없음·목록 갱신 중·오래된 목록·연결 불가에는 열 수 없다. 폴더 자체는 대상이 아니다.
- PLAN-002: 이동·복사·분류와 연결 폴더 기준 목적지 상대 경로를 입력한다. 빈 경로는 연결 루트다. `/`로 구분하며 절대 경로, 역슬래시, 빈 조각, `.`/`..`, 제어 문자를 거부한다. 목적지 기본 폴더는 존재해야 한다. 입력 변경은 이전 결과/요청을 즉시 무효화한다.
- PLAN-003: 이동은 원본 위치에서 목적지로, 복사는 원본을 유지하고 목적지에 같은 이름으로 생성하는 예상 결과를 표시한다. 분류는 **확장자별 이동 제안**이다. `.md`→`마크다운`, `.txt`→`텍스트`, 나머지→`기타`(대소문자 무관). AI 추론·본문 읽기가 아니다. 목적지 아래 해당 분류 폴더가 없으면 생성 예정으로만 표시한다. 실제 생성하지 않는다.
- PLAN-004: 생성 요청마다 출발 목록과 목적지 목록을 읽기 권한으로 재확인한다. 선택 파일이 없거나 폴더로 바뀌면 실패하고 목록 새로고침을 안내한다. 목적지의 동일 이름 파일/폴더, 같은 출발·도착, NFC/대소문자를 무시하면 같은 이름인 잠재 충돌, 중복 도착, 분류 폴더 자리를 차지한 파일을 표시한다. 덮어쓰기/자동 이름 변경은 하지 않는다.
- PLAN-005: 목적지 1,000개 상한에 걸리면 확인된 충돌은 표시하되 나머지도 `전체 확인 필요`로 표시한다. 일부 목록에서 미발견을 빈 위치로 확정하지 않는다. 분류 폴더의 존재 여부가 부모의 일부 목록에서 확인되지 않으면 생성 예정으로 단정하지 않는다. 다른 파일시스템의 이름 비교 규칙을 보증하지 않는다.
- PLAN-006: 결과는 파일별 출발/도착/문제, 대상 수·문제 있는 파일 수, 생성 예정 폴더를 보여준다. 충돌이 없어도 적용 가능 인증이 아니며 `검토용 계획 · 원본 변경 없음`을 표시한다. 실제 실행 버튼·쓰기 권한 요청·본문 읽기·업로드·계획 영구 저장은 없다.
- PLAN-007: 취소/닫기/Escape는 진행 중 읽기를 중단하고 늦은 결과를 버린다. 선택은 유지하며 버튼 초점을 복구한다. 계획 중 목록·선택·연결·소유자 상태가 바뀌면 계획을 닫고 폐기한다. 경로 이탈은 계획을 닫으며 기존 파일 선택의 경로 왕복 보존 계약은 유지한다.
- PLAN-008: 읽기 권한 상실은 공통 연결 상태에도 반영한다. 없는 목적지·일반 읽기 오류는 입력/선택을 유지해 수정 후 재시도할 수 있다. 파일 본문/hash/size는 확인하지 않으며 검토 후 외부 변경은 자동 감지하지 못한다. 실제 적용 전 검증은 별도 단계다.

## 구현 책임과 화면 기준

순수 이름/경로/계획 규칙은 local-folders/lib, 요청·취소·연결 수명은 store의 별도 계획 controller, 브라우저 읽기는 기존 session/listSourceFolder를 재사용한다. 목록 controller는 선택만 소유한다. UI는 선택 도구의 진입 버튼, native dialog의 입력/검토 화면으로 분리한다. 기존 공통 버튼·CSS 토큰·팔레트·achromatic-ledger 구성을 유지한다.

화면의 질문은 “선택한 파일을 어디로 옮기거나 복사하며 무엇이 충돌하는가?”다. 실제 선택 이름과 상대 경로가 중심이며 합성 자료는 검증에서만 주입한다. 최대 1,000개 파일, 분류 3종, 목적지 목록 최대 4개를 순서대로 읽는다. 390/768/1440/1920px에서 행은 줄바꿈하고 dialog 내부만 세로 스크롤한다. native select/input과 명시적 버튼을 사용해 IME Enter로 자동 제출하지 않는다.

## 검증과 완료 조건

명세→실패 테스트→구현→통과. 합성 고정 core(무작위 seed 없음)로 성공/충돌/잘못된 경로/부분 목록을 검증한다. 별도 controller tests는 실제 목록 store와 합성 비동기 reader를 사용해 선택·소유자 변경·취소·늦은 결과를 검증한다. 브라우저는 실제 UI/session/IndexedDB/Web Locks/OPFS와 합성 picker/권한을 연결하고 sentinel 원본 무변경, 요청 모드, 본문 읽기0, 외부 전송0을 확인한다. holdout은 구현자가 작성한 core와 분리된 경계 재검토로 기록하며 독립 사용자 평가라고 부르지 않는다.

pnpm check와 관련 선택/연결/미리보기 회귀, 키보드/초점·좁은 화면·합성 IME, 동일 production 조건의 6경로×3회 desktop/390px 전후 측정을 실행한다. 신규 계획 생성 시간과 100/1,000개 규모 비용은 별도 기록하며 field INP로 해석하지 않는다. 실제 OS 선택창·OS IME·실제 디스크 권한·인증·원본 적용은 미검증/미구현으로 남긴다.
