# 대화 중심 자료 정리 개편안

## 2026-11-17 — 파일 확인과 공통·개별 지정

- CF-011: 정리 범위·참고·목적지 picker는 기존 목록 읽기를 재사용해 현재 폴더의 파일명도 표시한다. 파일 본문 읽기·전송·쓰기와 폴더 선택은 분리한다. 목록 상한/읽기 실패/권한/취소 처리는 유지한다.
- CF-012: 확인 자료는 파일명과 지정 상태의 간단한 행으로 먼저 표시한다. 공통 목적지는 제외하지 않은 목적지 질문 자료에 한 번에 지정하고, 개별 지정으로 예외를 정한다. 원인·날짜 근거·발췌·제외는 해당 파일 행에서 확인한다. 날짜 답변은 그 파일의 실제 근거를 사용한다.
- CF-013: 목적지는 기존 폴더 picker로 고르며 최종 목적지 하위의 상대 경로로 변환·검증한다. 새 하위 경로는 명확한 경로 입력으로 지정할 수 있지만 이 조작은 원본 파일/폴더를 만들거나 옮기지 않는다. 경로 검증과 기존 변경 계획/실행 승인은 유지한다. 여러 답변은 함께 검증하며 기존 날짜 답변과 제외 상태를 보존한다.
- CF-014: 범위 조건, 확인 질문, 전송 확인, 변경 계획을 동시에 표시하지 않는다. 질문에서 지정을 마친 후 명시적 다음으로 전송 확인에 들어간다. 새 동의와 명시 전송을 거치며 이전 제안/동의는 답변 변경 시 무효화한다. 공통 Stepper는 표시만 맡고 실제 상태/실행 권한은 controller/기존 엔진이 소유한다.

이번 실행 결과와 이전 실패/검증 한계는 [정리 UX 검증](../verification/organization-ux-20261117/README.md)을 따른다. 아래 과거 흐름은 당시 기록으로 보존한다.

## CF-003 실제 채팅 답변 연결 — 2026-11-08

질문이 생성되면 공통 입력창은 별도 답변 초안을 사용한다. 예: ‘검토 기준일로 하고, 혼합자료는 학습 폴더로’. 이름/상대 경로는 현재 질문의 문서에서, 날짜와 의미는 실제 발췌 후보에서 하나로 정할 때만 반영한다. 목적지는 문서 이름을 명시하고, 공백이 있는 폴더 이름은 따옴표로 감싼다. 문서 제외와 날짜로 나누지 않기도 지원한다. 답변 문장은 로컬의 제한된 표현 해석이며 일반 자유 대화 이해나 모델 호출이 아니다.

입력만으로 기존 요청/자료/동의는 변하지 않는다. 제출한 모든 절을 해석·검증한 뒤 함께 반영한다. 하나라도 애매하거나 모순·부정·미지원 표현/경로가 있으면 기존 답변을 보존한다. 답변 확정 시 기존 제안/동의를 폐기하고 새 동의·명시 전송을 거친다. 초기 요청 수정은 조건 영역의 명시 행동으로 전환한다. 초안/확정 문장은 Provider가 소유하고 조건·선택 변경/취소/계정 초기화 때 폐기한다. 전송 중 답변 제출은 차단한다.

[구현·검증·지원 범위](../verification/organization-reply/README.md), [실제 호출 순서](../reports/organization-reply-reading.md). 아래 ‘자연어 답변 후속’ 문구는 이 단위 전 상태다. 실제 Windows 전체 여정은 여전히 미검증이다.

최신 적용(2026-11-08): 사용자의 긍정 피드백과 실제 적용 요청 후 정식 채팅의 질문/전송 확인/제안/검토를 대화로 옮기고 일반 복사·이동과 비교 표시를 공유했다. [구현·검증·한계](../verification/chat-first-live/README.md). CF-003의 자유로운 자연어 답변 해석은 후속이며 기존 검증된 답변 컨트롤을 사용한다. 아래 범위는 초기 시안 단계 기록이다.

2026-11-08. 사용자 실제 사용 피드백: 읽을 정보가 많고, 토큰 등 기술 정보와 긴 자료 창을 스크롤해야 하며, 정리될 모습을 볼 수 없다. 채팅보다 오른쪽 창이 주가 된 느낌이다. 기능 검증 결과와 사용하기 쉬운 화면이라는 평가는 구별한다.

## 범위

이번 단위는 기존 기능의 책임을 확인하고, 대화 중심 흐름의 설계와 분리된 시안을 만든다. 실제 채팅 경로 교체·모델 호출·파일 쓰기는 수행하지 않는다. 사용자 요청의 전면 개편 방향은 반영하되 이 시안을 실제 기능 구현 완료로 보고하지 않는다. 기존 실제 검증은 첫 응답의 확인 필요2개까지 사용자 보고가 있으며, 답변 재전송/실행/복구와 물리 한글 입력은 미완료다.

## 관측한 원인

- `LiveConversation`은 요청 제출 때 `setPanelOpen(true)`로 자료 창을 연다. 대화에는 현재 요청과 상태 문구를 합성해 보여 준다.
- `OrganizationPreparationPanel`은 조건, 질문, 원본 발췌, 전송 확인, 제안과 실행을 같은 세로 흐름에 합친다. 현재 해야 할 일과 이미 본 정보의 구분이 약하다.
- `ConversationWorkspace`의 메시지는 텍스트다. 실제 질문/답변과 변경 제안은 별도 dialog 안에 있어 대화에서 결정을 이어갈 수 없다.
- 결과의 경로 문자열은 있어도 현재 폴더와 정리 후 구조를 함께 보여 주지 않는다.

## 새 흐름과 수용 기준

1. CF-001: 요청·진행·질문·답변·변경 미리보기가 대화의 같은 흐름에 있다. 오른쪽 자료 창은 필요할 때 여는 참고 영역이며 필수 조작을 독점하지 않는다.
2. CF-002: 연결한 범위와 후보 수를 짧게 표시한다. 불명확한 범위만 확인하고 이미 선택한 조건/답변을 반복해서 요구하지 않는다.
3. CF-003: 현재 결정할 질문을 먼저 보여 준다. 관련 질문은 한 번에 답할 수 있고 지난 결정은 짧은 요약으로 접는다. 선택지와 자연어 답변은 동일한 검증된 답변 상태로 연결하는 것이 실제 구현의 목표다. 시안은 선택지로 흐름을 검토한다.
4. CF-004: 전송 전에 대상·보내는 내용·외부 서비스·동작을 한곳에서 확인한다. 후보 상세를 열지 않아도 핵심 전송 사실은 보인다. 명시 동의/전송 직전 원본 재검사/조건 변경 시 무효화는 유지한다. 보안 확인을 없애는 방식으로 클릭 수를 줄이지 않는다.
5. CF-005: 토큰 수·해시·수정 시각·모델 상세·상한 정책은 ‘상세’로 옮긴다. 한도/실패/권한처럼 현재 판단에 필요한 문제는 해당 행동 옆에 표시한다.
6. CF-006: 현재 구조와 제안 도착 구조를 나란히 보여 준다. 복사는 남는 원본, 이동은 옮겨지는 원본을 실제 선택에 맞춰 표시한다. 새로 만들 폴더와 파일별 도착 경로를 함께 확인한다.
7. CF-007: 복사/보존 후 이동은 사용자가 고른다. 조건 수정→이전 승인 폐기→공통 검사→최종 실행→결과/복구를 유지한다. 자동 전송/자동 쓰기/완료처럼 보이는 거짓 시뮬레이션은 없다.
8. CF-008: 지금 필요한 기본 행동은 한곳에 둔다. 기본 행동을 찾으려고 자료 창의 맨 아래로 이동할 필요가 없어야 한다. 상세는 사용자가 열고 닫으며 대화/초안/결정은 보존한다.
9. CF-009: 390/768/1440/1920px에서 확인한다. 모바일은 같은 결정 흐름을 한 열로 제공하고 모든 조작은 키보드 이름과44px 이상 누름 영역을 갖는다. 색만으로 변경을 구분하지 않는다.
10. CF-010: ‘질문에 답하는 중/제안 검토/원본 검사/실행/부분 실패/복구’를 구별한다. 모델 결과를 실제 파일 변경 결과처럼 표시하지 않는다.

## 재사용과 실제 기능 연결 순서

공통 메뉴·브랜드·버튼·아이콘·서체/색/간격 토큰은 유지한다. 새 스킨이나 범용 컴포넌트 계층을 만들지 않는다. 기존 preparation controller의 snapshot/questions/answers/consent와 execution controller의 batches/outcomes가 상태 소유자다. 표시 위치를 대화로 옮겨도 서버/로컬 경계를 복제하지 않는다.

실제 기능 연결은 메시지에 안전한 상호작용 영역 추가 → 질문/대상 확인 표시 이전 → 실제 proposal에서 현재/도착 구조 투영 → 기존 managed 검토/실행 연결 순서다. 자연어 답변의 문서/날짜/목적지 연결, 취소/뒤로/늦은 응답, 동의 폐기, 원본 변경, 부분 실패를 기존 실패 테스트에 추가한다. 시안의 선택 결과를 실제 AI 파싱이 구현된 근거로 삼지 않는다.

## 시안의 정직한 경계

`/preview/screens/chat-first`는 이미 준비된 합성 두 파일과 예시 도착 경로로 화면만 검토한다. 예시 경로는 사용자의 실제 AI 응답이 아니다. 대화 입력은 작성할 수 있지만 AI로 전송하지 않는다. 실제 실행 버튼은 비활성이고 이유를 표시한다. 실제 폴더/계정/보관함 상태를 읽지 않는다.
