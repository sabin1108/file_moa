# 미확인 생성 작업의 현재 대상 확인

2026-10-31. 사용자가 작업 기록 조회 다음 단계 진행을 요청했다. 이번 단위는 기록과 현재 존재/종류의 읽기 전용 대조다.

- TARGET-001: 결과 미확인이고 경로/종류가 일관된 행에 `현재 상태 확인`을 제공한다. 자동 실행하지 않는다. 기록 완료/실패를 변경하거나 자동 재생성/덮어쓰기/삭제/복구하지 않는다. 조회 시각과 현재 존재/없음/종류 다름을 기록 상태와 분리한다. 존재는 생성 주체·작업 성공을 증명하지 않는다. 없음은 과거 생성 실패나 삭제를 증명하지 않는다.
- TARGET-002: session이 현재 owner/root/연결 세대와 AbortSignal을 확인한다. reader는 현재 폴더의 기록을 다시 읽어 동일 ID·경로·종류·상태·시각·개수인지 확인한다. 기록이 바뀌거나 사라지거나 더 이상 미확인이 아니면 대상 접근 없이 새로고침을 안내한다. 현재 부모 직접 자식만 접근한다. 경로 또는 종류 충돌 기록은 버튼 대신 확인 불가 이유를 표시한다.
- TARGET-003: root 읽기 권한을 확인하고 부모를 다시 연다. directory/file handle의 create:false 조회로 존재와 종류만 대조한다. 대상 파일의 getFile/본문/hash, 대상 폴더 열거/재귀, requestPermission, writable, 삭제, journal 쓰기, 외부 전송은 없다. 기록 JSON 읽기에는 기존 HISTORY 한도를 적용한다.
- TARGET-004: 같은 부모/대상을 한 번 더 열어 isSameEntry로 교체를 감지하고 마지막 읽기 권한/연결을 확인한다. 둘 다 없는 경우에만 현재 없음, 종류/핸들/존재가 달라지면 확인 중 변경 오류다. 부모 없음/부모 교체/읽기 거부는 대상 없음으로 표시하지 않는다. 이 API는 원자적 스냅샷을 제공하지 않으므로 확인 직후의 외부 변경은 보장하지 않는다.
- TARGET-005: 팝업에서 한 항목씩 확인한다. 다른 항목을 누르면 이전 요청/결과를 폐기하고 해당 행에 현재 결과를 표시한다. 닫기/취소/기록 새로고침/연결·위치 변경도 진행 중 확인을 폐기한다. 오래된 성공/실패 응답을 표시하지 않는다. 기록 목록/선택/검색은 보존한다.
- TARGET-006: 새로고침·앱 재접속 뒤 사용자가 다시 폴더를 연결하고 기록을 열어 같은 기능을 실행할 수 있다. 자동 재연결/자동 권한 요청은 추가하지 않는다. 확인 결과는 메모리 상태이며 디스크에 저장하지 않는다.

구현 순서: 명세 → 존재/없음/종류 충돌/기록 변경/권한/취소/교체/무쓰기 실패 테스트 → reader/session → 기존 history controller 수명 확장 → 행 표시 → 단위·타입·lint·경계·build·OPFS 브라우저·성능 비교. 기존 UI 토큰/native dialog를 재사용하며 의존성을 추가하지 않는다.
