# 반복 확인 피드백·파일 코드 가독성 — 2026-11-03

사용자가 앞선 작업 완료 뒤 목적지 새로 만들기 구획, 계획 재확인/검사 완료의 지나치게 짧은 깜빡임,타입/any/재사용 점검,사람이 읽기 쉬운 선언·if·try 문단을 요청했다. Zod 적용이 적합하면 허용하고 필요성1~2줄을 요구사항에 기록하도록 했다.

## 동작 계약

- FEEDBACK-001: 목적지의 현재 폴더 확정/새 항목 생성/하위 폴더 탐색을 구획한다. 생성은 별도 테두리와 배경, 하위 폴더는 제목/구분선. 각 현재 위치와 쓰기 권한 계약을 유지한다.
- FEEDBACK-002: 계획 생성/재확인의 로딩 표시는 최소360ms 유지한다. 읽기는 즉시 시작하고 원래 읽기가 오래 걸리면 추가360ms를 더하지 않는다. 재확인 중 이전 계획 DOM/영역을 유지하되 재확인 중임을 알리고 복사 전 검사로 진행하지 못한다. 취소/닫기/입력변경/연결변경/권한실패는 지연 없이 처리하며 늦은 완료는 무시한다.
- FEEDBACK-003: 복사 검사는 중간idle발행 없이loading으로 시작한다. 실제 성공 결과의 공개만 최소360ms 뒤로 미루고 실제 검사/쓰기 실행을 지연시키는 서비스 계약은 추가하지 않는다. 검사 중에는 성공 결과/실행 승인을 제공하지 않는다. 이후 기존 순차 체크 효과를 적용한다. 실패는 즉시 알린다.
- READABILITY-001: 아래 변경 범위에서 한 줄의 복수 선언·독립문장·if/try/catch를 구분한다. 이벤트 처리와 요청 수명에 의미 있는 빈 줄을 두며 한 파일을 기계적으로 여러 모듈로 쪼개지 않는다. 기존 동작/권한/취소 경계를 먼저 테스트로 고정한다.
- TYPE-001: 파일 기능 source의 명시적any사용을 검색하고 lint의no-explicit-any를error로 고정한다. 외부 입력은unknown과 검사로 좁힌다. 반복되는 파일 항목 선택 콜백은 기존 항목 종류 타입을 기준으로 공유한다. 타입과 값의 변환을 숨기는 광범위한cast를 추가하지 않는다.
- SCHEMA-001: Zod4.6.7을web직접 의존으로 고정하고 복구 보관함 식별JSON파서에만 좁게 적용한다. strictObject/safeParse/infer로 스키마·타입 중복을 줄이며 기존UUID문자열/정규UTC시각/추가키 거부 계약을 보존한다.8KiB·UTF-8·권한·재읽기 검증은서비스에 남긴다. 작업 기록의 순서/해시/연결 규칙을 전면 재작성하지 않는다.

## 정리 계획과 범위

현재373개 단위·283개 브라우저 회귀가 기준이다. 기능변경은 최소시간/반복검사 수명 실패 테스트를 먼저 추가한다. 코드정리는 동작변경과 구분해 변경된TS의컴파일결과/테스트를 비교한다.

대상은local-folders의이번 변경에 직접 닿는 `folder-search-controller`, `source-plan-controller`, `copy-inspection-controller`, `source-navigation-controller`, `folder-tree-search`, `pasted-folder-path`, `recovery-vault`, `use-selection-row`, 그리고계획/검사/목적지/검색/이전항목/기록 표시컴포넌트다.서비스전체·승인된채팅·과거실험화면을일괄수정하지않는다.

1. 실제로사용하지않는선택모드setter/cancelSelection과선택버튼CSS가있는지검색하고호출이없을때삭제한다.
2. 중복콜백타입/최소표시시간정책을두실제사용처에서공유한다.새범용계층은추가하지않는다.
3. 선언/조건문/예외처리/JSX속성을읽을수있게정리한다.길어진함수는의미가있는판정함수만분리한다.
4. Zod기록형식경계는기존실패/성공테스트를그대로통과해야한다.패키지추가가client경로에포함되는지도측정한다.
5. 타입/lint/단위/경계/build,반복계획/검사프레임,구획과4폭캡처,복사원본/저널회귀를검증한다.

Fallback검토:검색의일부폴더읽기실패→incomplete표시는근거있는부분결과계약이다.목적지문법오류→루트부터다시고르기는입력원문을보존하는기존명시적탐색동작이다.오류를성공으로바꾸는새fallback은추가하지않는다.작성자는정리계획을만들고별도read-only검토자가범위/실패조건을검토한다.현재App에서는tmux실행모드를시작하지않고이국소단위의검토·수정·검증을직접수행한다.
