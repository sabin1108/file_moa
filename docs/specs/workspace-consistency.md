# 작업 화면 일관성 후속

2026-11-04 사용자 요구68~72. 기존 파일 보호·권한·실행 검증은 유지하고 표시/입력/전이의 불일치를 정정한다.

## 구현 순서와 완료 조건

1. 변경 전 controller의 승인/중복 실행/취소 회귀를 유지한다. copy/move는 처음 목적지 계획 화면에서 시작하고, 목적지 선택 버튼→같은 picker→선택 확정→명시 계획 확인 순서가 되는 실패 시험을 먼저 추가한다.
2. 파일/폴더 계획의 목적지 입력·작업 선택·계획 조작·헤더와 Stepper를 공통 표시 컴포넌트로 사용한다. 파일 충돌 overwrite와 재귀 트리의 처리 계약은 각각 유지한다. 폴더 선택 직후 자동 검사를 시작하지 않는다. 선택 확정/탐색 중 여부도 F5 초안으로 복원한다.
3. 복구 보관함은 현재 연결·사본 조회/상태 확인과 연결 관리(생성/다른 기존 보관함/해제)를 구분한다. 기존 버튼 이름을 유지하고 관리 조작은 하나의 이름 있는 묶음에 둔다.
4. 미리보기/편집은 공통 문서 작업면을 사용한다. 같은 제목·도구줄·정보 접힘·본문 폭/글자/행간/안쪽 여백을 적용하고 입력만 textarea로 전환한다. 저장 상태는 같은 정보 영역에 둔다.
5. 앱의 일시적인 안내에는 닫기 버튼과5초 자동 닫기를 제공한다. 진행 중/실행 확인/작업을 막는 오류는 자동으로 지우지 않는다. 이미지의 창은 브라우저 File System Access 쓰기 권한창이므로 앱 CSS로 바꾸거나 생략하지 않는다. 기존 앱 권한 안내를 활용한다.
6. 관련 단위·브라우저/키보드·390/768/1440/1920 화면, 타입/lint/경계/build를 확인하고 경로별 성능을 기록한다. 사용자 요구/짧은 오류/상세 인수인계/코드 설명서를 갱신한다.

## 검증할 실패 조건

- 계획·목적지를 바꾸면 이전 검토로 실행할 수 없다. 목적지 미선택이면 계획 버튼 비활성.
- picker 닫기/Escape는 계획으로 돌아가고 선택했던 목적지를 유지한다. 파일/폴더·혼합 모두 같은 조작을 제공한다.
- F5 이후 목적지 확정/탐색 상태를 보관하되 쓰기 승인은 재생하지 않는다.
- 초안 편집의 첫 백업/반복 수동/주기 저장·조합·외부 변경 차단은 유지한다.
- 일시 알림 닫기는 파일 처리 상태를 바꾸지 않으며 새 안내는 다시 표시한다.5초 이후 사라지고 오류·행동 요청은 남는다.

실행 근거는 docs/verification/workspace-consistency/README.md에 기록한다. 예정된 검사를 통과로 기록하지 않는다.
