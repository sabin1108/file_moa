# 이메일 인증 화면 연결 — 2026-11-06

사용자 요청: 기존 템플릿·프로토타입을 참고하고 Stepper 재사용을 우선한다.

- 공통 `WorkflowStepper`의 표시/ARIA/CSS를 수정하지 않고 회원가입과 재설정에서 같은 컴포넌트를 사용한다. 단계 목록은 인증 기능의 데이터이며 기존 파일 작업 URL 훅에 인증 로직을 섞지 않는다.
- 기존 AuthShell/인증 CSS를 표시 책임의 공통 레이아웃으로 옮겨 실제 화면과 프로토타입이 함께 사용한다. 시안 표시는 프로토타입에만 남기며 원래 색상·배치·조작 토큰을 유지한다. 승인된 채팅/파일 디자인은 변경하지 않는다.
- `/login`, `/welcome`, `/verify-email`, `/forgot-password`, `/reset-password`, `/account`. 마지막은 서버 세션으로 확인한 계정과 로그아웃만 제공한다. 기존 개발용 폴더를 로그인 회원에게 자동 연결하지 않는다.
- 모든 폼은 Server Action → 같은 프로세스의 인증 handler를 호출한다. 자기 HTTP API에 fetch하지 않고 기존 Origin/CSRF/요청 제한을 유지한다. 응답 쿠키는 설치된 Better Auth의 공개 cookie parser/options로 Next 쿠키 저장소에 반영한다.
- 이메일 확인 메일은 동일한 Better Auth 토큰을 `/verify-email` 확인 폼으로 전달한다. 명시적 확인 후만 완료 단계를 표시한다. 재설정 링크는 기존 API callback에서 `/reset-password`로 이어진다. URL step을 바꿔 완료/인증을 만들 수 없다.
- 이름·이메일 입력만 sessionStorage에 보존한다. 비밀번호/확인·확인/재설정 token·서버 응답은 초안에 저장하지 않는다. token은 화면 메모리/hidden 제출에만 쓰고 진입 직후 URL에서 제거한다. 이 시점 이후 새로고침은 새 링크 안내로 닫힌다. 폼 제출을 새로고침/뒤로가기로 자동 재실행하지 않는다.
- AUTHUI-001 서버 입력검증/확인 비밀번호/이메일 정규화/안전한 상태 반환, 002 공통 Stepper/URL 단계 정규화/민감초안제외, 003 실제 가입→메일확인→로그인→계정→로그아웃과 쿠키, 004 재설정/만료/재사용/새로고침, 005 키보드/IME/중복제출/390·768·1440·1920px/반응형을 검사한다.
- 실제 사용자/메일/폴더에 쓰지 않고 가상 PostgreSQL·메일 수신 대체·독립 브라우저로 검증한다. UI 신규 비용과 기존 6경로의 2폭/3회 성능 회귀를 구분한다. 물리 IME/실사용 INP/운영메일·공유limiter·전체 브라우저 계정격리는 별도다.
