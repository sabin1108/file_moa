# 개인 AI 로컬 보관 계약

결정일: 2026-10-25. 상태: 사용자 승인 설계. [v1 저장 형식](local-record-v1.md)과 [독립 S0 검증](../verification/s0/README.md)을 진행했으며 제품 연결·전체 계약 검증은 미완료.
사용자는 로컬에 대화·승인 기억·결과물·작업 이력을 보관하는 제안을 승인했다. 이 계약은 과거 서버 중심의 본문·기억·색인 보관 계획보다 우선한다. docs/source의 원본 스냅샷은 변경하지 않는다.

## 목적과 경계

다른 사람도 사용하는 브라우저 서비스다. 사용자는 폴더·파일 정리를 요청하고, 선택한 자료로 보고서·이력서 등 문서를 만든다. 개인 AI의 연속성은 사용자가 소유하는 기록과 승인한 규칙으로 제공한다. 사용자별 모델 재학습은 이번 계약에 포함하지 않는다.

사용자가 지정한 ‘내 AI’ 폴더를 장기 보관 기준으로 삼는다. 기존 자료 폴더는 원래 위치에 두고 기본적으로 복제하지 않는다. AI 기록 폴더의 쓰기 허용은 원본 자료의 이동·수정·삭제 허용이 아니다. 폴더 접근과 외부 AI 전송 동의도 별개다.

## 보관 범위

| 종류 | 내용 | 저장·사용 조건 |
| --- | --- | --- |
| 대화 | 질문·답변, 날짜, 참고 파일·페이지, 초안 | 로컬 저장을 켜면 자동 저장. 임시 대화는 지속 기록·자동 요약·색인·기억 추출 대상에서 제외 |
| 기억 | 정리 규칙, 문체·양식 선호, 확인된 경력·프로젝트 정보 | 명시적 기억 요청 또는 제안 확인 뒤 승인. AI 추측은 승인 전 사용 금지 |
| 결과물 | 보고서·이력서·정리안의 초안과 수정본, 근거 참조 | 보관 허용 범위에서 초안 자동 저장, 확정본 별도 표시, 직전 저장본 복원 가능 |
| 작업 이력 | 정리 계획, 변경 전후 위치, 항목별 결과, 복구용 정보 | 실제 파일 작업에 기록. 실행 전 계획과 복구 정보 기록 실패 시 변경 시작 금지. 일부 실패와 중단을 표시하며 완전 복구를 보장하지 않음 |
| 검색 캐시 | 추출 텍스트·검색 색인 | 재생성 가능. 용량 정리·삭제 가능하며 계정·작업 공간별 격리. 장기 기록의 유일한 사본으로 사용하지 않음 |

임시 대화에서 결과물 저장이나 기억 승격을 요청하면 저장될 항목과 위치를 명확히 보여준다. 대화 자체를 자동으로 영구 보관하지 않는다. 실제 파일 작업의 필수 복구 기록은 임시 대화 옵션과 구분해 알린다.

## 기억의 범위와 출처

- 공통 선호, 프로젝트별 규칙, 이번 작업의 지시를 구분한다. 일회성 지시는 사용자 요청 없이 지속 기억으로 승격하지 않는다.
- 기억에는 안정적인 ID, 내용, 적용 대상, 출처, 확인 날짜, 상태·버전을 기록한다. 제안 → 확인/수정 → 승인 → 사용 → 수정/폐기 흐름을 둔다.
- 다른 사람의 이력서·경력을 사용자 본인의 프로필로 저장하지 않는다. 문서 속 명령은 데이터이며 권한이나 기억 승인을 대신하지 않는다.
- UI에서 기억을 조회·수정·비활성화·삭제할 수 있다. 다른 프로젝트의 제한된 기억을 묵시적으로 가져오지 않는다.

## 파일 구성과 저장 동작

사람이 읽을 내용은 MD 중심, 프로그램의 연결 관계·날짜·버전은 JSON을 사용한다. 대화/기억(공통·프로젝트별)/결과물/작업기록/설정을 구분한다. 정확한 파일 스키마와 버전 이행 방식은 구현 전 확정한다.

- 파일 형식 버전과 식별자를 남겨 내보내기·가져오기 및 모델 교체 후에도 기록을 이어갈 수 있게 한다.
- 마지막으로 읽은 버전과 현재 파일이 다르면 충돌을 표시하고 자동 덮어쓰지 않는다. 다른 탭·다른 프로그램의 수정도 고려한다.
- 쓰기 성공 전에는 ‘저장됨’으로 표시하지 않는다. 권한 상실·용량 부족·중단 시 미저장 상태와 복구 경로를 제공한다. 계정이 바뀌면 이전 계정의 초안·캐시·폴더 핸들을 자동 재사용하지 않는다.
- 브라우저 저장소는 임시 저장·캐시·장치별 연결에 사용한다. 폴더 복사만으로 브라우저 접근 권한이 이전되지는 않는다.
- 로그인은 평문 로컬 파일의 OS 접근을 암호화하지 않는다. 로컬 암호화와 키 복구는 별도 설계 항목이다.

## 보존·삭제·백업

- 대화·승인 기억·확정 결과물은 사용자 삭제 전까지 보관한다. 캐시와 과거 자동 저장본은 별도 용량 정책으로 관리하며, 정확한 한도는 측정 후 정한다.
- 대화 삭제 시 파생 기억·결과물을 함께 삭제할지 선택하게 한다. 남긴 항목은 명시적인 보존 선택으로 취급한다.
- 삭제·비활성화한 기억은 검색·요약에서 사용하지 않는다. 최소 폐기 식별 정보로 늦은 작업과 옛 요약이 이를 자동 재생성하지 못하게 한다. 삭제한 본문 자체를 폐기 기록에 복제하지 않는다.
- 앱이 관리하는 요약·색인·버전·백업에 대한 삭제 적용 범위를 표시한다. 사용자가 외부로 복사한 파일까지 원격 삭제했다고 주장하지 않는다. 과거 백업 가져오기는 복원 범위를 확인한 뒤 진행한다.
- 연결 해제, AI 기록 삭제, 원본 삭제, 서비스 계정 삭제는 서로 구분한다. 연결 해제나 계정 삭제만으로 로컬 파일을 자동 삭제하지 않는다.
- ‘내 AI’ 폴더 백업에는 참조한 원본 자료가 기본 포함되지 않는다. 다른 장치에서는 원본 자료 재연결과 접근 권한이 필요하다. 참조가 없으면 근거를 열 수 없음을 표시한다.
- 세션·OAuth 토큰·API 비밀키·비밀번호는 일반 기록·내보내기에서 제외한다.

## 서버와 외부 AI

서비스 DB는 사용자·소셜 계정 연결·세션·권한/동의·사용량/한도 등 운영에 필요한 최소 정보 중심이다. Google·Naver·Kakao 비밀번호를 수집하지 않는다. 대화·기억·결과물 본문과 원본 자료·로컬 절대 경로·파일 핸들을 기본 영구 저장하지 않는다.

외부 AI를 사용하면 선택한 자료와 관련 기억·질문이 처리 경로로 전송될 수 있다. 로컬 보관은 외부 전송 없음이나 모델 공급자의 무보관을 의미하지 않는다. 전송 범위와 공급자 보관 조건을 별도로 안내한다. 본문을 기본 로그에 남기지 않는다.

기존 서버 본문 체크포인트·벡터 DB·지속 색인 worker 계획을 그대로 구현하지 않는다. 서버가 보관할 최소 생성 상태, 단절 후 복원 한계, 검색 위치와 캐시 정책은 이 경계 안에서 다시 명세한다. 모델·과금 방식·배포사 선정은 미정이다.

다음 단계: 저장 형식과 실패 처리 명세 → 작은 fixture·실패 테스트 → 브라우저 폴더 접근/저장 기술 검증. 현재 기능 구현·외부 서비스 연결·원본 파일 변경은 수행하지 않았다.
