# 로컬 검색과 RAG 후속 명세 — 2026-11-15

- RAG-S01: 원문·사용자 선택 의도·확정 입력과 조건 출처를 보존하는 로컬 query plan을 만든다. 필수/선호/정확 구절/제외/확장자/경로를 구별한다. 따옴표·기술 기호·고유 대상과 명시 조건을 임의로 버리지 않는다.
- RAG-S02: 문서 종류는 다른 대상이 있을 때 선호 조건으로 제안할 수 있으나 화면에 표시하고 미충족 후보를 관련 자료로 구분한다. 유형만 검색하면 그 유형을 필수로 유지한다. 정확 구절·필수 대상·제외·형식·경로를 fallback에서 완화하지 않는다. 일반 자연어 의미 이해를 보장하지 않는다.
- RAG-S03: 날짜는 기존 확인 단계와 날짜 기준을 유지한다. 최근/애매한 기간·다중 대상의 의미는 임의 확정하지 않는다. 이전 대화는 명시 선택 없이 검색 입력으로 추가하지 않는다. 모델이 만든 이름/날짜/조건도 원문 출처를 검증한다.
- RAG-S04: 검색은 범위 안에서 실제 관측한 이름/경로/본문을 비교한다. 전체 조건 일치와 선호 조건 미확인을 구분해 정렬하고 결과 수·시간·본문·후보 한도를 유지한다. 명시 조건을 모두 적용할 수 없는 입력은 실행을 막고 입력 확인을 요청한다.
- RAG-S05: 기존 IndexedDB에 미지원 형식을 포함한 metadata 목록을 둔다. 원본 hash/parser/현재 권한이 최종 기준이고 size/mtime은 단서다. 부분 탐색·권한 상실·취소 뒤 누락 삭제 금지. schema migration은 기존 유효 본문과 별도 AI 기록을 보존한다.
- RAG-S06: 파생 본문은500개/UTF-16추정50MiB 안에서 오래된 항목을 제거할 수 있다. metadata는 별도 상한을 갖고 본문 제거가 원본 삭제를 뜻하지 않는다. 상태/수동 갱신/기기 색인 지우기는 현재 계정의 활성 연결 scope에서만 실행한다. 두 탭과 quota/blocked/손상을 검증한다.
- RAG-S07: 직접 작성한 dev/holdout의 출처·기대 결과·금지 결과를 고정하고 Recall@K/MRR/무관 후보/조건 보존을 비교한다. lexical 라이브러리는 같은 평가에서 품질·bundle·메모리·갱신 비용을 보고 선택한다. 의미 누락이 남으면 선택 local embedding의 기기 비용을 비교하고 기본 검색은 모델 없이 유지한다.
- RAG-S08: 원격 query 해석을 제공할 경우 별도 명시 조작과 전송 미리보기 뒤 질문만 전송한다. 파일 이름/경로/본문/검색 결과/다른 대화는 덧붙이지 않는다. 인증·workspace·Origin·한도·timeout·schema·대상 변경을 검증하고 실패 시 로컬 원문 검색으로 복귀한다. 유료 실호출은 합성 공급자 테스트와 구분한다.
- RAG-S09: 선택 자료 답변은 최종 질문으로 원본을 재읽고 발췌/hash를 다시 생성한다. 부분 범위 승인·전송 동의·전후 권한/hash 확인·인용이 실제 발췌에 속하는지 검증한다. metadata-only나 의미 유사성 점수만으로 질문 근거를 만들지 않는다.
- RAG-S10: metadata 갱신은250항목/약1초 배치의 마지막 완료 지점을 기기에 저장한다. queue·관측·실패·한도·활동 시각을 검증하고 다른 탭/다음 방문에서 이어간다. checkpoint 전체 추정2MiB를 넘기면 일부 결과로 끝내며 삭제 확정은 하지 않는다. 실패가 있는 cycle도 가능한 queue를 끝까지 확인하고 retain 없이 종료한다.24시간 비활동/손상/미지원 checkpoint는 재사용하지 않는다.
- RAG-S11: 연결별 명시 opt-in 후 보이는 화면에서30초 간격 metadata만 자동 확인한다. 숨김/해제/owner 변경은 취소하고, 이미 실행 중인 사용자 작업은 건너뛰며 새 사용자 작업의 정상 취소가 자동 설정을 끄지 않는다. 타 탭 잠금에 대기하지 않는다. 저장/권한/terminal 상한 실패는 안내 후 자동 확인을 끈다. 본문 추출·AI·권한 요청·원본 쓰기는 자동 실행하지 않는다.
- RAG-S12: 기기 색인 지우기는 documents/catalog/stats/checkpoint를 원자 삭제하고 자동 확인을 꺼 늦은 자동 재생성을 막는다. 원본과 AI기록은 유지한다. 운영 반영은 migration·usage 제약·제한 runtime 검증 뒤 flag 설정·배포·인증 브라우저 확인 순서다.

변경 순서: 실패셋/명세 → query plan/순위 → catalog/갱신 → UI·상태·로컬 관리 → 같은 corpus 대안 평가와 조건부 선택 → 최종 RAG 회귀 → 전체 정적/브라우저/비용 검증. 기존 동작 중 범위가 바뀐 테스트는 근거와 함께 고치고, 개인 파일을 합성 테스트셋으로 수집하지 않는다.

활성 scope는 현재 탭의 세션 선택이다. repository.active는 복원 기본값이며 다른 탭의 기존 선택을 강제 변경하지 않는다. 연결 삭제는 공유 저장소 재검사로 감지한다. 같은 날 후속에서 위S10~12의 지속 checkpoint/자동 확인을 추가했다. 초기 검증과 후속 검증은 구분한다. [초기 실행·평가·한계](../verification/local-rag-20261115/README.md)
