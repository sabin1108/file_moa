# 정식 TXT/MD 연결·전송 확인 명세 초안

## 2026-11-08 후속 구현 — 질문·답변·참고 구조·기존 실행 연결

아래 초기 단위의 미연결 표시는 당시 상태다. 실제 날짜 의미/혼합 자료 묶음 질문, 답변 수정과 재동의, 명확한 폴더 표현 추론, 참고 디렉터리 메타데이터, 복사/이동 선택과 기존 검토·실행·보존/복구를 연결했다. [검증/한계](../verification/live-organization-completion/README.md), [호출 흐름](../reports/live-organization-completion-reading.md).

- LT-R01: 질문 ID/문서/종류와 실제 날짜 라벨·근거를 검증한다. 보류 문서 누락/가짜 날짜/중복 답변/범위 밖 목적지는 거부한다. 명확히 답한 내용을 반복 질문하지 않는다.
- LT-R02: 날짜/목적지/이번 제외 답변은 조건의 일부다. 수정/제거는 옛 제안·동의·승인을 폐기하고 자동 호출하지 않는다. 질문 이력은 답 수정에 사용한다.
- LT-R03: 알려진 경로와 명백한 표현만 조건을 채우며 명시 UI 선택·해제가 우선이다. 참고 구조는 깊이3/80방문/200대기/5초/16KiB 제한의 폴더 메타데이터이며 전송 직전에 다시 비교한다. 참고 본문은 읽지 않는다.
- LT-R04: 사용자가 복사/이동·기준 목적지를 선택하면 출발 부모/목적지별 기존 managed 요청으로 투영한다. 보류/중복 도착/같은 경로는 실행 불가다. 새 폴더 생성은 기존 picker에서 별도 명시 행동이다.
- LT-R05: 제안 원본과 현재 managed 검사 파일의 hash/크기/mtime을 비교하고 기존 권한/충돌/실행 검사도 유지한다. 한 묶음의 원본 변경은 모든 옛 묶음을 차단한다. 결과·실패는 유지하고 새 준비가 필요하다.
- LT-R06: 실제 쓰기/보존/journal/복구는 기존 엔진을 사용한다. F5/답 변경/취소로 자동 재실행하지 않는다. 실제 Windows 전체 여정은 합성 검사로 완료 처리하지 않는다.

## 2026-11-08 현재 구현 — 전송 직전 재검사와 인증된 요청

기존 로컬 준비 뒤 **선택한 원본 재검사 → 새 명시 전송 → 인증된 Server Action → 검증된 AI 제안 표시**를 연결했다. 아래 첫 단위의 ‘전송 미연결’ 문구는 당시 상태다. 이번 검증은 합성 파일·공급자 대체 및 실제 Next의 비로그인/Origin 거부 범위이며, 개인 문서 실전송·실제 인증과 공급자를 함께 거치는 여정 완료를 뜻하지 않는다. [실행 근거](../verification/live-ai-transfer/README.md), [코드 호출 흐름](../reports/live-ai-transfer-reading.md).

- LT-S01: `ready`에서 현재 확인 키와 선택 문서가 일치할 때만 `send()`한다. session의 소유자/연결/세대를 고정해 선택한 경로만 다시 읽고 전체 SHA256·발췌 SHA256·발췌·크기·수정 시각을 대조한다. 같은 크기의 내용 변경, 누락, 부분 읽기, 권한 실패는 전송을 막고 준비/동의를 폐기한다. 재검사와 외부 OS 쓰기를 원자적으로 잠그는 기능은 아니다.
- LT-S02: Action은 매 호출 `requireWorkspace()`와 Origin을 검사한다. 브라우저 owner 값은 현재 세션과의 불일치를 거부하는 조건이며 권한의 근거가 아니다. 전체 입력 UTF-8 JSON 64KiB, TXT/MD 40개, 파일당 2MiB 메타데이터, 발췌 1,200자/총6,000자, 경로·중복·scope·발췌해시를 검사한다. 서버는 로컬 handle/전체 파일 해시의 진실성이나 소유권을 독립 증명하지 못한다.
- LT-S03: 기존 `consumeAll`로 요청당1회·작업 공간/로그인 계정당 시간당3회와 샘플 공용 분당1회/시간당12회를 함께 예약한다. 요청 ID는 `발급시각:UUID`이며 5분 유효(+30초 미래 오차)다. 요청 예약1시간보다 유효기간이 짧아 오래된 ID의 재사용을 거부한다. 같은 ID는 같은/다른 payload 모두 보수적으로 거부하며 응답을 캐시해 재전달하지 않는다. 본문/결과 DB 보관이나 새 테이블은 추가하지 않았다.
- LT-S04: 예약 직후와 모델 응답 직후에도 사용자/작업 공간/세션 사용자/만료를 검사한다. 모델 대기에 DB 트랜잭션을 유지하지 않는다. 기존 Gemini countTokens(최대8,192입력)/JSON 생성(최대3,200출력/25초)/ID·본문 인용·날짜·경로 검증을 재사용한다. 참고 폴더는 경로만 전달하며 읽지 않은 구조를 안다고 주장하지 않도록 구분한다.
- LT-S05: 확인 체크 자체는 전송하지 않는다. 버튼에 의한 새 요청만 허용하고 한 번 사용한 동의는 비운다. 실패 후에도 새 확인과 명시 전송이 필요하다. 취소는 재검사를 중단하거나 응답 반영을 버린다. 이미 서버에 간 호출은 클라이언트 취소로 공급자 중단/환급을 보장하지 않는다. 계정 변경 응답은 초안/발췌/동의/결과를 비운다. F5/화면 이동은 자동 요청을 하지 않는다.
- LT-S06: 전송 전 Google Gemini, 이름·상대 경로·발췌·요청·조건·한도를 표시한다. 짧은 문서는 발췌에 본문 전체가 포함될 수 있다. 토큰 사전 계산도 Google로의 전송이다. 파일 바이너리/핸들은 보내지 않는다. 제안·확인 필요·인용·모델/토큰은 표시하되 실제 파일 실행은 연결하지 않는다.

후속: 자연어 범위 추론, 실제 자료 기반 날짜/혼합 질문과 답변, 복사/이동 선택, 기존 실행 projection/적용 직전 재검사. LT-T04~06/11의 전체 완료와 일반 PDF/XLSX 지원은 이번 범위가 아니다. 전체 해제 모드 유지 불일치도 별도 미해결이다.

2026-11-07. 사용자에게 범위·복사/이동·혼합 자료·날짜 기준을 질문하고 받은 답을 반영했다. 제품 선택은 아래 ‘확정된 요구’를 따르며 수치 한도·세부 API는 기존 제약 안에서 구현/측정할 초안이다. 이 문서는 기능 구현·개인 파일 전송 완료 증거가 아니다.

## 확정된 요구

- LT-001: 연결된 폴더 전체를 탐색 후보로 삼을 수 있다. 사용자의 의사가 우선이므로 범위를 특정 폴더로 고정하지 않고 대화에서 필요한 범위를 확인한다. 명확히 지정한 범위를 다시 묻거나 불필요한 시작 마법사로 대화를 막지 않는다. ‘회사 전체에서 찾기’와 ‘보고서 폴더를 기준으로 정리하기’를 동시에 표현한다.
- LT-002: 탐색 범위, 정리 기준/참고 폴더, 최종 목적지는 서로 다른 값이다. 기준 폴더를 탐색 범위로 축소하거나 목적지로 단정하지 않는다. 뜻이 불명확하면 현재 폴더 구조와 요청을 근거로 확인 질문을 만든다.
- LT-003: ‘모아줘/정리해줘’만으로 복사/이동을 정하지 않는다. 계획 검토에서 사용자가 선택해야 적용할 수 있다. 요청에서 명시한 동작은 제안에 반영하되 검토·승인은 유지한다.
- LT-004: 관련 내용은 있으나 여러 주제로 분류가 애매한 자료는 ‘확인 필요’ 목록으로 모은다. 자료마다 질문하여 흐름을 끊지 않고 마지막 검토에서 함께 의사를 묻는다. 임의 분류하거나 보류를 적용 완료로 세지 않는다.
- LT-005: 보고일/기준일 등은 우선 날짜 후보로 포함할 수 있다. 실제 정리 기준은 사용자 의도를 확인하여 정한다. 사용자가 든 보고일/파일 생성일은 예시이며 고정 선택지 목록이 아니다. 원자료에서 확인 가능한 날짜의 의미·근거에 따라 질문을 구성한다. 확인할 수 없는 생성일을 수정일로 바꾸어 표시하지 않는다.
- LT-006: 폴더 연결·로컬 분석·외부 AI 전송·원본 변경은 서로 다른 허용 단계다. ‘연결된 폴더 전체’가 자동으로 모든 본문을 외부에 전송하라는 뜻은 아니다. 사용자 선택 범위와 실제 전송 자료를 확인한 뒤 전송 동의를 받는다.

## 구현할 흐름과 상태

`요청 입력 → 범위/기준 확인 → 로컬 후보 읽기 → 전송 자료 확인 → 동의 → 인증된 AI 분석 → 제안/확인 필요를 모음 → 마지막 질문·작업 선택 → 최종 계획 검토`

AI 결과를 받았다는 이유로 쓰기를 시작하지 않는다. 실제 복사·이동·복구 연결은 기존 계획·권한·충돌·원본 재검사 계약을 따른다.

1. **요청과 범위:** 기본 후보는 현재 연결된 전체 범위다. 사용자가 회사 하위/선택 파일을 지정하면 그 범위로 좁힌다. 불명확한 부분만 질문한다. ‘어디서 찾을지’와 ‘어떤 폴더 구조를 참고할지’를 각각 표시한다.
2. **로컬 후보 snapshot:** 브라우저에서 접근 허용된 경로만 열고 TXT/MD를 읽는다. 연결/계정/범위 세대를 고정하며 취소 후 늦은 읽기를 게시하지 않는다. 원본을 쓰지 않는다. 전체 내용의 해시와 size/lastModified, 문서 ID를 로컬에서 연결한다. CPU가 큰 해시/검색/발췌는 Worker 책임으로 둔다.
3. **범위 완전성:** 발견한 수·읽은 수·제외/실패 수·실제 전송 수를 구분한다. 상한·권한 철회·중단으로 일부만 읽었으면 전체 검색 완료나 ‘자료 없음’을 단정하지 않는다. 범위를 좁히거나 다음 묶음을 명시 선택한다. 자동으로 여러 유료/모델 요청을 이어 보내지 않는다.
4. **전송 확인:** 문서 이름·전송될 발췌·제외 이유·공급자·실제 후보 수를 보여준다. 문서당/총량 한도와 토큰 사전 계산을 적용하며 연결된 모든 본문을 통째로 업로드하지 않는다. 실제 MD/TXT 범위와 발췌 기준을 공개한다.
5. **동의:** 요청·범위·선택 문서·발췌/버전 hash·정리 기준에 묶는다. 내용이나 조건이 바뀌면 기존 동의를 무효화한다. URL 복원/F5는 읽기 상태만 복원하고 전송/쓰기를 재실행하지 않는다.
6. **서버 호출:** requireWorkspace로 계정/공간을 확정하고 요청 스키마·Origin·문서/발췌/출력 상한·멱등성·사용량을 검증한다. 로컬 handle/절대 경로/클라이언트가 주장하는 workspace 권한을 신뢰하지 않는다. 원문·결과의 기본 영구 보관/로그는 기존 로컬 보관 계약에 따라 금지한다.
7. **검토와 질문:** 명확한 일치와 확인 필요를 함께 보여주고, 혼합 주제·기준 불명확 항목은 마지막에 묶어 질문한다. 선택 가능한 날짜 기준은 실제 자료 근거로 구성한다. 사용자가 이미 명확히 답한 조건을 계속 재질문하지 않는다. 질문의 답이 바뀌면 그 답에 의존한 계획·동의·버전을 갱신한다.
8. **원본 적용 준비:** 복사/이동 미선택, 미해결 필수 질문, 내용 변경, 권한 철회, 목적지 충돌을 별도로 표시한다. 적용 전에 원본을 다시 읽고 hash/상태를 비교하며 변경됐으면 계획을 무효화한다. 보류 자료는 임의로 쓰지 않는다.

### 클라이언트와 서버의 해시 의미

아래는 정식 endpoint를 구현할 때 지켜야 할 계약이며 현재 연결 완료 상태가 아니다. 전체 파일 해시는 클라이언트의 원본 버전 재검사에 사용한다. 서버는 로컬 디스크를 읽을 수 없으므로 그 해시로 실제 파일 소유/접근 권한을 증명했다고 판단하지 않는다. 서버는 전달받은 발췌/요청의 일관성 해시·멱등성과 인증된 사용자 범위를 검증해야 한다. 절대 경로와 실제 handle 대응표는 브라우저에 남긴다.

## 첫 구현 단위 — 로컬 자료 준비 (2026-11-07 구현)

기존 채팅/자료 창·파일 연결·목적지 탐색을 재사용한다. 대화 요청은 먼저 입력할 수 있고, 범위가 미확정이면 읽기 전에 전체/하위/선택 범위를 확인한다. 명시적으로 선택한 범위는 다시 묻지 않는다. 이 단계는 자연어의 범위를 자동 추론하는 AI가 아니라 사용자가 확인한 조건을 보관하는 준비 단계다.

- 탐색 범위, 참고 폴더, 목적지, 정리 기준 문장을 독립 상태로 보관한다. 참고/목적지 선택은 탐색 범위를 바꾸지 않는다. 새 폴더 생성은 이 준비 화면에서 제공하지 않는다.
- 단일 루트 안에서 TXT/MD를 재귀로 읽으며 기존 2MiB/500문서/50MiB와 탐색 1,000폴더/20,000항목/깊이64/15초 상한을 적용한다. 상한·일부 읽기 실패는 불완전 결과로 표시한다. 내부 기록/복구 보관함은 제외한다.
- 같은 File의 바이트를 Worker에서 한 번 읽어 UTF-8 검증, 전체 SHA256, 요청 단어 주변 최대1,200자 발췌와 발췌 SHA256을 만든다. 요청 단어는 발췌 위치/입력량을 제한하는 보조 기준이며 의미 일치 판정이 아니다.
- 샘플과 공통 후보 제한 함수로 최대40개/약6,000자 입력 묶음을 고르고 원본 읽은 수·후보 수·실패/제외를 구별한다. 사용자는 실제 발췌를 보고 후보를 제외할 수 있다. 실제 공급자 토큰 계산/전송은 후속이다.
- 불완전 범위는 일부만 준비됐음을 별도로 수락해야 동의할 수 있다. 동의는 요청·범위·기준·참고·목적지·선택 문서의 전체/발췌 hash에 묶이며 조건 변경/다시 읽기/연결 변경/취소로 폐기한다.
- 본문·요청·동의는 Provider 수명의 메모리에만 둔다. 경로 이동은 유지하지만 F5/로그아웃/계정·폴더 교체는 초기화하고 자동 읽기/전송/쓰기를 실행하지 않는다. snapshot은 읽은 시점의 사본이며 외부 프로그램 변경을 계속 감시하는 기능은 아니다. 후속 전송/적용 직전 재검사는 별도 필수다.
- 전송 준비 동의를 마쳐도 서버 호출/AI 제안/계획 적용은 활성화하지 않는다. 날짜 후보 의미 판단·혼합 자료 질문·복사/이동 선택은 후속 검토 단계다.
