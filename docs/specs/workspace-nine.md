# 대화·자료·로컬 기록 연결 계약

2026-11-09 사용자 요청 ‘9번까지 쭉 이어서 작업해’의 구현 범위다. [기존 로컬 보관 계약](local-ai-storage.md)과 [v1 기록 형식](local-record-v1.md)을 유지한다. [실행 및 검증](../verification/workspace-nine/README.md)을 완료 증거와 구분한다.

## 로컬 기록

사용자가 별도 내 AI 폴더를 선택하고 쓰기를 허용하면 `.moa-ai-v1/owner.json`의 계정·작업 공간을 확인한다. 원본 자료·복구 보관함과 겹치는 폴더는 선택하지 않는다. 대화/결과물/기억/프로필은 각각 하위 폴더의 MD 본문과 정확한 v1 JSON 메타데이터로 보관한다. 본문 안의 엄격한 상태 JSON도 전체 본문 SHA-256에 포함한다. 세션·비밀번호·공급자 키를 기록 payload로 받지 않는다.

기본은 임시 대화다. 보관을 켠 대화는 입력이 멈춘 뒤 800ms, 진행 중 답변은 변경이 멈춘 뒤 2초에 저장한다. 화면에 공개한 답변까지만 보관한다. 새 대화/다른 대화 열기는 현재 미저장 대화 저장을 먼저 기다리고, 복원한 진행 중 답변은 중단 상태로 바꾼다. 복원은 AI 요청을 만들지 않는다. 화면 이동 정리 시에도 마지막 저장을 시도하며 저장 전 브라우저 종료에는 미저장 안내를 제공한다. 프로세스 강제 종료까지 저장 성공을 보장하지 않는다.

같은 기록의 쓰기는 Web Locks로 직렬화하고 마지막으로 읽은 head와 parent를 비교한다. 다른 탭·외부 편집과 충돌하면 덮어쓰지 않는다. 새 revision만 생성하고 writer 오류의 아직 유효한 자기 파일만 정리한다. 한 기록은 본문당 2MiB, 누적 50MiB, 최대 1,000개 revision이다. 신규 기록은 네 관리 폴더를 합친 유효 ID 디렉터리500개 상한이며 정상·손상·미완료 삭제 폴더도 실제 제거 전까지 자리를 차지한다. workspace 생성 잠금 안에서 존재 여부·소유권·개수와 삭제 표식을 다시 확인하고 새 디렉터리 자리를 예약한다. 기존 기록 갱신과 삭제·삭제 재개는 이 생성 상한으로 차단하지 않는다. 이미 초과한 저장소는 최대501개 복구 창과 경고를 제공하고 한 번에 더 많이 해석하지 않는다. 신규 생성 상한을 올리거나 기존 파일을 자동 삭제하지 않는다. 한도 전에 실패시켜 기존 head를 보존한다. 권한 상실 등으로 정리도 실패하면 파일을 임의 복구하지 않고 오류로 표시한다.

단일 대화의 질문·답변/자료 작업 한 묶음은 turn 하나이며, 실패·중지 기록도 포함해500turn 상한이다. 저장 schema, 일반/자료 요청 시작, reducer와 화면이 같은 상수를 사용한다. 상한 도달 뒤에는 다음 요청을 보내거나 새 turn을 추가하지 않고 입력 초안을 유지한다. 기존500초과 상태를 복원한 경우 자동으로 자르지 않는다. 저장 실패 또는 미저장 임시 대화에서 다른 일반/임시 대화로 이동하려면 ‘계속 편집’ 또는 ‘미저장 내용 버리고 전환’을 직접 선택한다. 버리기는 해당 snapshot·선택·연결 revision을 다시 검사한 뒤에만 실행한다. 대화/계정/연결/진행 작업이 바뀌면 옛 확인을 적용하지 않는다. 정상 저장한 현재 대화를 다시 선택해도 이전 목록 payload로 최신 화면을 되돌리지 않는다. 500turn과 기록500개는 다른 한도이며 바이트·revision 한도도 별도로 적용한다.

삭제는 본문 없는 tombstone을 먼저 쓴다. 앱 기록 폴더의 해당 ID와 모든 revision만 삭제한다. 파생 결과물·기억의 동반 삭제는 별도 선택이다. 파생 저장은 원본 대화의 잠금도 공유하고, 동반 삭제 tombstone 이후의 늦은 파생 저장은 거부한다. 외부 내보내기·사용자 복사본은 삭제하지 않는다. 연결 해제와 계정 삭제는 로컬 원본 삭제가 아니다.

2026-11-13 실패 복구 보완: 목록은 정상 기록, 읽지 못한 개별 기록, 미완료 삭제를 구분해 반환한다. 빈 폴더·빈 JSON·형식/본문 검증 실패는 해당 기록만 제외하고 경고하며 파일을 자동 수선하거나 지우지 않는다. owner manifest·읽기 권한·연결 세대·알 수 없는 I/O 오류는 전체 실패로 유지한다.

미해결 저장소 경고는 정상 기록의 저장·자동 저장 성공이나 폴더 선택 취소로 지우지 않는다. 일시적인 저장 오류는 성공한 재시도로 해제할 수 있지만, 저장소 경고는 목록 재검증 결과로 갱신한다. 깨끗한 목록을 확인하거나 연결을 끝내면 이전 경고를 해제하며, 저장마다 전체 목록을 다시 읽지는 않는다.

유효한 tombstone과 동반 삭제한 대화를 참조하는 기록은 기존 삭제 의도에 따라 이어서 정리한다. 실패해도 정상 목록을 유지하고, 같은 삭제 버튼·다시 읽기·새 연결 뒤에 재개한다. 파생 삭제는 대화 잠금→기록 잠금 안에서 최신 revision과 원본 대화 참조 및 cascade 표식을 다시 확인한다. 이미 대화 참조를 제거한 새 버전은 보존한다. 손상되어 참조를 확인할 수 없는 기록은 자동 삭제하지 않는다. 이미 시작한 삭제 범위를 묵시적으로 확대하지 않는다.

결과물 초안은 1.5초 변경 대기 뒤 자동 저장하고 확정본은 직접 저장한다. 이전 버전 불러오기는 편집 내용만 바꾸며 저장하면 새 revision이 된다. MD/TXT 내보내기는 표시 본문만 내려받는다. 미저장 편집기를 닫기 전 버리기 여부를 표시한다.

## 기억과 전송

프로필은 직접 작성한 정보다. 기억은 제안/승인/비활성 상태와 global/project 범위가 있다. 제안과 비활성 기억은 사용하지 않는다. 임시 대화의 자동 기억 추출·자동 승인은 없다. 임시 답변에서 결과물이나 기억을 선택하면 별도 편집기에 표시하고 해당 항목만 보관한다.

다음 질문에 프로필·기억을 포함하려면 사용자가 별도 체크해야 한다. 전송 직전 로컬 기록을 새로 검증하고 승인된 공통 및 지정 프로젝트 기억만 포함한다. 최대 10개·6,000자이며 한도 초과 시 일부를 몰래 잘라 전송하지 않는다. 본문은 서버 원장에 저장하지 않는다.

## 선택 자료와 폴더

기존 자료 준비의 선택 범위·발췌 확인을 재사용한다. 자료 질문은 정리 제안과 별도 Server Action이다. 질문과 선택 발췌의 명시적 동의 뒤 전송 직전에 hash·크기·수정 시각·권한을 다시 읽고, 응답 뒤에도 다시 확인한다. 입력 변경·계정/활성 root 변경·취소는 늦은 응답 표시를 막는다. 서버는 origin/session/owner/한도/엄격한 입력/발췌 hash를 검증한다. 인용은 제공한 문서 ID와 발췌에 실제로 포함된 8~200자 문장만 허용한다. 답변 근거의 사실적 충분성까지 자동으로 입증하는 검사는 아니다.

자료 폴더는 계정·작업 공간별 stable connection ID를 갖는다. 같은 표시 이름/상대 경로로 합치지 않는다. 기존 단일 source는 legacy 연결로 읽으며 활성 연결을 새로고침 뒤 복원한다. 개별 해제는 해당 참조·캐시만 지우고 원본은 유지한다. 사용 권한 요청은 사용자의 활성화 조작에서 시작한다. 진행 중 파일 작업에서는 전환을 차단한다.

PDF는 승인한 `pdfjs-dist@6.5.438`을 같은 origin의 브라우저 Worker에서 실행한다. 바이트 hash는 원본으로 계산하고 최대 2MiB·50쪽·200,000자까지만 읽는다. 쪽 표식을 텍스트에 남기며 잘림을 표시한다. 암호 PDF·손상·이미지 전용은 별도 제외 사유다. 원격 글꼴·CMap·WASM URL을 제공하지 않고 원본 PDF를 편집하지 않는다. OCR·의미 검색은 이번 범위에서 도입하지 않았다. 현재 필요한 근거는 명시적 조건 검색으로 검증하며, 의미 검색은 추가 모델 비용·본문 전송·갱신 기준을 별도 검토해야 한다.

추출 색인은 IndexedDB의 재생성 가능한 캐시다. 계정/작업 공간/connection/path별 레코드에 원본 hash·parser version을 보관하고 같은 경로의 오래된 hash는 교체한다. 연결 세대 검사 뒤 동일 트랜잭션에서 저장하며 전체 스캔 성공 때만 누락 경로를 정리한다. 부분 실패·권한 상실을 파일 삭제로 해석하지 않는다. 캐시는 source bytes 검사를 대신하지 않는다. 연결당 500개·보수적으로 50MiB 한도를 두고 캐시 오류가 원본 읽기를 막지 않게 한다.

## 사용량과 계정 삭제

사용량 원장은 workspace/request ID 고유 키와 공급자·작업·모델·토큰·시각·상태만 보관한다. 예약은 중복 거부, 최종 정산은 `reserved` 조건으로 한 번만 반영한다. 공급자 사용량을 확인하지 못하면 0으로 만들지 않는다. 계정·공간별 10회와 공유 분당 1회/시간당 12회는 기존 예약에서 조회한다. 비용은 확인한 단가가 있는 정확한 모델만 표준 예상값으로 표시하고 실제 청구로 부르지 않는다.

운영 DB migration을 적용하기 전 `AI_USAGE_LEDGER_ENABLED=false`를 유지한다. 비활성 상태를 UI에 표시하고 과거 토큰을 소급 생성하지 않는다. 원장은 [migration](../../apps/web/prisma/migrations/20261109010000_ai_usage/migration.sql)을 적용한 뒤 서버 환경에서 활성화한다.

계정 삭제는 같은 계정의 최근 24시간 세션·체크 확인·30분 메일 토큰을 요구한다. GET 링크는 확인 화면만 연다. 토큰 원문 대신 SHA-256과 세션에 묶인 확인 정보만 저장한다. 최종 POST는 DB 트랜잭션에서 계정 연결과 같은 advisory lock을 얻고 세션/토큰/만료/대표·멤버 연결을 다시 확인한 뒤 토큰과 user를 함께 삭제한다. FK cascade가 세션·로그인 수단·작업 공간·사용량을 정리한다. 실패 시 전부 rollback한다. Better Auth SDK의 비원자적 삭제 endpoint는 비활성으로 유지한다. Kakao 로그인 보류도 유지한다.
