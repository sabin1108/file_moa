# 파일 작업 선택·팝업·검사 UX — 2026-11-02

2026-11-03 정정: 상위 이동의 형태와180ms 전환 규칙은 [후속 안정성 명세](folder-interaction-stability.md)가 우선한다. 반복 전체 진입 효과는 제거하고 열린 목록/입력을 보존한다.

사용자 요청: 파일 선택 후 복사/이동을 바로 고르고, 분류는 향후 챗봇에서만 지정한다. 팝업 밖으로 휠이 전달되지 않아야 하며 목적지 확정은 버튼으로 인식돼야 한다. 검사와 예상 결과는 기술 문자열 대신 파일·폴더·출발/도착·확인 상태로 보여준다. 같은 이름은 계속/중단과 별도 덮어쓰기 경고를 거치며 기존 목적지는 전용 복구 보관함에 보관하는 후속 계약이 필요하다.

## 이번 UI 계약

- ACTION-001: 선택 도구에 `복사`, `이동` 버튼을 나란히 제공한다. 선택이 없거나 목록이 오래되었으면 비활성. 누른 작업을 dialog 첫 상태에 전달하고 I/O/권한/쓰기를 시작하지 않는다. 기존 선택과 닫기 초점 복원을 유지한다.
- ACTION-002: 수동 화면에는 분류 선택/안내를 제공하지 않는다. 향후 챗봇 분류는 제안 계획과 검토를 거쳐야 하며 이번에 AI를 구현하지 않는다. 이동은 현재 목적지/예상 결과 검토이며 실제 원본 삭제를 연결하지 않는다.
- ACTION-003: 팝업이 열리면 배경 스크롤을 잠그고 닫기/언마운트 때 원래 스타일·위치를 복원한다. 목적지 선택 중에는 헤더/새로 만들기/목록/배경 어느 곳의 세로 휠도 폴더 목록에 적용한다. 일반 계획 화면에서는 팝업에만 적용한다. 목록의 맨 위/아래에서도 배경은 움직이지 않는다. 확대용 Ctrl+휠은 가로채지 않는다. 키보드·터치도 배경으로 연결되지 않게 한다.
- ACTION-004: 현재 폴더 이름과 경로는 정보로, `이 폴더 선택`은 일반 크기의 진한 버튼으로 분리한다. 클릭/hover/pressed/focus/disabled 상태를 제공하고 기존 접근성 이름을 유지한다.
- ACTION-005: `파일 내용`, `변경 여부`, `이름 충돌`을 아이콘과 짧은 설명으로 표시한다. 실제 검사 전체가 끝나기 전 개별 항목을 성공으로 표시하거나 가짜 진행률을 만들지 않는다. 실행 중에만 점검 표시를 움직이고 reduced-motion에서는 정지한다. 원문은 읽을 수 있는지, 크기/한도, 두 번 읽은 내용이 같은지, 목적지 이름이 겹치는지를 설명한다. 악성 코드/문서 의미/복사 후 성공 검사로 오해하지 않게 한다.
- ACTION-006: 완료 후 파일별 확인 행과 사람용 용량을 표시한다. 해시·수정 시각은 접힌 `기술 정보`에 두고 SHA-256이 내용 변경 비교용 값임을 설명한다. 예상 결과는 한 파일별 행 안에 출발 폴더→도착 폴더, 원본 유지/이동 예정, 충돌 상태를 분리해 표현한다.

## 충돌·복구 실행 순서

1. 현재 변경 없는 UI 개선을 먼저 검증한다.
2. 전용 복구 보관함의 최초 생성/선택·연결 수명·백업 형식·검증·실패/취소 계약을 구현한다. 기존 `.moa-history` 작업 기록 위치와 별개이며 과거의 필수 기록 폴더 선택기를 되살리지 않는다.
3. 계속→충돌 파일과 변경 전/후 표시→`복구 사본을 남기고 덮어쓰기`/`작업 중단` 경고를 연결한다. 복구 사본 검증 전에는 기존 목적지 writable을 열지 않는다. 충돌 검사만 생략하는 구현은 금지한다.
4. 복원·보관 기간·즉시 삭제는 별도 복구 보관함 관리 흐름에서 처리한다. 보관 기간은 사용자에게 선택하게 하며 자동 삭제/영구 삭제를 이번 UI 변경으로 실행하지 않는다.

성공 기준: unit에서 직접 작업 선택과 초기화·I/O0, 실제 Chromium에서 전체 위치 휠/끝 경계/배경 고정·닫기 복원·직접 작업·분류 부재·버튼 상태·검사 진실성·접힌 기술 정보·파일별 경로 표시,390/768/1440/1920px, Escape/Tab/초점·reduced motion, 기존 복사 회귀. 이어 타입/lint/전체 테스트/경계/build와6경로 전후 성능을 기록한다. 개인 파일에는 쓰지 않는다.

## 추가 요청 — 같은 날 단계 흐름

- ACTION-007: 목적지를 먼저 명시적으로 선택한다. 경로 표시 자체가 선택 창을 여는 버튼이며 직접 경로 입력도 그 창 안에 둔다. 목적지 미확정 상태에서는 계획 생성을 시작하지 않는다.
- ACTION-008: 목적지+계획 → 검사 → 실행/결과의3단계다. 검사 중/완료에는 목적지 입력을 숨기고, 실행 중/결과에는 검사 입력도 숨긴다. ‘목적지·계획 수정’으로 되돌아가면 검사 승인은 폐기한다. 앞 단계 이름과 현재 단계는 표시하며 완료를 가장 위에 보여준다.
- ACTION-009: 예상 결과는 출발/도착 폴더 각각 아래에 해당 파일을 붙인 구조로 보여준다. 선과 폴더/파일 아이콘으로 포함 관계를 표현하고, 작업 중 표시만 실제 상태에 맞춰 움직인다. 의미 없는 가짜 진행률이나 완료 전 성공 표시를 만들지 않는다.
- ACTION-010: 복사 결과가 completed이고 기록까지 확정된 경우만 `확인`으로 창을 닫고 해당 목적지 목록으로 이동한다. 취소/미확인/실패에 성공 이동을 적용하지 않는다. 탐색 실패는 기존 listing 오류로 알리고 복사를 다시 실행하지 않는다.
- ACTION-011: 이전 확인 목록의 열린 폴더를 재클릭하면 parent.path로 이동한다. 다른 폴더는 기존대로 해당 하위 폴더를 연다.

검증 보완: 하위 목록이 짧거나 화면 밖이면 휠은 팝업 자체에 적용한다. 완료 화면은 검토한 계획을 기본 접힘으로 두고 확인 행동을 노출한다. 실행 진입 예외로 항목 결과가 없을 때는 `계획·검사 다시 확인`으로 승인을 폐기하고1단계로 복귀할 수 있다. 부분 실행 결과는 자동 재시도하지 않는다.

요구사항 원장은 E:/memory/chatbotfolder/Requirements/요구사항.md. 번호별1~3줄로 누적하며 취소는 삭제 대신 `{취소됨}`으로 표시한다. 이동 실행은 이 요청에서 상태 확인 대상이며 아직 미구현이다.
