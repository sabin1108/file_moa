# 복사 전 읽기 전용 검사

2026-10-30. 사용자는 계획 단계를 끝내고 가능한 구현과 테스트를 진행하도록 명시했다. 이번 완료 단위는 실제 복사에 앞선 내용 검사다. 기존 [복사 안전 검토](../../.omx/plans/copy-apply-review-20261030.md)의 실제 쓰기·journal 미해결을 해결했다고 취급하지 않는다.

## 동작 계약

- INSPECT-001: 충돌 없는 복사 계획에서만 `복사 전 검사`를 제공한다. 명시적으로 누르기 전 본문/hash 읽기 없음. 이동·분류에는 추가하지 않는다.
- INSPECT-002: 서비스는 입력을 복사하고 copy 종류, 경로, 동일 이름, 단일 출발/목적지, 중복/충돌/폴더 생성 없는 계획을 검증한다. 실제 출발·목적지 목록으로 다시 계산한다. 일부 목적지 목록은 통과하지 않는다.
- INSPECT-003: 파일별 크기·수정 시각·SHA-256을 읽는다. Worker에서 File 바이트 읽기와 SHA-256을 수행하며 한 번에 한 파일만 처리한다. UI에는 handle/본문을 전달하지 않는다. 다시 연 파일의 entry·metadata·hash가 다르면 검사 실패다. 검사 끝에 목적지 충돌과 읽기 권한을 다시 확인한다. 시점 검사이며 이후 외부 변경이나 실제 적용 안전성을 보증하지 않는다.
- INSPECT-004: 초기 검사 한도는 100파일, 파일당 16MiB, 합계 64MiB다. 미리보기/업로드 한도와 별개인 메모리·작업량 제한이다. 파일 내용 읽기 전 전체 metadata로 한도를 확인한다. 최대 입력의 실제 Worker 검사 시간은 검증 기록에 남긴다. 임의 크기의 실제 복사를 허용하는 정책이 아니다.
- INSPECT-005: 취소/계획 입력·목록·선택·연결·소유자 변경/닫기 시 Worker를 종료하고 늦은 결과를 폐기한다. 진행 중 검사 버튼은 `검사 취소`로 유지한다. 권한 상실은 연결 상태에도 반영하며 자동 권한 요청은 없다. 오류 뒤 계획을 유지해 재검사할 수 있다.
- INSPECT-006: 검사 완료는 파일 수·합계 크기와 파일별 읽은 정보로 표시한다. hash는 `검사 상세` 안에 둔다. 2026-11-01 [명시적 복사 실행](copy-execution.md)으로 후속 조작을 연결했다. 검사는 계속 읽기 전용이며 실행은 별도 버튼·쓰기 권한·재검사에서만 시작한다. 검사 결과는 메모리에만 존재한다.
- INSPECT-007: 원본/목적지 생성·쓰기·삭제, 권한 요청, 업로드/저장 모두 0. 기존 계획·목적지 선택 흐름은 그대로 검증한다.

## 구현 책임과 검증

lib은 DTO·한도·계획 입력 검증, services는 파일 읽기/Worker 수명, session은 연결 세대와 권한, 별도 검사 controller는 취소·결과 상태, 표시 컴포넌트는 검사 조작과 상세를 맡는다. 기존 plan이 검사 수명을 폐기한다. 공통 버튼/상태/평평한 행과 현재 achromatic-ledger 토큰을 재사용한다. 화면 질문은 “선택 파일을 지금 읽을 수 있고 목적지와 충돌하지 않는가?”다.

실패 테스트를 먼저 실행한 뒤 구현한다. 단위/통합: 변조 계획, 한도, 검사 중 동일 size/mtime 변경, 마지막 충돌, 권한, 연결 교체, 취소와 Worker 해제. 브라우저: 실제 Worker+Web Crypto+OPFS 합성 파일, 알려진 hash, 원본 sentinel 무변경, 쓰기/전송 0, 취소/오류/재시도, 390/768/1440/1920px, 키보드/합성 IME. 경로별 성능 전후와 한도 입력 검사 비용은 분리한다. 실제 OS 권한창·물리 IME·native disk는 별도 미검증이다.
