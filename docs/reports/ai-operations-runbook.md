# AI 운영 점검과 비용 확인

2026-11-08. 실제 문서 AI 전송은 로그인·작업 공간·Origin·입력·원본/발췌 해시·새 동의를 확인한 뒤 요청한다. 같은 이메일을 계정 병합의 근거로 사용하지 않는다.

## 현재 제한

- 실제 정리: 같은 requestId 1회, 작업 공간/사용자 각 시간당 3회. 샘플과 공유하는 전체 분당 1회·시간당 12회 제한. DB가 원자적으로 함께 예약한다.
- 실패·취소도 공급자에게 도달했을 수 있으므로 예약은 반환하지 않는다. 재전송은 사용자가 새로 확인한다.
- 서버는 `AI_PROVIDER=openai`와 서버 전용 `OPENAI_API_KEY`를 사용한다. 키가 없거나 화면의 공급자와 달라지면 전송 전에 거부한다.
- 운영의 익명 샘플 AI는 기본 꺼짐이다. `ENABLE_PUBLIC_SAMPLE_AI=true`를 별도로 켜면 전체 한도를 공유한다.
- 정리 입력 8192/출력 3200토큰과 25초 상한은 공급자 호출을 제한한다. 출력 상한 도달·거절·잘못된 JSON을 성공으로 표시하지 않는다.

## 실패 시 확인 순서

1. 사용자가 본 문구와 대략 시각만 확인한다. 키·인증 URL·파일 본문을 복사하도록 요구하지 않는다.
2. Vercel 서버 로그의 `Live AI operation.`을 확인한다. 허용 필드는 단계·공급자·결과·시간과 알려진 토큰 수뿐이다. 사용자/작업 공간 ID·경로·질문·응답·오류 객체는 기록하지 않는다.
3. `quota` 실패는 DB/예약 경로, `limit`는 요청 한도를 확인한다. `session` 실패는 인증을 다시 확인한다. 입력 거부는 모델 호출 전에 끝나며 이 진단 로그를 만들지 않는다.
4. `generation`에서 `timeout/unavailable`이면 공급자 상태·프로젝트 키 권한·모델 허용·잔액과 배포 환경 변수를 확인한다. 로그만으로 이 원인을 하나로 확정할 수 없다. `response` 실패는 응답 검증 거부다. 자동 재시도하거나 실패 응답 원문을 로그에 추가하지 않는다.
5. 토큰이 기록되고 결과가 세션 오류이면 모델 응답 뒤 세션 확인에서 폐기된 경우다. 비용이 없었다고 안내하지 않는다. 공급자가 사용량을 반환하기 전에 실패한 경우 소비량은 이 로그로 알 수 없다.

## 크레딧·결제·키 관리

API 플랫폼의 **같은 프로젝트** Limits/Usage/Billing에서 확인한다. 사용자가 설정한 월 $10 enforced limit과 알림이 실제 키의 프로젝트에 적용되는지 확인하고, 월간 혜택 크레딧·만료는 Billing을 기준으로 한다. 요청 수 제한이나 예상 토큰 가격은 실제 결제액을 대신하지 않는다.

키 노출이 의심되면 해당 프로젝트에서 키 폐기 → 새 키 발급 → 로컬/배포의 서버 환경 변수 교체 → 배포 → 합성 자료로 명시 점검한다. 키 원문은 Git·스크린샷·채팅·로그에 남기지 않는다. 현재 배포를 바꾸지 않고 유료 생성만 멈추려면 공급자 키/모델 접근을 프로젝트에서 차단한다.

현재 DB는 요청 횟수 예약을 지속 저장하며 실제 토큰/금액별 정산 원장은 없다. 이번 진단은 집계를 위한 민감 정보 없는 단서이며 결제 원장이 아니다. 다수 사용자에게 공개하기 전 실제 토큰 사용량·실패/미확정 사용량의 지속 집계와 경보를 별도 구현해야 한다. 로그 접근·보존 기간은 배포 서비스 설정을 따른다.

## 자동/실제 검증 구분

기본 `pnpm test`는 모의 공급자와 합성 자료를 사용한다. 유료 검사는 `MOA_RUN_OPENAI_LIVE=1`과 별도 `tests/database/vitest.openai-live.config.mts`로만 실행하며 생성은 1회·재시도 0회다. 현재 실제 기록은 [합성 API 확인](../verification/completion-five/openai/actual-check.json)에 있다. 한 사례 통과를 다양한 문서의 전체 품질로 확대하지 않는다.
