# 사용자 강조 기준과 적용 — 2026-11-02 복사 작업 마감

11월1일 사용자는 실제 복사와 파일별 진행·결과, 작업 기록, 재접속 확인을 구현해 달라고 요청했다. 이어 설치의 대상이 최종 사용자라면 안 되며, AI에게 맡기는 폴더의 원본이 걱정된다는 관점에 집중해 달라고 설명했다. 11월2일에는 어제 중단된 작업을 로그와 필요시 memory에서 찾아 이어서 완료하도록 요청했다.

이 요구를 최종 사용자의 별도 설치 없는 브라우저 흐름, 원본 읽기만 허용하는 복사 서비스, 사용자가 검토 뒤 직접 누르는 실행, 알려진 목적지 충돌 중단으로 적용했다. 외부 OS 프로그램까지 잠그는 보장과 앱이 원본을 변경하지 않는 계약은 구별했다. 실제 AI/API가 구현됐다고 표현하지 않았다.

기존 SDD/TDD 요구에 따라 명세→실패 조건→구현→검증을 연결했다. 어제 기록된 새 모듈 부재 RED와 오늘 실제 화면에서 찾은 ‘복사 완료/아직 미적용’ 문구 모순 RED를 구별해 보존했다. 표시 수정 후 최종 복사 브라우저18개, 전체331개/31파일과 타입·lint·경계·43페이지 빌드를 통과했다. 기존 폴더57개·기록42개 회귀는 오늘 표시 수정 직전에 통과했다.

유지보수 기준은 표시, 요청 수명, 순수 기록 규칙, 파일 접근을 기능별 모듈로 나누는 방식으로 적용했다. 이번 문구 수정도 표시 컴포넌트에 기존 실행 여부만 전달해 해결했다. 새 의존성·범용 실행 계층·추가 파일 쓰기 경로는 만들지 않았다. 읽을 순서는 코드 가이드에, 수치·실행 조건과 검증 한계는 별도 보고서에 남겼다.
