# 사용자 강조 기준과 적용 — 2026-11-02 탐색 후속

사용자는 폴더를 왕복할 때 직접 경로 입력칸이 누적되는 실제 오류, 깜빡이며 바뀌는 화면, 깊이를 알기 어려운 경로, 선택 버튼을 거쳐야 하는 번거로움, 찾기 어려운 상위 이동을 지적했다. 요구사항6·7이 실제 구현된 것인지도 확인해 달라고 했다. 반복 메시지는 하나의 요청으로 처리하고 원장18~23번에 간단히 누적했다.

경로 오류는 실제 브라우저 실패부터 재현했다. 두 형제 폼이 같은 경로 key를 쓰던 원인을 찾아 식별자를 분리하고20회 왕복의40개 위치에서 단일 입력과 정확한 경로를 검증했다. 시각 전환은180ms로 제한하고 reduced-motion을 존중했다. 예상 결과는 각 폴더를 개별 줄과 들여쓰기/연결선으로 표현했다.

길게 누르기는 사용자가 시간을 위임해650ms로 정하고 누름 진행선, 이동/스크롤 취소, 기존 키보드 체크박스를 함께 제공했다. 합성 터치에서 선택 도구가 나타나며 행이 밀려 다른 파일이 열리는 문제를 발견해 한 번의 후속 click을 차단했다. 독립 읽기 검토에서 다중 포인터와 방문 기록의 항목 종류 변경 문제를 보완했다. 폴더를 선택해도 미구현 재귀 작업을 조용히 실행하거나 파일만 처리하지 않는다.

최종341개/32파일과 타입·lint·경계·빌드를 통과했고 새 브라우저66개, 기존 UI69·복사25·폴더57·계획30개를 확인했다.6경로 성능은 이전 UI와 비교하며 시각 전환 시간/선택 임계값을 성능 수치로 오해하지 않게 구분했다. 개인 파일을 시험하지 않았고 OS 권한창·실물 모바일 검증을 주장하지 않는다.

요구사항6·7은 기록된 요구이며 구현 완료가 아니다. 전용 보관함·백업 검증이 아직 없어 덮어쓰기를 차단한다고 명확히 답했다. 이번 상태 질문을 실제 덮어쓰기나 삭제 구현 요청으로 확대하지 않았다.
