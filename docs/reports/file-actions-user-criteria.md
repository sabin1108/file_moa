# 사용자 강조 기준과 적용 — 2026-11-02 파일 작업 UX

사용자는 추상적인 ‘변경 계획 검토’보다 복사/이동을 먼저 선택하고, 분류는 챗봇에서만 지정하도록 요구했다. 목적지 선택과 직접 입력을 분리하지 말고 경로 표시에서 같은 창으로 진입하게 하며, 계획이 진행될수록 앞 단계 입력을 숨겨 스크롤 부담을 줄이도록 요청했다.

이를 직접 작업 버튼, 명시적 목적지 확정, 목적지·계획→검사→실행/결과의3단계로 구현했다. 기존 상태에서 단계를 계산하고 실제 성공·기록 확정 때만 확인으로 목적지 폴더에 이동한다. 완료 화면의 검토한 계획은 접고 필요할 때 다시 열게 했다. 팝업 전체 휠 경계를 적용하며 작은 화면의 짧은 폴더 목록에서 팝업이 막히던 문제도 실제 회귀 테스트로 고쳤다.

사용자가 SHA-256과 글 위주의 예상 결과를 이해하기 어렵다고 지적한 점은 검사 항목3개, 파일별 확인, 출발/도착 폴더 구조와 아이콘으로 표현했다. 비교값은 기술 정보 안에 설명과 함께 접었다. 애니메이션은 실제 진행 중만 사용하고 정지 선호 설정을 따른다. 공통 버튼/아이콘/CSS 토큰을 재사용하며 새 의존성을 추가하지 않았다.

같은 이름의 계속/중단과 덮어쓰기는 기존 목적지를 사용자가 지정한 전용 복구 보관함에 남기는 방향으로 정리했다. 이 부분은 이번에 구현 완료로 보고하지 않는다. 복구 사본 검증→목적지 재검사→쓰기→검증 순서, 복원/기간/즉시 삭제의 후속 실패 조건을 별도 명세로 남겼고 현재 충돌 차단을 유지했다. 실제 이동도 아직 계획만 제공한다.

SDD/TDD 요구는 사용자 행동 계약→실패 테스트→최소 구현→검증으로 연결했다. controller4개 테스트를 추가하고 실제 Chromium에서 휠/단계/완료 이동을 검사했다. 독립 읽기 검토에서 발견한 실행 진입 예외의 재검사 경로를 보강했다. 최종335개/31파일, 타입·lint·경계·43페이지 빌드와 새 UX69·복사25개를 통과했다. 폴더/계획/목적지/검사 회귀와6경로 성능도 별도 원자료로 남겨 모형 검증과 OS 실제 사용 검증을 구별했다.

사용자는 요구사항 기록 자체도 번호별1~3줄만 요구했다. `E:/memory/chatbotfolder/Requirements/요구사항.md`에17개를 저장했으며 이후 요청은 누적하고 취소는 삭제하지 않고 `{취소됨}`으로 표시한다. 긴 구현 과정은 이 보고서에 분리했고 요구사항 원장을 완료 목록으로 오해하지 않게 했다.
