# 초보 티가 나는 대시보드 UI의 3가지 치명적 실수와 해결책

이 문서는 Kole Jain의 YouTube 영상 **[The 3 dashboard UI flaws that give away you've NEVER built one](https://www.youtube.com/watch?v=Ksx9C2-3yMo)** 의 핵심 내용을 요약한 가이드입니다.

대시보드를 디자인하는 것과 실제로 잘 작동하게 만드는 것에는 큰 차이가 있습니다. 그저 예뻐 보이는 UI가 아니라 실무에서 완벽하게 작동하는 대시보드를 만들기 위해 반드시 피해야 할 3가지 초보적인 실수와 그 해결책을 소개합니다.

---

## 1. 데이터가 UI 형태를 결정하지 못함 (Not Letting Data Drive the Form)

**문제점:**
모든 대시보드의 공통점은 '데이터를 보여주는 것'입니다. 하지만 데이터의 특성을 고려하지 않고 일률적인 표(Table) 형태로만 디자인하면 가독성이 떨어지고 사용하기 불편해집니다.

**해결책 및 예시:**
* **데이터에 맞는 시각적 처리:** 부서명이나 고용 상태처럼 정해진 범주가 있는 데이터는 단순 텍스트가 아닌 **칩(Chip/Badge)** 형태로 변경합니다.
* **숫자 정렬:** 숫자로 된 데이터는 자리수에 맞춰 비교하기 쉽도록 **우측 정렬(Right-align)** 합니다.
* **가독성 확보:** 긴 텍스트는 말줄임표(Truncate) 처리하여 다른 열(Column)에 충분한 여백을 주고, 비활성화된 항목은 회색으로 흐리게 처리하여 직관성을 높입니다.
* **형태의 전환:** 시간에 따른 변경 이력 같은 데이터는 억지로 표에 구겨 넣기보다 **타임라인(Timeline)** 형태로 배치하는 것이 데이터를 훨씬 잘 나타냅니다.
* **목적에 맞는 색상 사용:** 대시보드에서 색상은 단순히 예쁘게 보이기 위해 쓰는 것이 아닙니다. 긴급한 액션은 빨간색으로, 작성자는 쉽게 알아볼 수 있도록 아바타 이미지로 표시하여 눈이 데이터를 빠르게 읽을 수 있도록 해야 합니다. 시간 차원이 포함된 데이터라면 차트(Chart)를 활용하는 것이 텍스트를 읽는 것보다 훨씬 빠릅니다.

## 2. 점진적 공개(Progressive Disclosure)의 부재

**문제점:**
초보 디자이너는 폰트 크기나 색상으로만 계층 구조(Hierarchy)를 나누려 합니다. 하지만 대시보드에서는 '무엇을 보여주고 무엇을 숨길 것인가'에 대한 계층 구조도 매우 중요합니다. 모든 기능을 화면에 늘어놓으면 사용자가 압도당하게 됩니다.

**해결책 및 예시:**
* **중요도에 따른 숨김 처리:** 자주 쓰이지 않는 '공유'나 '삭제' 같은 부가 기능은 화면에 항상 띄워둘 필요가 없습니다. 팝오버(Popover) 메뉴 안에 넣거나, 마우스를 올렸을 때(Hover)만 버튼이 나타나게 합니다.
* **명시성 스펙트럼 (Spectrum of Explicitness):** 항상 노출되는 버튼(가장 명시적임)부터, 마우스 호버 시에만 나타나는 아이콘(덜 명시적임)까지 기능의 중요도에 맞춰 명시성을 조절해야 합니다.
* **온보딩(Onboarding) 적용:** 사용자가 처음 로그인했을 때 6개의 복잡한 안내 모달을 띄우는 대신, 가장 중요한 단일 액션에만 툴팁을 표시하고 사용자가 이를 완수하면 다음 단계를 안내하는 식으로 순차적(Sequence)으로 기능을 노출해야 합니다.

## 3. '보이지 않는 UI (Invisible UI)'의 간과

**문제점:**
UI는 눈에 바로 보이는 것만큼이나 **당장 보이지 않는 요소들**이 중요합니다. 초보 디자이너나 AI는 이를 놓치기 쉽지만, 밀도 높은 대시보드일수록 이런 숨겨진 UI 없이는 제대로 기능할 수 없습니다.

**해결책 및 예시:**
* **숨겨진 상호작용 설계:** 표의 특정 셀에 마우스를 올렸을 때 나타나는 '복사(Copy)' 칩, 작은 삼각형으로 표시된 '댓글(Comment)' 기능, 호버링 시 나타나는 세부 정보 등이 보이지 않는 UI의 대표적 예시입니다.
* **툴팁(Tooltip)의 필수적 활용:** 모든 사용자가 아이콘의 의미나 모호한 라벨의 뜻을 알고 있을 것이라 가정해서는 안 됩니다. 초보들의 대시보드에서 가장 많이 빠져있는 요소가 바로 툴팁입니다.
* **기능 확장을 위한 공간 확보:** 새로운 기능이 추가된다고 해서 항상 새로운 페이지를 만들어야 하는 것은 아닙니다. 모달, 드로어(Drawer), 호버 상태 등을 잘 오케스트레이션(조율)하면 기존 화면 안에서도 훌륭하게 기능을 소화할 수 있습니다.

---

### 💡 요약
훌륭한 대시보드를 구축하려면 다음 세 가지를 기억해야 합니다.
1. **데이터 자체가 UI의 형태를 결정하게 하라.**
2. **사용자가 필요해지기 전까지는 부가 기능을 적절히 숨겨라 (점진적 공개).**
3. **대시보드를 실제로 작동하게 만드는 것은 숨겨진 '보이지 않는 UI (상호작용, 툴팁 등)' 들이다.**
