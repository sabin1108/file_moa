 시니어 개발자가 알아야 할 8가지 API 디자인 패턴
이 영상은 시스템이 성장함에 따라 발생하는 복잡성을 해결하고, 확장 가능하며 유지보수가 쉬운 API를 설계하기 위한 8가지 핵심 패턴을 소개합니다.
8가지 API 디자인 패턴
 3. 리소스 지향 설계 (Resource-Oriented): 동작(Action) 중심이 아닌 리소스(User, Product 등) 중심으로 URL을 설계하고, HTTP 메서드(GET, POST, PUT, DELETE)로 동작을 정의합니다.
 4. 페이지네이션 (Pagination): 대량의 데이터를 한 번에 보내지 않고 페이지 단위로 나누어 응답하여 성능을 최적화합니다.
 5. 필터링 및 필드 선택 (Filtering & Field Selection): 클라이언트가 필요한 데이터만 필터링하고 특정 필드만 요청하도록 하여 불필요한 데이터 전송을 방지합니다.
 6. 멱등성 (Idempotency): 네트워크 오류로 인한 재요청 시에도 서버 상태가 중복으로 변하지 않도록 고유 키를 사용해 안전한 처리를 보장합니다.
 7. BFF (Backend For Frontend): 클라이언트(웹, 앱, TV 등)별로 최적화된 API 계층을 두어 각기 다른 요구사항을 효율적으로 처리합니다.
 8. API 게이트웨이 (API Gateway): 분산 시스템의 단일 진입점을 구축하여 인증, 속도 제한, 라우팅 등을 중앙에서 관리합니다.
 9. 비동기 API (Asynchronous API): 시간이 오래 걸리는 작업은 즉시 응답 후 백그라운드에서 처리하고, 클라이언트는 상태를 조회하게 합니다.
 10. 버전 관리 (Versioning): API 변경 시 기존 클라이언트가 깨지지 않도록 하위 호환성을 유지하며 점진적으로 발전시킵니다.
 핵심 결론
 * 문제 해결 중심: 패턴을 단순히 암기하는 것이 아니라, **"어떤 문제를 해결하기 위해 이 패턴을 쓰는가?"**를 고민해야 합니다.
 * 미래를 위한 설계: 시니어 개발자는 당장의 구현뿐만 아니라, 6개월 후 발생할 문제와 변화를 예측하며 API를 설계합니다.
